## Start with Inth

[Inth](https://inth.com) is the recommended backend for c15t applications. Use
the endpoint supplied by your project in the [framework quickstart](/docs/frameworks).
You get a backend connection without running the SQL service described in these
guides.

Self-hosting uses `@c15t/backend` and the same client hosted mode. Choose it when
you need to operate the service yourself. You own database provisioning,
migrations, backups, policy configuration, signing secrets, availability and
upgrades.

## What the backend provides

| Capability | How clients use it |
| --- | --- |
| Reusable configuration | `/manifest` publishes policy rules, translation configuration and IAB metadata for caching and local resolution. |
| Request initialization | `/init` resolves the policy for a request's location, language and privacy signals. |
| Consent persistence | Subject endpoints record confirmed category receipts and retrieve current choices. |
| Identity and privacy directives | Subject links and separate directive records support device and authenticated identity workflows. |
| Legal-document versions | An authenticated release endpoint stores the current document identity. Exported helpers sign and verify document snapshots. |

For Next.js request rendering, prefer the cached manifest path described in
[data fetching](/docs/guides/data-fetching). A browser-only application can use
regular initialization. A static frontend can use either Inth or a separately
deployed self-hosted backend; static hosting does not require offline mode.

## What offline mode changes

`offline()` resolves policy and retains choices through client-side storage. It
does not call this backend, create SQL consent records or obtain hosted
configuration. It is an alternative deployment mode, not a faster transport to
the same service. See [deployment modes](/docs/guides/deployment-modes).

## Operate your own backend

Start with the [self-hosted quickstart](/docs/self-host/quickstart), then review
[database setup](/docs/self-host/guides/database-setup) and
[configuration](/docs/self-host/api/configuration). Use
[HTTP endpoints](/docs/self-host/api/endpoints) to integrate a custom server
client, and [policy configuration](/docs/self-host/guides/policy-packs) when you
own the policy manifest.
