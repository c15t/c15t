## Find your API base URL

All paths are relative to the backend's mount point. With
`basePath: '/api/c15t'`, `/manifest` is available at `/api/c15t/manifest`.
The framework adapters call these endpoints for you. Prefer the adapter unless
you are building a custom transport or server integration.

| Method and path | Purpose | API key |
| --- | --- | --- |
| `GET /status` | Service status and configured version. | No |
| `GET /manifest` | Geo-independent policy configuration, optionally sliced with `?language=en`. | No |
| `GET /init` | Resolve configuration for this request's location, language and privacy signals. | No |
| `POST /sessions` | Report an init a host resolved from a cached manifest. Server-to-server only; nothing is stored. | No |
| `POST /subjects` | Record a consent submission and its category receipts. | Optional, affects asserted identity authority |
| `GET /subjects/:id` | Read this subject's consent status, merged choices and privacy directives. Optional `?type=a,b` filter. | No, the subject ID is the capability |
| `PATCH /subjects/:id` | Link `externalId` and optional `identityProvider`. | Optional, distinguishes browser and API authority |
| `GET /subjects?externalId=...` | Retrieve subjects for an external identity. | Required |
| `GET /consents/check?externalId=...&type=a,b` | Return `hasConsent` and `isLatestPolicy` for every requested type. | No |
| `POST /subjects/:id/privacy-directives` | Record a privacy directive for one subject. | No, subject-scoped |
| `GET /subjects/:id/privacy-directives` | Read directives applying to the subject. | No, subject-scoped |
| `POST /privacy-directives` | Record an identity-level privacy directive. | Required |
| `GET /privacy-directives?externalId=...&identityProvider=...` | Read identity-level privacy directives. | Required |
| `PUT /legal-documents/:type/current` | Publish a legal document's current version, hash and effective date. | Required |
| `GET /spec.json` | Discover the enabled OpenAPI routes. | No |

Subject IDs allow public reads of that subject's state. Treat them as private
capabilities. Do not expose administrative API keys to make browser requests.

## Fetch reusable configuration

```bash
curl -i 'http://localhost:3000/api/c15t/manifest?language=en'
```

`/manifest` returns the policy configuration and a revision, with an `ETag` and
public cache headers. It contains no visitor's consent choices. A matching
`If-None-Match` returns `304`. See [caching](/docs/self-host/guides/caching) before
putting a CDN in front of the backend.

## Resolve a request with `/init`

```bash
curl -i 'http://localhost:3000/api/c15t/init' \
  -H 'x-c15t-country: DE' \
  -H 'Accept-Language: en'
```

This development request supplies a location explicitly. In production, use the
framework adapter and trusted deployment headers. `/init` resolves location,
language and GPC against the manifest. Its `policyResolution` distinguishes a
matched rule from an unmatched or failed resolution. A `200` response alone does
not establish that a rule matched.

`/init` uses `Cache-Control: no-store`. It can include a signed
`policySnapshotToken` when signing is configured and a policy matched. For
request-time framework rendering, prefer a cached manifest and local resolution
when the adapter supports it. Do not cache one visitor's resolved `/init` result
as shared configuration.

## Report a session

```bash
curl -i 'http://localhost:3000/api/c15t/sessions' \
  -H 'Content-Type: application/json' \
  -H 'X-C15T-Version: 3.0.0' \
  -H 'X-C15T-Client-IP: 203.0.113.42' \
  -H 'User-Agent: Mozilla/5.0' \
  -d '{"source":"route","revision":"…","resolution":"matched","policy":{"id":"eu-opt-in","fingerprint":"…","matchedBy":"country","model":"opt-in"},"jurisdiction":"GDPR","country":"DE","region":null,"language":"de","gpc":false}'
```

A host that resolves init from a cached manifest never calls `/init`, so the
backend would not know a visitor was served. The framework adapters send this
report server-to-server after each resolution, detached from the response. The
route accepts nothing a page could have sent: a request carrying `Origin`, or
one without the `X-C15T-Version` header every c15t client sends, is rejected
with `400`. The
visitor's user agent travels as `User-Agent` and the visitor's address on
`X-C15T-Client-IP`, a dedicated header because a platform in front of the
backend rewrites `X-Forwarded-For` to the connecting server. The backend applies
its `ipAddress` masking and tracking settings to that value, records the report
on the request's wide event, hands it to the `sessions.onReport` sink, waits for
the sink, and answers `204`. It writes nothing to the database.

The body shape is `consentSessionReportSchema` in `@c15t/schema`. `source` is
`route` for an init route and `render` for a server-rendered page; `init` is
reserved for the backend's own `/init`, which emits the same event, and a report
claiming it is rejected with `400`. Neither route reports a prefetch or
prerender (`Sec-Purpose`, `Purpose`, `Next-Router-Prefetch`). One page view can legitimately produce more
than one report, for example a `render` followed by a `route` when the client
re-initialises, and every full page load produces a new one. Count sessions by
deduplicating on `source` and grouping by visitor on the consuming side; the
report carries no visitor identifier of its own.

## GET /c15t.js

The [script-tag build](/docs/frameworks/javascript/script-tag) of the consent banner, pre-configured for this backend. The response is the `@c15t/browser` bundle behind a queued `config` call that carries the instance's manifest, the backend origin, and the defaults set in the `script` option. `GET /c15t.headless.js` serves the build with no UI. `GET /c15t.iab.js` serves the optional IAB CMP and preference UI. Use `script.iabPath` to change its path and `script.config.iab` to set CMP options.

| Query | What it does |
| --- | --- |
| `language` | Slice the inlined manifest's translations to one language. |

Cached like `/manifest`: `Cache-Control: public, s-maxage=…` and an `ETag` that answers `If-None-Match` with `304`. Requires `@c15t/browser` next to `@c15t/backend`, or `script.bundles` pointing at the bundle files. Set `script.enabled: false` to remove all three routes.

## Save and read choices

The v3 client sends `POST /subjects` with a domain, policy type, `preferences`,
`givenAt` timestamp and the per-category receipts confirmed by the action. Let the
client construct this payload so effective permissions are not mistaken for an
explicit grant. Hydration, a dismissed notice and a GPC signal are not consent
submissions.

The response includes `subjectId`, `consentId`, `appliedPreferences` and `givenAt`.
Read `GET /subjects/:id` to inspect merged category choices. A type filter changes
which consent records are returned and how `isValid` is calculated; it does not
filter away the subject's cookie-banner choice state.

When the client declares vendors, a save also carries `vendorChoice`: the complete
per-vendor grant map with one confirmation time. The backend stores it as sent on
the consent row, including vendors the client declared in code rather than in the
manifest, and returns `subjectVendorChoice`: the most recent act decides every
vendor it names, and a vendor an earlier act decided but the latest one omits
keeps that earlier grant. The aggregate's `confirmedAt` is the time of the oldest
decision still in it, so a retained grant is never presented as newer than it is. A map that omits a vendor the manifest declares is
stored too: the client saw an older manifest, so its silence about that vendor
is not a decision. A vendor no act ever named follows its category.
Retrying the same act with a different map is a `CONFLICT`, like a retry with
different receipts, and so is any retry against a stored map that cannot be
read. Migration `4-vendor-choice` adds the column.

Privacy directives are stored separately from consent records. Saving consent
does not delete an existing directive. An API-authenticated identity link has
different authority from a browser-asserted link.

## Make an administrative request

Use a server environment variable containing a configured API key:

```bash
curl 'http://localhost:3000/api/c15t/subjects?externalId=customer-123' \
  -H "Authorization: Bearer $C15T_API_KEY"
```

Missing or invalid keys return `401` on protected routes. Invalid input returns
an error body containing `message` and `cause.code`; individual validation paths
can return `400` or `422`. Inspect both the HTTP status and error code. Database
errors return a generic failure to the client, with details available through
[server logging](/docs/self-host/guides/observability).

The OpenAPI document lists available routes and security declarations. Use the
published `@c15t/schema` contracts and client adapters for complete payload types;
the generated document does not describe every field accepted by each handler.
