## Choose where policy is managed

For [Inth](https://inth.com), manage the project's policy in the hosted service.
Importing presets into a browser using `hosted()` does not change that policy.
The examples on this page configure a self-hosted backend. Offline clients use
their own `offline({ policyRules })` configuration instead.

For an explanation of how an existing Next.js app follows a policy, read
[policy presets](/docs/frameworks/next/concepts/policy-presets). A framework
component does not need a database configuration to consume hosted policy.

## Configure `manifest.policyRules`

```ts title="c15t-backend.config.ts"
import {
  defineConfig,
  inspectPolicyRules,
  policyRulePresets,
} from '@c15t/backend';

const url = process.env.DATABASE_URL;
if (!url) throw new Error('Set DATABASE_URL');

const policyRules = [
  policyRulePresets.europeOptIn(),
  policyRulePresets.quebecOptIn(),
  policyRulePresets.usPrivacyStatesOptOut(),
  policyRulePresets.worldOptOutNoPrompt(),
];

const { errors } = inspectPolicyRules(policyRules);
if (errors.length) throw new Error(errors.join('\n'));

export default defineConfig({
  database: { dialect: 'postgres', url },
  trustedOrigins: ['https://app.example.com'],
  manifest: { policyRules },
});
```

This example deliberately chooses opt-out behavior for unmatched known locations.
Review whether that behavior fits your processing before adopting it. Presets
encode consent behavior and geographic matches. They do not decide which laws
apply to your business or establish a legal basis for a vendor's processing.

The authored input is `policyRules`. The generated `/manifest` contains
`policyPacks`; passing that generated field back as configuration is unsupported
and yields `policyFailure`.

## Understand rule selection

A known region match takes precedence over a country match. Array order resolves
ties at the same specificity. A rule with `match.isDefault` handles unmatched
locations. A fallback handles missing inputs; do not assume the default handles
every missing-country or missing-region case.

The Europe preset includes an unknown-location fallback. For custom packs with
subdivision rules, define the intended missing-region behavior. If no country
rule, region fallback or global fallback can resolve a missing subdivision,
resolution can fail with `insufficient-inputs`.

```ts title="consent-policies.ts"
import { policyMatchers, policyRulePresets } from '@c15t/backend';

const us = policyRulePresets.usPrivacyStatesOptOut();
export const usWithMissingState = {
  ...us,
  match: policyMatchers.merge(us.match, policyMatchers.regionFallback(['US'])),
};
```

This partial policy adds a fallback for a known US country with a missing state.
It does not expand coverage for known states. Put the resulting rule in your
`manifest.policyRules` array.

## Choose the consent behavior

| Model | Initial optional permissions | UI and rights |
| --- | --- | --- |
| `opt-in` | Wait for a recorded choice. | A choice prompt can request permission. |
| `opt-out` | In-scope processing may start under the rule, subject to privacy signals. | The rule defines notice, opt-out and preference rights. |
| `none` | In-scope categories are allowed by policy. | No consent UI appears unless rights are explicitly configured. |
| `iab` | Follow the IAB policy and client add-on. | Requires matching IAB configuration. |

Effective permission is not an explicit consent receipt. A no-banner rule does
not prove the user accepted anything. Keep any preference controls required by
the selected rule available after the initial page view.

## Available presets

All presets return ordinary policy rule objects. Review their categories,
prompt, rights and matchers in your editor or with `inspectPolicyRules()` before
publishing changes. Prefer opt-in variants when an opt-out preset's processing
assumptions do not fit your application.

| Preset family | Configuration choices |
| --- | --- |
| Europe | `europeOptIn()`, `europeIab()` |
| US privacy states | `usPrivacyStatesOptIn()`, `usPrivacyStatesOptOut()` |
| California | `californiaOptIn()`, `californiaOptOut()` |
| Québec | `quebecOptIn()` |
| Canada outside Québec | `canadaOptIn()`, `canadaOptOut()` |
| Australia | `australiaOptIn()`, `australiaOptOut()` |
| Japan | `japanOptIn()`, `japanOptOut()` |
| Switzerland | `switzerlandOptIn()`, `switzerlandOptOutNoPrompt()` |
| Restricted statistics profiles | `ukStatistics()`, `malaysiaStatistics()` |
| Reviewed UK statistics with consent | `ukStatisticsAndConsent('review-1')` |
| Other regional opt-in | Singapore, Malaysia, Thailand, Indonesia, Philippines, Vietnam, Brunei, Laos, China, South Korea, India, Brazil, Turkey and more in `policyRulePresets`. |
| Global defaults | `worldNone()`, `worldOptOutNoPrompt()` |

Statistics profiles are scoped configurations, not permission to run arbitrary
analytics or marketing vendors. Inspect their allowed categories and required
rights. Do not substitute them for a full consent configuration based only on a
vendor calling its product analytics.

## Compose custom rules

`policyBuilder.create()` accepts canonical rule fields with flat `countries`,
`regions`, `isDefault` and `fallback` match inputs. `createPack()` preserves the
supplied order. `createPackWithDefault()` appends the explicit default you supply
if none exists. `composePacks()` preserves order and keeps the first occurrence
of each rule ID.

These helpers do not make invalid inputs valid. Validate the final composed
array with `inspectPolicyRules()`. For IAB rules, pass `{ iabEnabled: true }` to
the inspector and configure [IAB support](/docs/self-host/guides/iab-tcf).

## Publish and verify a policy change

Inspect `/manifest` after deployment. Its revision should change when the
configuration changes. Allow for [manifest cache windows](/docs/self-host/guides/caching)
or purge the old revision. Check `/init` for each supported region, an unknown
country and a missing subdivision. Confirm the expected model, prompt and rights.

Invalid rules create a `policyFailure` and a failed resolution, even when the
HTTP response succeeds. Verify the browser's effective permissions, visible
controls and saved receipts after the change. Do not rely only on a banner
screenshot to establish policy behavior.

## Combine UK exceptions with consent

Declare `exemptions` only after reviewing every processing operation in the
category. A declaration allows that category before consent and gives the visitor
an objection control. It does not record consent or establish eligibility for a
vendor automatically.

This partial configuration belongs in `manifest.policyRules`. Place the UK rule
before any other rule that matches GB at the same specificity.

```ts title="c15t-backend.config.ts"
import type { PolicyRule } from '@c15t/backend';

const policyRules = [
  {
    id: 'uk-statistics-and-advertising',
    match: { countries: ['GB'] },
    model: 'opt-in',
    prompt: 'choice',
    categories: ['measurement', 'marketing'],
    scopeMode: 'strict',
    exemptions: {
      measurement: { kind: 'uk-statistics', revision: 'statistics-review-1' },
    },
  },
  {
    id: 'consent-required',
    match: { isDefault: true, fallback: true },
    model: 'opt-in',
    prompt: 'choice',
    categories: ['measurement', 'marketing'],
    scopeMode: 'strict',
  },
] satisfies PolicyRule[];
```

In GB, measurement is initially allowed and marketing waits for consent. Outside
GB, including unknown geography, both categories wait for consent. The stock
preferences controls label exempt processing and let visitors turn it off.
Provide clear information about its purpose before processing starts, and a
persistent way to open those controls. An all-exempt scope has no automatic
consent prompt, so publish that information in the page itself.

`policyRulePresets.ukStatisticsAndConsent('statistics-review-1')` returns the UK
rule with measurement and marketing in scope. The older `ukStatistics()` preset
is a statistics-only opt-out profile; it does not enable this mixed policy or
create separate exemption preferences.

The validator requires explicit GB-only matchers. Exemptions cannot appear on a
default or global fallback, or under `iab` or `none`. `uk-statistics` applies only
to measurement. `uk-appearance` applies to functionality or experience, for
appearance and functionality processing that meets its own conditions. Marketing
cannot be exempted. Update `revision` when the reviewed processing changes.

### Check the statistics conditions

The [PECR Schedule A1 statistics exception](https://www.legislation.gov.uk/uksi/2003/2426/schedule/A1)
requires processing solely to collect statistics for improving the service.
Review the [ICO exceptions guidance](https://ico.org.uk/for-organisations/direct-marketing-and-privacy-and-electronic-communications/guidance-on-the-use-of-storage-and-access-technologies/what-are-the-exceptions/)
against the deployed configuration and contracts. In particular:

- Produce aggregate statistics for your service, with no individual histories,
  profiling, advertising or cross-site tracking.
- Restrict sharing to what the exception permits. An analytics provider must act
  on your instructions and must not reuse the information for its own purposes.
- Explain the processing and offer a free, simple objection mechanism.
- Use consent where the same storage or access operation also serves a
  non-exempt purpose. Ad measurement still requires consent.

This first version exempts a whole category. If measurement contains both
eligible statistics and consent-required analytics, leave measurement under
consent. Granular vendor consent can further restrict a category, but it does
not let c15t exempt only one vendor inside that category.

### Review premade integrations

Premade integrations configure script loading and callbacks. Their vendor name
or `category: 'measurement'` does not determine PECR eligibility.

| Integration or use | Review before declaring an exemption |
| --- | --- |
| Advertising pixels and advertising measurement | Keep under consent. |
| GTM and other tag containers | Review every tag and every purpose. A container is not an exemption declaration. |
| Analytics with user identification, session replay, profiles, advertising links or vendor reuse | Keep under consent unless the deployed processing is changed and reviewed against the exception. |
| Current Plausible, Fathom and Pirsch loaders | Review revocation separately. Removing their script tag does not stop an SDK that has already initialized. |
| Aggregate service statistics | A possible candidate after checking data use, configuration, sharing, information and objection controls. |

c15t does not automatically exempt any premade integration. The shipped helper
also cannot inspect your vendor account settings or data-processing contract.
Cookieless tracking alone does not establish eligibility; storage and access
rules can apply to other techniques too.

An objection must stop ongoing collection as well as future script loads.
Removing a script element does not stop an SDK's existing timers, listeners or
network requests. Review the helper's revocation behavior and the provider's
supported opt-out or shutdown API. The runtime and framework adapters reload
after a saved objection by default, so the next page starts without that script.
If you disable `reloadOnConsentRevoked`, use the headless kernel directly, or
need to stop collection in another open tab, supply a script `onConsentChange`
callback that stops collection when `hasConsent` becomes false. Use a
consent-required configuration until the deployed processing can honor an
objection. c15t cannot undo earlier collection.

Localize the optional `common.exemptStatisticsNotice`,
`common.exemptAppearanceNotice`, `common.exemptProcessing` and
`common.consentRequired` translation keys for your visitors. The stock UI falls
back to English when these keys are absent.

### Check the appearance conditions

The appearance exception covers changes that follow a visitor's preferences,
such as a remembered language or display choice. It does not exempt advertising
or personalization inferred from tracking. Explain the processing and offer the
same free, simple objection mechanism. Review functionality and experience
operations separately before declaring `uk-appearance` for either category.

### Keep objections separate from consent

The kernel stores objections and reversals in `exemptionPreferences`, separately
from `explicitChoice`. A positive exemption preference resumes exempt processing;
it never grants consent-required processing. Objections do not expire with
consent receipts. An old explicit refusal remains effective until the visitor
reverses it.

Accept All preserves an existing exemption objection. Reject All objects to
exempt processing too. A visitor can explicitly turn the category back on in
preferences. Removing the exemption makes the category wait for valid consent;
a stored exemption preference cannot supply it. Material policy changes can also
invalidate existing consent grants.

Script gates use effective permissions. Vendor consent signals, including Google
Consent Mode, keep exempt categories denied because exemption permission is not
consent. Do not use an exemption to load a script whose own terms or consent
requirements prohibit that processing.

Exemption rules use policy contract version 2. Updated clients advertise support
for version 2; older clients receive a safe policy failure rather than a rule
whose exemption semantics they cannot enforce. Ordinary rules retain version 1
wire output and fingerprints. Upgrade the backend and clients together before
publishing exemption rules.
