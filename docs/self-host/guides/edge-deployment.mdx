---
title: Manifest delivery at the edge
description: Deliver a versioned manifest while retaining origin receipt and privacy endpoints.
---

## Generate a manifest

```ts
import {
  buildConsentManifestFromConfig,
  policyRulePresets,
} from '@c15t/schema';

const manifest = await buildConsentManifestFromConfig({
  policyRules: [policyRulePresets.europeOptIn()],
});
```

Serve the generated version 2 manifest through your deployment's static or edge
cache. Keep its revision and ETag aligned. Configure the adapter's manifest mode
with the same manifest and keep category receipt and privacy endpoints on the
origin backend. Rebuild the manifest whenever rule behavior changes.

Each entry in the manifest's `policyPacks` array contains `match`, a normalized
`rule`, and producer-computed `fingerprints`. This wire field differs from the
backend configuration's `policyRules`. If building an individual entry, call
`createConsentManifestPolicyPack(rule)` with an authored `PolicyRule`. Old
`policy`, `resolvedPolicy` and single-fingerprint entries are unsupported.

The former unstable edge initializer and consent resolver are removed. Use the
shared manifest builder and the current adapter server helpers. Do not infer
permission from geography or implement another cookie interpreter.

Preserve `x-c15t-policy-contract: 1` through proxies. Unsupported semantics and
invalid manifests select safe opt-in behavior. An old cached runtime can still
retain stored grants under GPC; invalidate and redeploy that client before relying
on the new rules. See [wire rollout](/docs/upgrade-v3#coordinate-the-wire-rollout).
