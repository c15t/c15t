## Register scripts on the provider

Pass the array from `src/scripts.ts` to `ConsentProvider` as the
`scripts` prop. The [quickstart](/docs/frameworks/svelte/quickstart) sets up
this file:

<include src="../../shared/examples/svelte/scripts.mdx" />

Replace the placeholder PostHog project key with your own.

The provider loads the script loader as a separate chunk, shared with the
[network blocker](./network-blocker), and only when `scripts` is not empty or
the blocker has rules, so an app with neither never downloads it. A
single-page app has no server render to link the chunk from, so the browser
requests it after your app's JavaScript has run. A SvelteKit app can preload
it from the server-rendered page; the SvelteKit scripts guide shows how.

## Send your own analytics events

`getEventDispatcher()` from `@c15t/svelte` returns the provider's event
dispatcher. It sends to the provider's `scripts` and checks consent when an
event goes out. Call it while a component inside `ConsentProvider`
initializes, and send a pageview when your router's path changes:

<include src="../../shared/examples/svelte/analytics-events.mdx" />

Call `events.track('sign_up', { method: 'email' })` from an event handler for
your own events. `track` sends to every registered script with an event API and drops the
event while measurement is denied. `pageview` sends only to the integrations
named in `pageviews`, and the first call records the path without sending.
Every dispatcher shares one pageview history for the provider's lifetime.
See [send events only to allowed integrations](/docs/integrations/overview#send-events-only-to-allowed-integrations)
for the supported vendors.
