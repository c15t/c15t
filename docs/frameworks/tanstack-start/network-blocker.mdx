## Add rules

Pass `networkBlocker` rules to `ConsentRoot` to stop `fetch` and
`XMLHttpRequest` calls to a domain until its category is allowed. Use it as a
backstop for beacons an SDK sends itself. Load vendor SDKs through
[`scripts`](/docs/frameworks/tanstack-start/scripts) first, so they do not run
at all before consent.

{/* example: fragment */}

```tsx title="src/routes/__root.tsx"
const networkBlocker = {
  rules: [
    { id: 'google-analytics', domain: 'google-analytics.com', category: 'measurement' },
    { id: 'meta-pixel', domain: 'facebook.com', pathIncludes: '/tr', category: 'marketing' },
  ],
};

<ConsentRoot state={consent} backendURL={backendURL} initRoute={false} scripts={scripts} networkBlocker={networkBlocker}>
```

The blocker runs in the browser only. It does not see requests your server
functions or server routes make.

## Verify the blocked requests

Open DevTools Network in a private window, under a policy that asks for
consent.

1. Before a choice, requests matching a rule are absent, and the console logs
   each blocked request.
2. Allow the rule's category and save. Matching requests go out.
3. Reject, reload, and check that they stay absent.
