`c15t/tanstack-start/server` reads the current request through `getRequest()` from `@tanstack/react-start/server` and returns a serializable consent config. Call it from server functions, server route handlers, or request middleware. It is not safe to import from client components.

## readInitialConsentConfig

Reads the `c15t` cookie and the geo, language, and GPC headers. It never touches the network, so use it when you want the fastest possible loader and are happy for the browser to run init through the same-origin route.

```ts
import { createServerFn } from '@tanstack/react-start';
import { readInitialConsentConfig } from 'c15t/tanstack-start/server';

export const getConsentConfig = createServerFn({ method: 'GET' }).handler(() =>
  readInitialConsentConfig()
);
```

Options:

- `cookieName`: the persistence cookie name, if you changed `storageConfig.storageKey` on the client.
- `country` and `language`: override the detected values. Handy in development.
- `request`: a `Request` or a function returning one. Defaults to `getRequest()`. Pass the request a server route handler already holds, or a plain `Request` in tests.

## prefetchInitialConsent

Does everything `readInitialConsentConfig` does, then resolves init for this request from your backend's consent manifest so the first paint already carries the policy, UI mode, translations, and IAB metadata.

```ts
import { createServerFn } from '@tanstack/react-start';
import { prefetchInitialConsent } from 'c15t/tanstack-start/server';

export const getConsentConfig = createServerFn({ method: 'GET' }).handler(() =>
  prefetchInitialConsent({ backendURL: 'https://your-instance.c15t.dev' })
);
```

`createConsentConfigHandler(options)` from the quickstart is the same call wrapped in a handler function, and falls back to `readInitialConsentConfig` when you omit `backendURL`.

Options on top of `readInitialConsentConfig`:

- `backendURL`: your c15t instance. The manifest is read from `${backendURL}/manifest` through an in-process cache that honours the backend's `s-maxage` and ETag. Relative URLs resolve against the request's `x-forwarded-*` and `host` headers, which covers Node, Cloudflare Workers, Vercel, and Netlify.
- `manifestURL`: an explicit manifest URL when it does not live under `backendURL`.
- `manifest`: an inline manifest. Use it when `@c15t/backend` runs in the same process, or with a build-time module generated by `c15t/tanstack-start/static`.
- `fetch`, `forwardHeaders`, and `cache` for custom transports, authentication headers, and cache isolation in tests.

<Callout type="warn">
  Never point `backendURL` at the app's own `/api/c15t` route. A server that fetches itself during server rendering waits on the request it is already handling and deadlocks the dev server. The helper detects that case, skips the fetch, and returns the baseline config.
</Callout>

If the manifest cannot be loaded, the helper returns the baseline config and the browser runs init on mount. Nothing is thrown into your loader.

## Same-origin consent routes

`createConsentServerRoute()` from `c15t/tanstack-start/api` serves two endpoints from one splat route:

| Endpoint | Behavior |
| --- | --- |
| `GET /api/c15t/manifest` | Passes the cached backend manifest through with its `cache-control`, `etag`, `last-modified`, and `content-language` headers. Answers `304` to a matching `if-none-match`. Forwards `?language`. |
| `GET /api/c15t/init` | Resolves init from the cached manifest for the request's headers. Sends `cache-control: private, no-store`. Fetches the Global Vendor List only when the manifest enables IAB. |

Consent saves are not proxied. `ConsentBoundary` sends `POST /subjects` straight to `backendURL` and asserts the decision inputs it resolved through the init route, so the backend rejects a save made against a stale policy.

Prefer two route files? Export `manifestGET` and `initGET` instead:

```ts title="src/routes/api/c15t/init.ts"
import { createFileRoute } from '@tanstack/react-router';
import { createConsentServerRoute } from 'c15t/tanstack-start/api';

const { initGET } = createConsentServerRoute();

export const Route = createFileRoute('/api/c15t/init')({
  server: { handlers: { GET: initGET } },
});
```

Configuration comes from the options object, then the `C15T_BACKEND_URL` environment variable, then `VITE_C15T_BACKEND_URL`. Set `C15T_MANIFEST_URL` to override the manifest location.

## Prerendered and static builds

When a page is prerendered there is no visitor request at build time, so no geo headers exist. Render the strictest policy first and let the browser fix it up:

```ts title="src/consent-manifest.ts"
// Generated at build time with createStaticManifestModule() from
// c15t/tanstack-start/static, or fetched with loadStaticManifest().
export { consentManifest } from './generated/consent-manifest';
```

```tsx title="src/routes/__root.tsx"
import { createRootRoute } from '@tanstack/react-router';
import { ConsentBoundary, consentPrefetchHead } from 'c15t/tanstack-start';
import { createStaticConsentResolver } from 'c15t/tanstack-start/static';
import { consentManifest } from '../consent-manifest';

export const Route = createRootRoute({
  ssr: false,
  head: () => ({
    ...consentPrefetchHead({ backendURL: '/api/c15t' }),
  }),
  component: RootComponent,
});
```

`createStaticConsentResolver({ manifest, geoURL })` returns an `initial` result resolved with the strictest policy pack and a `resolved` promise that re-resolves once geo is known. `consentPrefetchHead()` adds an inline `<script>` to the route's `head()` that starts the same-origin init request before hydration, so the browser has an answer by the time the boundary mounts.

## Request middleware

`consentRequestMiddleware()` from `c15t/tanstack-start/middleware` normalizes the request once for every server route and server function. Register it in `src/start.ts` with `createStart(() => ({ requestMiddleware: [consentRequestMiddleware()] }))`, or attach it to a single route through `server.middleware`. Downstream code can read `context.consent` for the parsed `country`, `region`, `language`, and `gpc` values.
