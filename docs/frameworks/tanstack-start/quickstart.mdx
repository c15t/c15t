## Before you start

This guide sets up the recommended path for a TanStack Start app with server
rendering. On each request, a server function in the root loader reads the
visitor's consent cookie and location headers, resolves their policy from a
cached policy manifest, and hands the result to `ConsentRoot`. The banner is
part of the first HTML, and gated scripts can run right after hydration.

It needs a running Start server. For SPA mode, prerendered pages or a static
host, or to stream the page before consent resolves, see
[rendering](/docs/frameworks/tanstack-start/rendering).

You need an [Inth](https://inth.com) project. In the project, set the policy
rules for your regions, add your site's origin to the trusted origins, and copy
the backend URL. The URL is public configuration, not a secret.
[Choose your setup](/docs/concepts/choose-your-setup#decide-who-runs-the-consent-backend)
covers self-hosting and offline mode.

## Install c15t

<CommandTabs command="c15t@alpha @c15t/integrations@alpha" mode="install" />

`c15t` contains the TanStack Start adapter at `c15t/tanstack-start`.
`@c15t/scripts` holds the vendor loaders used below.

## Set the backend URL

Add the Inth backend URL and your vendor IDs to `.env`:

```dotenv title=".env"
VITE_C15T_BACKEND_URL=https://your-project.inth.app
VITE_POSTHOG_KEY=
VITE_X_PIXEL_ID=
```

Paste the backend URL exactly as Inth shows it. The server function and the
browser both read `VITE_C15T_BACKEND_URL`, and Vite writes it into both bundles
at build time, so rebuild after you change it. Leave a vendor ID empty to skip
that vendor. Keep secrets out of `VITE_` variables.

## Read location headers on every request

Register `consentRequestMiddleware` in `src/start.ts`. It reads the country and
region headers your host or CDN adds, such as `cf-ipcountry` or
`x-vercel-ip-country`, plus `accept-language` and the Global Privacy Control
header. It writes them onto the request in one format that the server function
reads.

<include src="../../shared/examples/tanstack-start/start.mdx" />

If `src/start.ts` already exists, add `consentRequestMiddleware()` to its
`requestMiddleware` list.

## Register your vendor scripts

Create `src/scripts.ts`. PostHog waits for measurement permission and X Pixel
waits for marketing permission, so your policy must include both categories.
PostHog uses its EU host; change `region` to `'us'` for a US project. Remove any
other PostHog or X Pixel loader from your app so each vendor loads once.

What each part does:

- **`getConsentState`** runs on the server. `createConsentStateHandler` reads
  the `c15t` cookie and the headers from the middleware, fetches the policy
  manifest from your backend, caches it in memory, and resolves this visitor's
  policy. Declare the `createServerFn()` call in your own module, as shown.
  Start's compiler finds server code by that call site, so a server function
  built inside a package does not work.
- **The loader** awaits the result. `consentLoaderOptions` stops the loader
  from running again on client-side navigation, since the visitor's consent
  state does not change between routes.
- **`ConsentRoot`** creates the consent runtime from that state, so the server
  HTML and the first browser render match. `initRoute={false}` sends the
  browser's requests straight to your backend URL.
- **`scripts`** stays in this module. A server function can only return
  serializable data, and vendor loaders contain functions.
- **The stylesheet** loads through `head()` with Vite's `?url` import.

If the backend does not answer within 500 ms, the server function gives up and
returns the cookie and header state. The page renders without the banner,
optional categories stay denied, and the browser resolves consent after it
loads.

## Gate your own features

Read a category's permission with `useConsent` from `c15t/tanstack-start`:

{/* example: fragment */}

```tsx title="src/components/marketing-banner.tsx"
import { useConsent } from 'c15t/tanstack-start';

export function MarketingBanner() {
  return useConsent('marketing') ? <aside>Spring sale</aside> : null;
}
```

`useConsent` returns the permission right now. Under an opt-out policy it can be
`true` before the visitor has chosen anything. Read
[how consent works](/docs/concepts/how-consent-works#a-permission-is-not-a-recorded-choice)
before you record or report choices. For iframes, use `ConsentGate`; see
[scripts and embeds](/docs/frameworks/tanstack-start/scripts).

## Check that it works

Build the app with `vite build`, start the production server, and open the site
in a private window with DevTools open on the Network tab. Test under a policy
that asks for a choice, such as an EU opt-in policy. Your host must send a
country header; locally, add `consentRequestMiddleware({ country: 'DE' })` for
the test only.

1. **Server HTML.** View the page source. It contains an element with
   `data-testid="consent-banner-root"`.
2. **Before a choice.** There are no requests to `posthog.com` or
   `static.ads-twitter.com`.
3. **Reject all.** The banner closes and the vendor requests stay absent.
4. **Reload and view source again.** The HTML no longer contains the banner,
   because the server read the stored rejection from the `c15t` cookie.
5. **Privacy settings.** The footer link opens the dialog with Measurement and
   Marketing off. Turn Measurement on and save. PostHog's `array.js` loads and
   X Pixel stays absent.
6. **Turn Measurement off again.** The page reloads and PostHog does not load.
