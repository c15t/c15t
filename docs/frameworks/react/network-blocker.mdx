## Add rules

Some SDKs are already on the page and send beacons or API calls of their own.
Add `networkBlocker` rules to the provider options to stop `fetch` and
`XMLHttpRequest` calls to those domains until the category is allowed. Load
vendor SDKs through [`scripts`](/docs/frameworks/react/scripts) first, so they
do not run at all before consent.

This partial example adds the option next to the existing `mode` and
`scripts`:

{/* example: fragment */}

```tsx title="src/consent.tsx"
const networkBlocker = {
  rules: [
    { id: 'google-analytics', domain: 'google-analytics.com', category: 'measurement' },
    { id: 'meta-pixel', domain: 'facebook.com', pathIncludes: '/tr', category: 'marketing' },
  ],
};

<ConsentProvider options={{ mode, scripts, networkBlocker }}>
```

## Verify the blocked requests

Open DevTools Network in a private window, under a policy that asks for
consent.

1. Before a choice, requests matching a rule are absent, and the console logs
   each blocked request.
2. Allow the rule's category and save. Matching requests go out.
3. Reject, reload, and check that they stay absent.
