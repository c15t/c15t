## Prepare one request snapshot

```ts
import { readStoredRecordsFromCookieHeader } from '@c15t/core/modules/persistence';
import { resolvePolicyRules, policyRulePresets } from '@c15t/schema';

const now = Date.now();
const prefetch = {
  now,
  initialRecords: readStoredRecordsFromCookieHeader(
    request.headers.get('cookie') ?? '',
    undefined,
    now
  ),
  initialPolicyResolution: resolvePolicyRules({
    rules: [policyRulePresets.europeOptIn()],
    countryCode: null,
    regionCode: null,
  }),
};
```

This offline example uses the Europe preset's unknown-geography fallback. For
hosted data, use the adapter's server transport helpers and canonical init mapping.
Next.js provides [prefetchInitialConsent](/docs/frameworks/next/server-side).

Pass `prefetch` through `options.prefetch` to `ConsentProvider`, with the same
transport configuration on server and browser. The provider uses the prepared
policy, records and clock for its initial render. It does not renew records or
fetch initialization again when complete prepared data is available.

Read `Sec-GPC` as a detected signal only when its exact value is `1`; pass it as
`initialPrivacySignals.gpc`. Do not manufacture a developer override from a
missing header. After mounting, actual detected GPC can record a separate standing
directive through the public signal setter without a choice or new init request.

## Preserve the record boundary

The storage reader preserves per-category times, partial choices, notice dismissals
and standing privacy directives. It also reads valid v2 choices without rewriting
them. A notice stored only in localStorage cannot suppress server HTML before
hydration because the server never received it.

The old `ssrData` provider option and `useSSRStatus` hook are removed. Use prepared
records and policy with `usePolicyResolution` and `usePromptRequirement`. Keep
pending and failed initialization hidden without treating a missing policy as
permission. See [v3 migration](/docs/upgrade-v3).
