## The /init request goes to your-project.inth.app

**Check.** In DevTools Network, the `GET` request to `/init` goes to
`your-project.inth.app` and fails.

**Fix.** Replace the placeholder URL in `hosted({ url })` in `src/consent.tsx`
with the backend URL from your Inth project, exactly as Inth shows it, then
rebuild.

## There is no banner

**Check.** In DevTools Network, find the `GET` request to `/init` on your
backend URL.

| What you see | Cause | Fix |
| --- | --- | --- |
| No `/init` request | `ConsentProvider` is not mounted, or an error stopped `src/consent.tsx` from rendering | Check the console for errors and render one provider at the app root, as in the [quickstart](/docs/frameworks/react/quickstart) |
| `/init` fails with a CORS error | Your site's origin is not trusted | Add the exact origin, including port in development, to the trusted origins in your Inth project |
| `/init` returns 200 | The policy for this visitor asks for no banner, or a stored choice is still valid | Inspect the active policy with the component below, or clear site data |

A policy with `prompt: 'none'` shows no banner by design, and so does a
returning visitor with a valid stored choice. [Policies](/docs/concepts/policies)
explains why a region may not show one.

## Inspect the active policy

Render this component inside `ConsentProvider`. It reads state and records no
choice:

{/* example: fragment */}

```tsx title="src/consent-policy-debug.tsx"
import { useSnapshot } from 'c15t/react';

export function ConsentPolicyDebug() {
  const snapshot = useSnapshot();
  const resolution = snapshot.resolution;

  return (
    <pre>
      {JSON.stringify(
        {
          status: resolution.status,
          policy: resolution.status === 'matched' ? resolution.policy.id : null,
          prompt: snapshot.promptRequirement,
          permissions: snapshot.effectivePermissions,
          location: snapshot.location,
          privacySignals: snapshot.privacySignals,
        },
        null,
        2,
      )}
    </pre>
  );
}
```

The component re-renders on every consent change. Remove it after you finish.
For a feature gate, use `useConsent('marketing')` or the category you need.

## A vendor loads before the visitor chooses

**Check.** Search `index.html`, your entry module and any tag manager for the
vendor's script or SDK initializer.

**Fix.** Remove every loader except the one in `options.scripts`. c15t only
gates scripts registered with it, and the network blocker cannot stop code that
runs before the provider renders. [Scripts and embeds](/docs/frameworks/react/scripts)
covers the options.

## The banner has no styles

**Check.** In DevTools Elements, the banner has classes but no rules apply.

**Fix.** Import `c15t/react/styles.css` once in the module that renders the
provider. With Tailwind 3, keep that import above the `@tailwind` directives
and add `@c15t/ui/postcss-tailwind3` before `tailwindcss` in your PostCSS
config. Without the plugin, Tailwind 3 drops c15t's rules or fails the build
with `` `@layer components` is used but no matching `@tailwind components` directive is present ``.
See [Tailwind CSS](/docs/customization/tailwind#set-up-tailwind-css-3).

## The console warns that theme tokens are no longer turned into CSS

**Check.** `options.theme` holds colors, radius or other tokens, and the page
has no `c15t-theme` style element. The provider only reads `consentActions`
and slot styles from `theme`.

**Fix.** Move the tokens to your CSS or render `ConsentTheme`, as shown in
[customize](/docs/frameworks/react/customize#change-colors-fonts-and-radius).

## The banner is missing from server-rendered HTML

**Check.** Your app uses React Router framework mode, Remix or another
server-rendered setup without a c15t adapter. There this is expected: the
browser resolves consent after hydration.

**Fix.** None is needed for consent to work.
[Rendering](/docs/frameworks/react/rendering#react-router-remix-and-other-server-rendered-apps)
explains the options.
