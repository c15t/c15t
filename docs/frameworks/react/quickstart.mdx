## Before you start

This guide sets up a client-rendered React app built with Vite. The browser
loads the page, asks the consent backend for the visitor's policy, then shows
the banner or runs the scripts the visitor allowed.

- **Next.js or TanStack Start?** Use that framework's guide from the
  [framework list](/docs/frameworks). Their adapters resolve consent on the
  server.
- **React Router framework mode, Remix or another server-rendered React app?**
  This guide still works. The server renders the page without consent state and
  the browser resolves it after hydration. Read
  [rendering](/docs/frameworks/react/rendering#react-router-remix-and-other-server-rendered-apps)
  for what that means for the first paint.

You need an [Inth](https://inth.com) project. In the project, set the policy
rules for your regions, add your site's origin to the trusted origins, and copy
the backend URL.
[Choose your setup](/docs/concepts/choose-your-setup#decide-who-runs-the-consent-backend)
covers self-hosting and offline mode.

## Install c15t

<CommandTabs command="c15t@alpha @c15t/integrations@alpha" mode="install" />

`c15t` contains the React adapter at `c15t/react`. `@c15t/integrations` holds the
vendor loaders used below.

## Register your vendor scripts

Create `src/scripts.ts`. PostHog waits for measurement permission and X Pixel
waits for marketing permission, so your policy must include both categories.
Remove any other PostHog or X Pixel loader from your app so each vendor loads
once.

<include src="../../shared/examples/react/scripts.mdx" />

Replace `phc_your_project_key` with your PostHog project key and
`your-pixel-id` with your X Pixel ID. PostHog uses its EU host; add
`region: 'us'` for a US project. Remove the loader for a vendor you don't use.

`loadMode: 'after-consent'` keeps the PostHog SDK off the page until the
visitor allows measurement. `cookieless_mode: 'never'` turns off PostHog's
cookieless capture. See [integrations](/docs/integrations/overview) for other
vendors.

## Mount the provider

Create `src/consent.tsx`. `ConsentProvider` creates the consent runtime and
loads the scripts. `ConsentBanner` and `ConsentDialog` render when the policy
asks for them, and `ConsentDialogLink` keeps preferences reachable after the
banner closes.

<include src="../../shared/examples/react/consent.mdx" />

Replace `https://your-project.inth.app` with your project's backend URL,
exactly as Inth shows it, including any path prefix.

Wrap your app with it in `src/main.tsx`:

<include src="../../shared/examples/react/main.mdx" />

Keep `Consent` mounted for the life of the app. If you use a client-side
router, render the router inside `Consent` so navigation does not remount the
provider. The stylesheet import in `src/consent.tsx` styles the banner and
dialog; import it once.

## Gate your own features

Read a category's permission with `useConsent` inside the provider:

{/* example: fragment */}

```tsx title="src/marketing-banner.tsx"
import { useConsent } from 'c15t/react';

export function MarketingBanner() {
	return useConsent('marketing') ? <aside>Spring sale</aside> : null;
}
```

`useConsent` returns the permission right now. Under an opt-out policy it can be
`true` before the visitor has chosen anything. Read
[how consent works](/docs/concepts/how-consent-works#a-permission-is-not-a-recorded-choice)
before you record or report choices. For iframes, use
[`ConsentGate`](/docs/frameworks/react/components/consent-gate).

## Check that it works

Build and preview the production bundle with `vite build` and `vite preview`,
then open the site in a private window with DevTools open on the Network tab.
Test under a policy that asks for a choice, such as an EU opt-in policy.

1. **Before a choice.** The banner shows. There are no requests to
   `posthog.com` or `static.ads-twitter.com`.
2. **Reject All.** The banner closes and the vendor requests stay absent.
3. **Reload.** The banner stays closed and the vendor requests stay absent.
4. **Privacy settings.** The footer link opens the dialog with **Analytics** (the
   `measurement` category) and **Marketing** off. Turn on **Analytics** and save. PostHog's `array.js` loads and
   X Pixel stays absent.
5. **Turn Analytics off again.** The page reloads and PostHog does not load.

If the banner never appears, check the Network tab for the request to
`/init` on your backend URL. [Troubleshooting](/docs/frameworks/react/troubleshooting)
covers the common causes. [Verify consent](/docs/guides/verify-consent) has the
full release checklist.
