## What GPP does

`ConsentGPP` from `@c15t/react/gpp` installs `window.__gpp`, the GPP 1.1 CMP
API, and keeps its GPP string in step with the visitor's choices. Prebid.js,
Google Ad Manager and other ad tech read US privacy signals from it.

## Turn on GPP

Render `ConsentGPP` inside `ConsentProvider`:

{/* example: fragment */}

```tsx title="src/consent.tsx"
import { ConsentGPP } from '@c15t/react/gpp';

<ConsentProvider options={{ mode, scripts }}>
	<ConsentGPP />
	{children}
</ConsentProvider>;
```

`ConsentGPP` renders nothing. It installs `__gpp` after it mounts and
removes it when it unmounts. It lives in its own entry, like
`@c15t/react/iab`, so apps that do not import it bundle none of the GPP
code. `@c15t/react` already depends on `@c15t/iab`; with the `c15t`
package, import from `c15t/react/gpp`.

The props are the GPP options listed below, for example
`<ConsentGPP usFallback="none" />`. It works the same with a runtime you
pass to `ConsentProvider` as `runtime`.

The GPP string follows the policy and location your backend resolves for the
visitor, so a US visitor's state comes from the backend. With `offline()`
mode, pass the state yourself, for example
`overrides: { country: 'US', region: 'CA' }`.

To add the TCF EU section for visitors under an `iab` policy, set up
[IAB TCF](/docs/frameworks/react/iab) as well.
