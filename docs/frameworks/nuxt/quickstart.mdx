## Before you start

This guide is for a Nuxt app that runs a Nuxt server, built with `nuxt build`
and deployed to Node or a serverless preset. The server resolves each
visitor's policy, so the banner is part of the first HTML. For static hosting
or `ssr: false`, follow
[static and SPA output](/docs/frameworks/nuxt/rendering#deploy-to-static-hosting)
instead. [Choose your setup](/docs/concepts/choose-your-setup) compares every
option.

The guide uses [Inth](https://inth.com) for policies and consent records.
Create a project, set its policy rules, add your site's origin to its trusted
origins, and copy the backend URL. To run the service yourself, use a
[self-hosted backend](/docs/self-host/overview) URL instead. Offline mode keeps
policies in your code and choices in the browser, with no consent records.
Not recommended for production environments.

## Install c15t

<CommandTabs command="c15t@alpha @c15t/scripts@alpha" mode="install" />

`c15t/vue` is the Nuxt module. You do not install a separate Nuxt package.

## Add the Nuxt module

Paste the backend URL from your Inth project, such as
`https://your-project.inth.app`, into `.env`. The URL is public;
it ends up in browser code.

```dotenv title=".env"
NUXT_PUBLIC_C15T_BACKEND_URL=https://your-project.inth.app
```

Register the module in `nuxt.config.ts`:

<include src="../../shared/examples/nuxt/nuxt-config.mdx" />

`manifest: 'server'` adds two routes to your Nuxt server,
`/api/c15t/manifest` and `/api/c15t/init`. The server downloads your project's
public policy manifest, caches it, and resolves each visitor from the request's
location and language headers. Consent saves still go to Inth.
[Data fetching](/docs/concepts/data-fetching) compares this with calling the
backend on every request.

## Mount the consent UI

Add `ConsentRoot` and a preferences link to `app.vue`:

<include src="../../shared/examples/nuxt/root.mdx" />

`ConsentRoot` renders the banner when the visitor's policy asks for one and
loads the preference dialog when it opens. `ConsentPreferencesLink` renders a
Privacy settings button that reopens preferences. It renders nothing until the
policy offers preferences.

The module registers these components and the consent composables, so you
write no imports and no `app.use()`. Keep `ConsentRoot` in `app.vue`, outside
`<NuxtPage />`, so it stays mounted across navigation. The components bring
their own styles.

## Register consent-gated scripts

Remove any existing PostHog or X Pixel snippet so each script loads once. Add
measurement and marketing to your Inth policy, then put the vendor IDs in
`.env`. An empty ID leaves that vendor out.

```dotenv title=".env"
VITE_POSTHOG_KEY=
VITE_X_PIXEL_ID=
```

Create `app/consent-scripts.ts`. PostHog waits for measurement permission and
uses its EU region; change `region` to `'us'` for a US project. X Pixel waits
for marketing permission.

<include src="../../shared/examples/nuxt/scripts.mdx" />

Register the scripts in `app/app.config.ts`:

<include src="../../shared/examples/nuxt/app-config.mdx" />

The module merges the `c15t` key of `app.config.ts` over its options in
`nuxt.config.ts`, then starts one script loader in the browser after
hydration. Put options that contain functions, such as `scripts`, `callbacks`
and `consentSource`, in `app.config.ts`. Module options in `nuxt.config.ts`
reach the browser as JSON, which drops functions.

`app.config.ts` is part of the browser bundle, so it cannot read
`runtimeConfig`. The file above reads the IDs from Vite's `VITE_` variables at
build time. Vendor IDs are public, so you can also write them into the file.

## Verify the setup

Build and start the production server with `nuxt build` and
`node .output/server/index.mjs`. Open the site in a private window with your
browser's DevTools on the Network tab, under a policy that asks for consent.

1. Load a page and view its source. The banner markup,
   `data-testid="consent-banner-root"`, is in the HTML. The Network tab shows
   no requests to `posthog.com`, `static.ads-twitter.com` or
   `youtube-nocookie.com`.
2. Click Reject all, then reload. The banner stays closed and the vendor
   requests stay absent.
3. Click Privacy settings, allow Measurement and save. PostHog's `array.js`
   loads and the video appears. X Pixel stays blocked until you allow
   Marketing.
4. Turn Measurement off and save. The page reloads, the video is gone and
   PostHog does not load again.

[Verify consent](/docs/guides/verify-consent) has the full release checklist.
