## Why is there no banner?

Check, in order:

1. The visitor's policy asks for one. A policy with prompt `none` shows no
   banner, which is common in opt-out regions. `useConsentSnapshot()`
   exposes `policyRule.prompt`, and [DevTools](/docs/frameworks/nuxt/components/dev-tools)
   shows the matched policy. See [why the banner may be absent](/docs/concepts/policies#why-the-banner-may-be-absent).
2. `ConsentRoot` is in `app.vue`, not inside a page that unmounts.
3. The backend answered. In the Network tab, `/api/c15t/init` returns 200 with
   `manifest: 'server'`, or your `manifestURL` does with `manifest: 'client'`.
   While resolution fails, c15t shows no UI and keeps every optional category
   denied.
4. A stored choice exists. Clear the `c15t` cookie and localStorage entry, or
   use a private window.

## The banner is not in the server HTML

Only request-time rendering with `manifest: 'server'`, or with `manifest`
unset, puts the banner in the HTML. Prerendered routes, routes with a
`prerender`, `swr`, `isr` or `cache` rule, `nuxt generate` output and
`ssr: false` send the same HTML to every visitor, so the banner appears after
the browser resolves the policy.

With server rendering, the render waits at most `timeoutMs` for the policy,
500 milliseconds by default. A slower backend renders the page without consent
UI and the browser resolves the policy after hydration. Check the server log
for backend errors, and raise `timeoutMs` if your backend is reachable but
slow.

## The banner comes back after a visitor rejects

- The save failed. Filter the Network tab by `subjects` and check that the
  `POST` to your backend returns 2xx. A CORS error means the site's origin is
  missing from your Inth project's trusted origins.
- `storageConfig.storageKey` differs between the module options and
  `app.config.ts`, so the choice is written under one name and read under
  another.
- A cache in front of Nuxt, such as a CDN, stores pages that Nitro renders per
  request. The module only recognizes Nuxt's own prerendering and `prerender`,
  `swr`, `isr` or `cache` route rules. Use a route rule for those pages, or
  have the CDN skip HTML. See
  [prerendered and cached routes](/docs/frameworks/nuxt/rendering#prerendered-and-cached-routes).

## Scripts never load, or load before consent

- The scripts are in `nuxt.config.ts`. Move `scripts` to `app/app.config.ts`,
  because module options drop functions.
- The vendor ID is empty at build time. `app.config.ts` cannot read
  `runtimeConfig`, so a value set only at runtime never reaches it.
- A second loader, such as the vendor's own Nuxt module or a `useHead` script,
  also loads the vendor. Remove it, or the vendor loads without consent.

## Static hosting returns 404 for /api/c15t/manifest

A static host has no Nuxt server routes. Use `manifest: 'client'` with an
absolute `manifestURL`, or leave `manifest` unset, as in
[deploy to static hosting](/docs/frameworks/nuxt/rendering#deploy-to-static-hosting).
If the browser reports a CORS error for the manifest, add your site's origin
to the Inth project's trusted origins.

## Every visitor gets the same policy on a static site

In `manifest: 'client'` mode the browser has no request location, so it
resolves the policy for an unknown location. Set `geoURL` to an endpoint that
returns the visitor's `country` and `region`.

## A composable throws "Kernel not found"

The composable ran outside the Nuxt app, for example in a server route or a
plain module. Call consent composables inside a component's `setup`.

## Every visitor resolves the same location

The server found no location header, or a visitor-supplied `x-c15t-country`
header won. Check which headers reach Nuxt and which ones you trust in
[geography headers](/docs/frameworks/nuxt/geography-headers).
