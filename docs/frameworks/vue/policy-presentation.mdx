title: Policy prompts and persistent preferences
description: Configure Vue and Nuxt presentation without changing policy decisions or stored choices.
---

## Configure presentation

```ts
import { c15tVue } from '@c15t/vue/vue-plugin';

app.use(c15tVue, {
  backendURL: 'https://your-consent-backend.example',
  presentation: {
    prompt: { direction: 'row', primaryActions: ['accept', 'reject'] },
    preferences: { defaults: { measurement: false } },
  },
  callbacks: {
    onChoiceRecorded({ snapshot, confirmed, actionAt }) {
      console.log(
        'Recorded choices',
        confirmed,
        actionAt,
        snapshot.explicitChoice
      );
    },
    onPermissionsChanged({ snapshot }) {
      console.log('Effective permissions', snapshot.effectivePermissions);
    },
  },
});
```

For Nuxt, put callback functions in `app.config.ts` under `c15t`. Nuxt runtime
configuration must remain serializable.

The policy determines whether the first layer requires a choice, displays a
notice, or stays hidden. Presentation controls layout and appearance. The shared
resolver restores required controls and keeps actions that require equal
prominence equivalent.

A notice provides a dismiss action. Dismissal records only that the notice was dismissed;
it does not grant or reject categories and does not call `onChoiceRecorded`.
Notice prompts never trap focus or lock scrolling.

## Keep preferences accessible

```vue
<script setup lang="ts">
import ConsentRoot from '@c15t/vue/consent-root';
import ConsentPreferencesLink from '@c15t/vue/runtime/components/consent-preferences-link.vue';
</script>

<template>
  <ConsentRoot />
  <footer><ConsentPreferencesLink>Privacy settings</ConsentPreferencesLink></footer>
</template>
```

The preferences link works before or after a choice and when the first layer is
hidden. The floating dialog trigger also remains available while a notice is
open. Keep a preferences link in your page when you disable the floating trigger.

Preferences offer accept, reject and save independently of the first layer. The preferences dialog stays open while a save is pending and preserves the draft if the request fails. A completed save does not close a dialog that the visitor closed and reopened, or interrupt a newer save.
Saving preferences does not dismiss an outstanding notice. Drafts read the
visitor's explicit choices before restrictions such as Global Privacy Control
are applied. Saving confirms only the displayed scope. If the policy changes
materially while a draft is open, the visitor must review the updated choices
before saving.

## Read current state

```ts
import {
  useExplicitChoice,
  useEffectivePermissions,
  usePromptRequirement,
  useConsentDraft,
} from '@c15t/vue/vue-plugin';

const receipt = useExplicitChoice();
const permissions = useEffectivePermissions();
const prompt = usePromptRequirement();
const draft = useConsentDraft();
```

These composables must run inside a Vue component with the plugin installed.
`useStoredConsent()` also returns the actual explicit receipt, or `null`; it no
longer returns a writable `{ categories, policies }` projection. Receipt
confirmation times remain unchanged during hydration and ordinary reads.
`useConsent()` is a read-only view of effective permissions; edit preferences
through `useConsentDraft()` and save them explicitly. `useConsentInit()` exposes
translation, location and branding data. Read policy state through
`usePolicyRule()` or `useConsentSnapshot()`.

Use effective permissions for gates. A stored grant can be expired, outside the
current policy scope, or restricted by a privacy signal. `ConsentFrame` uses the
core gate evaluator and supports a `placeholder` slot for blocked embeds.

## Server rendering and Nuxt

Nuxt reads raw choice, notice and standing privacy records from the request
cookie header. It transfers those records and their evaluation time through
Nuxt state, together with the resolved init response. The first client render
uses the same policy, records and clock as the server. Runtime hydration starts
after the app mounts and does not renew or rewrite receipts.

For plain Vue SSR, read the records on the server and serialize both values into
your application payload:

```ts
import { readStoredRecordsFromCookieHeader } from '@c15t/core/modules/persistence';

const initialRecords = readStoredRecordsFromCookieHeader(
  request.headers.get('cookie') ?? undefined,
  undefined,
  Date.now()
);

// Use the same resolved init response and records on server and client.
app.use(c15tVue, { backendURL, prefetch: resolvedInit, initialRecords });
```

The server cannot read localStorage. Visitors with an older notice acknowledgement
stored only in localStorage may see the notice again. New notice and standing
privacy records include cookie projections that Nuxt can read.

`onChoiceRecorded` fires only for explicit accept, reject or save operations.
`onPermissionsChanged` fires when effective permission values change. Registering
callbacks, reading records and dismissing notices do not replay choice events.
