## Before you start

This guide is for a Vue 3 single-page app built with Vite. The browser
resolves each visitor's policy after the page loads, so it works on any static
host. For a Vue app that renders on the server, use the c15t Nuxt module.
[Choose your setup](/docs/concepts/choose-your-setup) compares every option.

The guide uses [Inth](https://inth.com) for policies and consent records.
Create a project, set its policy rules, add your site's origin to its trusted
origins, and copy the backend URL. To run the service yourself, use a
[self-hosted backend](/docs/self-host/overview) URL instead. Offline mode keeps
policies in your code and choices in the browser, with no consent records.
Not recommended for production environments.

The c15t components share code with the Nuxt module and import Nuxt-style

## Install the Vue plugin

Paste the backend URL from your Inth project, such as
`https://your-project.inth.app`, into `.env.local`. The URL is
public; it ends up in browser code.

```dotenv title=".env.local"
VITE_C15T_BACKEND_URL=https://your-project.inth.app
```

Install the plugin from `c15t/vue/vue-plugin` in `src/main.ts`:

<include src="../../shared/examples/vue/main.mdx" />

`c15t/vue` is the Nuxt module. Do not pass it to `app.use()`.

The plugin creates the consent runtime for this app. When the app mounts, it
reads the visitor's stored choice, asks Inth for their policy, and starts the
script loader for the `scripts` you pass. The next section creates
`src/scripts.ts`.

## Register consent-gated scripts

Remove any existing PostHog or X Pixel snippet so each script loads once. Add
measurement and marketing to your Inth policy, then add the vendor IDs to
`.env.local`. An empty ID leaves that vendor out.

```dotenv title=".env.local"
VITE_POSTHOG_KEY=
VITE_POSTHOG_HOST=
VITE_X_PIXEL_ID=
```

Set `VITE_POSTHOG_HOST` to the API host shown in your PostHog project. Restart
Vite after you change these values.

Create `src/scripts.ts`. PostHog waits for measurement permission. X Pixel
waits for marketing permission.

## Mount the consent UI

<include src="../../shared/examples/vue/app.mdx" />

`ConsentRoot` renders the banner when the visitor's policy asks for one and
loads the preference dialog when it opens. `ConsentPreferencesLink` renders a
button that reopens preferences, labelled with the dialog's title in the
visitor's language: Privacy Settings in English. It renders nothing until the
policy offers preferences. Replace `HomePage` with your own content or router
view. Keep `ConsentRoot` in the root component so it stays mounted. The
components bring their own styles; there is no stylesheet to import.

## Gate an embed

Wrap third-party iframes in `ConsentGate`. The iframe does not exist in the
page until its category is allowed, and it is removed when the visitor
withdraws permission.

## Verify the setup

Build and preview the production app with `vite build` and `vite preview`.
Open it in a private window with your browser's DevTools on the Network tab,
under a policy that asks for consent.

1. Load the page. A request to your backend's `/init` resolves the policy and
   the banner appears. No requests to `posthog.com`,
   `static.ads-twitter.com` or `youtube-nocookie.com` appear.
2. Click Reject all, then reload. The banner stays closed and the vendor
   requests stay absent.
3. Click Privacy Settings, allow Measurement and save. PostHog's `array.js`
   loads and the video appears. X Pixel stays blocked until you allow
   Marketing.
4. Turn Measurement off and save. The page reloads, the video is gone and
   PostHog does not load again.

[Verify consent](/docs/guides/verify-consent) has the full release checklist.
