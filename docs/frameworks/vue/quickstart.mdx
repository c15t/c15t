## Before you start

This guide is for a Vue 3 single-page app built with Vite. The build bundles
your project's public policy, and the browser resolves each visitor's policy
from it after the page loads, so it works on any static host. For a Vue app that renders on the server, use the c15t Nuxt module.
[Choose your setup](/docs/concepts/choose-your-setup) compares every option.

The guide uses [Inth](https://inth.com) for policies and consent records.
Create a project, set its policy rules, add your site's origin to its trusted
origins, and copy the backend URL. To run the service yourself, use a
[self-hosted backend](/docs/self-host/overview) URL instead. Offline mode keeps
policies in your code and choices in the browser, with no consent records.
Not recommended for production environments.

Bundling the policy at build time is the recommended production setup.
Rebuild after changing policies, translations or vendors.

## Add the Vite plugins

Add two plugins to `vite.config.ts`. The c15t components share code with the
Nuxt module and import Nuxt-style module names; `c15tVue()` from
`c15t/vue/vite` resolves those names in a plain Vue app. `consentManifest`
from `c15t/build` bundles your policy.

<include src="../../shared/examples/vue/vite-config.mdx" />

`https://benchmarks-inth.inth.app` is a demo project, so the snippet runs as
is. Replace it with your project's backend URL, including any path prefix, or
set `VITE_C15T_BACKEND_URL` when you build.

`consentManifest` downloads your project's public policy from `/manifest` when
`vite build` or `vite dev` starts, and writes it to `src/c15t-manifest.ts`.
Add that file to `.gitignore`.

## Install the Vue plugin

Install the plugin from `c15t/vue/vue-plugin` in `src/main.ts`:

<include src="../../shared/examples/vue/main.mdx" />

Use the same backend URL as in `vite.config.ts`; consent choices go to it.
Vite reads `VITE_C15T_BACKEND_URL` at build time for both files, so set it
before you build, not when you serve the files.

`c15t/vue` is the Nuxt module. Do not pass it to `app.use()`.

The plugin creates the consent runtime for this app. When the app mounts, it
reads the visitor's stored choice, resolves their policy, and starts the
script loader for the `scripts` you pass. `manifest: 'client'` with
`manifestSnapshot` resolves the policy from the bundled snapshot, with no
`/manifest` or `/init` request. The browser does not know the visitor's
location, so without `geoURL`, or a `country` and `region` passed to
`ConsentRoot`, every visitor gets the policy your project assigns when the
location is unknown. Configure that fallback rule in your project, or see
[rendering](/docs/frameworks/vue/rendering#resolve-from-the-manifest-in-the-browser)
for `geoURL`.

To apply policy edits without rebuilding, remove `consentManifest`, `manifest`
and `manifestSnapshot`. The plugin then requests the policy from the backend's
`/init` on every page load, and the backend resolves the visitor's location.
The next section creates `src/scripts.ts`.

## Mount the consent UI

<include src="../../shared/examples/vue/app.mdx" />

`ConsentRoot` renders the banner when the visitor's policy asks for one and
loads the preference dialog when it opens. `ConsentPreferencesLink` renders a
button that reopens preferences. Without slot content, its label is the
dialog's title in the visitor's language: Privacy Settings in English. It
renders nothing until the policy offers preferences. Replace the `<main>`
element with your own content or router view. Keep `ConsentRoot` in the root
component so it stays mounted. The components bring their own styles; there
is no stylesheet to import.

## Gate an embed

Wrap third-party iframes in `ConsentGate`. The iframe does not exist in the
page until its category is allowed, and it is removed when the visitor
withdraws permission.

## Verify the setup

Build and preview the production app with `vite build` and `vite preview`.
Open it in a private window with your browser's DevTools on the Network tab,
under a policy that asks for consent.

1. Load the page. The bundled manifest resolves the policy and the banner
   appears, with no `/manifest` or `/init` request. Test the unknown-location
   rule, or supply `geoURL` if you need regional policies. No requests to
   `posthog.com` or `youtube-nocookie.com` appear.
2. Click **Reject All**, then reload. The banner stays closed and the vendor
   requests stay absent.
3. Click **Privacy settings**, turn on **Analytics** (the `measurement` category) and save. PostHog's `array.js`
   loads and the video appears.
4. Turn **Analytics** off and save. The page reloads, the video is gone and
   PostHog does not load again.
