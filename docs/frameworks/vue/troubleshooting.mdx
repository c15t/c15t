## Vite fails to pre-bundle c15t's .vue files

**Check.** `vite dev` reports an error from dependency optimization for a
`.vue` file under `@c15t/vue`, or `manifest()` throws `c15t: manifest() has
no backend URL`. `consentManifest()` is missing from the `plugins` array of
`vite.config.ts`.

**Fix.** Add `consentManifest()` from `c15t/vue/vite` to the `plugins` array,
next to `@vitejs/plugin-vue`, and set `VITE_C15T_BACKEND_URL`. See the
[quickstart](/docs/frameworks/vue/quickstart#add-the-vite-plugin).

## app.use() throws "pass `mode`"

**Check.** The plugin options have no `mode`. Earlier v3 alphas took
`backendURL`, `manifest`, `manifestURL` and `manifestSnapshot` on the plugin.

**Fix.** Pass `mode: manifest()`, `hosted()` or `offline()` from
`c15t/vue/vue-plugin`. Move `backendURL` into the mode, such as
`hosted({ backendURL })`, or let `consentManifest()` supply it.

## app.use() fails or does nothing

**Check.** Look at where you import the plugin. `c15t/vue` is the Nuxt module
and is not a Vue plugin.

**Fix.** Import the plugin from `c15t/vue/vue-plugin`.

## A composable throws "Kernel not found"

**Check.** The component is outside the app that installed `c15tVue`, for
example in a separate `createApp()` instance, or the composable ran outside
`setup`.

**Fix.** Install the plugin on the app that renders the component, and call
composables inside `setup`.

## Why is there no banner?

**Check.** [DevTools](/docs/frameworks/vue/components/dev-tools) shows the
matched policy. With `hosted()`, find the `/init` request in the Network tab;
with `manifest({ source: 'runtime' })`, the `/manifest` request.

**Fix.** Work through these causes in order:

1. **The visitor's policy asks for no banner.** A policy with prompt `none`
   shows no banner, which is common in opt-out regions. See
   [why the banner may be absent](/docs/concepts/policies#why-the-banner-may-be-absent).
2. **`manifest()` resolves the unknown-location policy.** Without `inputs`
   or `geoURL`, every visitor gets the policy your project assigns when the
   location is unknown. Check that rule, then rebuild.
3. **`ConsentRoot` is inside a route that unmounts.** Put it in the root
   component.
4. **The backend did not answer.** With `hosted()`, `/init` must return
   200; with a runtime manifest, `/manifest` must. A CORS error means your site's origin is missing from the
   Inth project's trusted origins. While resolution fails, c15t shows no UI and
   keeps every optional category denied.
5. **A stored choice exists.** Clear the `c15t` cookie and localStorage entry,
   or use a private window.

## The app throws IABUnavailableError

**Check.** The error has the code `C15T_IAB_UNAVAILABLE` and reads
"c15t: this visitor's policy uses IAB TCF, but `iab` is not set." The
visitor's policy uses the `iab` model and the backend sent its vendor list,
but the plugin has no `iab` option, or has `iab: false` or
`iab: { enabled: false }`. The standard banner does not handle the IAB model,
so c15t throws rather than leave the visitor with no consent UI.
`app.use()` throws when the policy arrives with `prefetch`; otherwise the
error is uncaught once the policy resolves, and `ConsentRoot` renders
nothing.

**Fix.** If the site uses IAB TCF, pass `iab` to the plugin, such as
`app.use(c15tVue, { iab: {} })`. See [IAB TCF](/docs/frameworks/vue/iab).
If it does not, remove the `iab` model from the policy for that region in
your Inth project or policy pack. A backend that answers `gvl: null` turns
IAB off for that request, and nothing throws.

## Tokens in my CSS do not apply

**Check.** The c15tVue plugin appends a `<style id="c15t-css-vars">` element to
`<head>` when you install it. The element sets every token, including the
defaults. A `:root` rule in your stylesheet for the same variable competes
with it on source order, so it may lose.

**Fix.** Set values through the plugin's `tokens` option. See
[customize](/docs/frameworks/vue/customize#set-theme-tokens).

## A script loads twice, or before consent

**Check.** Look for the vendor in both the plugin's `scripts` and a
`createScriptLoader` call.

**Fix.** Keep only `scripts`.

**Check.** Look for the vendor's own snippet in `index.html`, or SDK
initialization in your code.

**Fix.** Remove it so c15t is the only loader.

## The page flashes without the banner on a server-rendered Vue app

**Check.** c15t does not support server rendering for plain Vue.

**Fix.** Use the c15t Nuxt module. See
[server rendering without Nuxt](/docs/frameworks/vue/rendering#server-rendering-without-nuxt).

## Names from an earlier alpha are missing

**Check.** An import or component from an earlier v3 alpha fails to resolve,
such as `c15t/vue/consent-root`, `ConsentPreferencesLink` or the default
export of `c15t/vue/vite`. The v3 alphas removed names that never shipped in
a stable release, with no alias.

**Fix.** Use the current names:

| Removed | Use instead |
| --- | --- |
| Vue plugin options `backendURL`, `manifest`, `manifestSnapshot`, `manifestURL`, `customFetch`, `domain` | `mode`, a factory from `c15t/vue/vue-plugin` that takes them |
| The default `c15tVue` export of `c15t/vue/vite` | `consentManifest` from `c15t/vue/vite`. The Vue app plugin keeps the name `c15tVue`. |
| `c15t/vue/consent-root`, `c15t/vue/consent-widget` | Named exports from `c15t/vue/vue-plugin` |
| `ConsentPreferencesLink`, `runtime/components/consent-preferences-link.vue` | `ConsentDialogLink`, `consent-dialog-link.vue` |
| `ConsentFrame` | `ConsentGate` |
| `hosted({ url })` | `hosted({ backendURL })`, or `VITE_C15T_BACKEND_URL` |
