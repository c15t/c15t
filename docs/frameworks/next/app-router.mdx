## Install and configure Inth

This setup requires a Next.js server and uses a cached manifest for policy
resolution. For `output: 'export'`, use
[static export](/docs/frameworks/next/static-export).

[Create an Inth project](/docs/guides/inth), configure policy rules and allow your
app's origin. Set `NEXT_PUBLIC_C15T_BACKEND_URL` to the exact absolute backend
endpoint supplied by Inth. This URL is public; do not put credentials in it.

<CommandTabs command="c15t" mode="install" />

## Share the consent URLs

Create this file at the project root. It contains plain configuration and can
be imported by route handlers, Server Components and Client Components.

```ts title="consent.config.ts"
import { defineConsentConfig } from 'c15t/next';

const backendURL = process.env.NEXT_PUBLIC_C15T_BACKEND_URL;
if (!backendURL) throw new Error('Set NEXT_PUBLIC_C15T_BACKEND_URL');

export const consentConfig = defineConsentConfig({
  backendURL,
  manifestURL: '/api/consent/manifest',
  initURL: '/api/consent/init',
});
```

## Serve the manifest and local init routes

The manifest route reuses public policy data from Inth. The init route resolves
that data using the current request's location, language and privacy signals.
Neither route proxies consent submissions; those still go to Inth.

```ts title="app/api/consent/manifest/route.ts"
import { createNextConsentRouteHandlers } from 'c15t/next/api';
import { consentConfig } from '../../../../consent.config';

export const { manifestGET: GET } =
  createNextConsentRouteHandlers(consentConfig);
```

```ts title="app/api/consent/init/route.ts"
import { createNextConsentRouteHandlers } from 'c15t/next/api';
import { consentConfig } from '../../../../consent.config';

export const { GET } = createNextConsentRouteHandlers(consentConfig);
```

These paths assume `app/` is at the project root. If you use `src/app/`, adjust
the config imports to its location.

## Resolve consent in the root layout

```tsx title="app/layout.tsx"
import type { ReactNode } from 'react';
import {
  ConsentBanner,
  ConsentBoundary,
  ConsentDialog,
  ConsentDialogLink,
} from 'c15t/next';
import { prefetchInitialConsent } from 'c15t/next/server';
import { consentConfig } from '../consent.config';
import 'c15t/next/styles.css';

export default async function RootLayout({ children }: { children: ReactNode }) {
  const config = await prefetchInitialConsent({ config: consentConfig });

  return (
    <html lang="en">
      <body>
        <ConsentBoundary config={config} consent={consentConfig}>
          {children}
          <ConsentBanner />
          <ConsentDialog />
          <footer>
            <ConsentDialogLink>Privacy settings</ConsentDialogLink>
          </footer>
        </ConsentBoundary>
      </body>
    </html>
  );
}
```

The helper reads request cookies and geographic headers, then resolves policy
from the manifest. Awaiting it lets the server render the resolved prompt. The
boundary receives the same prepared state so the first client render agrees.
The `config` prop is the prepared visitor state; `consent` is the shared URL
configuration. They serve different purposes.

To let the page render while resolution is pending, remove `async` and pass the
promise returned by `prefetchInitialConsent` without awaiting it. The consent
prompt stays hidden until resolution completes. Reading request context still
requires request rendering; this does not turn the layout into a static export.

## Add client behavior inside the boundary

Consent hooks and browser callbacks belong in Client Components. Keep request
helpers in server files. For vendor callbacks, put a client wrapper around this
boundary and pass `scripts` as a top-level prop, following
[script loading](/docs/frameworks/next/script-loader). Do not mount a second
provider or also load the vendor through `next/script`.

## Verify the manifest path

Inspect server requests and confirm that consent resolution reads the manifest
instead of calling Inth `/init`. Warm requests should reuse policy data according
to its cache headers. Consent choices should still post to Inth `/subjects`.

Test a new visitor, a returning rejection and two locations. Missing geographic
headers must follow your unknown-location rule. See
[data fetching](/docs/frameworks/next/data-fetching) for cache defaults,
geography, regular `/init`, offline mode and failure handling, then run
[the consent checks](/docs/guides/verify-consent).
