## Choose how to manage consent

We recommend [Inth](/docs/guides/inth) for managed policy and consent records.
This guide uses cached manifests for request-time resolution and a Next.js
rewrite so browser consent requests stay on your origin.

| Mode | What you manage |
| --- | --- |
| Inth hosted | Configure policy and allowed app origins; Inth runs the backend and stores submissions. |
| [Self-hosted](/docs/self-host/quickstart) | Run the c15t backend and database. Use the same hosted transport and rewrite setup with your backend endpoint. |
| [Offline](/docs/frameworks/next/data-fetching#use-offline-mode-deliberately) | Bundle policy rules and keep choices in browser storage. No consent backend requests or backend records. |

This setup requires a Next.js server. For `output: 'export'`, use
[static export](/docs/frameworks/next/static-export), which can still connect to
Inth directly from the browser.

## Install c15t and configure your backend

[Create an Inth project](/docs/guides/inth), configure its policy rules and allow
your app's origin. Copy its backend endpoint for the upstream configuration.

If you chose self-hosting, complete the
[backend quickstart](/docs/self-host/quickstart) and use its public endpoint in
the steps below. Offline setups do not need an endpoint or rewrite; use the
[offline example](/docs/frameworks/next/data-fetching#use-offline-mode-deliberately).

## Keep browser requests on your origin

Set `C15T_BACKEND_URL` to the absolute endpoint supplied by Inth or your
self-hosted backend, including any path prefix. Add this fallback rewrite to your existing Next.js configuration:

```ts title="next.config.ts"
import type { NextConfig } from 'next';

const backendURL = process.env.C15T_BACKEND_URL;
if (!backendURL) throw new Error('Set C15T_BACKEND_URL');
const upstreamURL = backendURL.replace(/\/$/, '');

const config: NextConfig = {
  async rewrites() {
    return {
      fallback: [
        {
          source: '/api/c15t/:path*',
          destination: `${upstreamURL}/:path*`,
        },
      ],
    };
  },
};

export default config;
```

The local manifest and init routes below take precedence. Other requests,
including `POST /api/c15t/subjects`, pass through the rewrite to Inth. The browser
uses your site's origin for consent traffic. The backend URL is a public service
endpoint. This server environment variable configures the upstream destination;
the browser only needs the relative `/api/c15t` URLs.

Restart Next.js after changing the rewrite. Keep this catch-all in `fallback`,
not `beforeFiles`, so it cannot bypass the local route handlers.

## Share the consent URLs

Create this file at the project root. Server prefetch and the client boundary
share these first-party URLs:

```ts title="c15t.config.ts"
import { defineConsentConfig } from 'c15t/next';

export const consentConfig = defineConsentConfig({
  backendURL: '/api/c15t',
  manifestURL: '/api/c15t/manifest',
  initURL: '/api/c15t/init',
});
```

## Serve the manifest and local init routes

Both handlers fetch the absolute upstream endpoint. Do not pass the browser's
`backendURL: '/api/c15t'` to these handlers: its derived manifest URL would point
back to the local manifest handler and recurse.

```ts title="app/api/c15t/manifest/route.ts"
import { createNextConsentRouteHandlers } from 'c15t/next/api';

const backendURL = process.env.C15T_BACKEND_URL;
if (!backendURL) throw new Error('Set C15T_BACKEND_URL');

export const { manifestGET: GET } =
  createNextConsentRouteHandlers({ backendURL });
```

```ts title="app/api/c15t/init/route.ts"
import { createNextConsentRouteHandlers } from 'c15t/next/api';

const backendURL = process.env.C15T_BACKEND_URL;
if (!backendURL) throw new Error('Set C15T_BACKEND_URL');

export const { GET } = createNextConsentRouteHandlers({ backendURL });
```

The manifest route reuses public policy data from Inth. The init route resolves
that data using the current request's location, language and privacy signals.
The rewrite handles consent submissions separately.

These paths assume `app/` is at the project root. If you use `src/app/`, adjust
the layout's config import to its location.

## Resolve consent in the root layout

```tsx title="app/layout.tsx"
import type { ReactNode } from 'react';
import {
  ConsentBanner,
  ConsentBoundary,
  ConsentDialog,
  ConsentDialogLink,
} from 'c15t/next';
import { prefetchInitialConsent } from 'c15t/next/server';
import { consentConfig } from '../c15t.config';
import 'c15t/next/styles.css';

export default async function RootLayout({ children }: { children: ReactNode }) {
  const config = await prefetchInitialConsent({ config: consentConfig });

  return (
    <html lang="en">
      <body>
        <ConsentBoundary config={config} consent={consentConfig}>
          {children}
          <ConsentBanner />
          <ConsentDialog />
          <footer>
            <ConsentDialogLink>Privacy settings</ConsentDialogLink>
          </footer>
        </ConsentBoundary>
      </body>
    </html>
  );
}
```

The helper reads request cookies and geographic headers, then resolves policy
from the manifest. Awaiting it lets the server render the resolved prompt. The
boundary receives the same prepared state so the first client render agrees.
The `config` prop is the prepared visitor state; `consent` is the shared URL
configuration. They serve different purposes.

To let the page render while resolution is pending, remove `async` and pass the
promise returned by `prefetchInitialConsent` without awaiting it. The consent
prompt stays hidden until resolution completes. Reading request context still
requires request rendering; this does not turn the layout into a static export.

## Add client behavior inside the boundary

Consent hooks and browser callbacks belong in Client Components. Keep request
helpers in server files. For vendor callbacks, put a client wrapper around this
boundary and pass `scripts` as a top-level prop, following
[script loading](/docs/frameworks/next/script-loader). Do not mount a second
provider or also load the vendor through `next/script`.

## Verify the manifest path

Inspect server requests and confirm that consent resolution reads the manifest
instead of calling Inth `/init`. Warm requests should reuse policy data according
to its cache headers. In the browser, consent choices should post to `/api/c15t/subjects`; the rewrite
forwards them to Inth `/subjects`.

Test a new visitor, a returning rejection and two locations. Missing geographic
headers must follow your unknown-location rule. See
[data fetching](/docs/frameworks/next/data-fetching) for cache defaults,
geography, regular `/init`, offline mode and failure handling, then run
[the consent checks](/docs/guides/verify-consent).
