## Compose policy actions

```tsx
import { ConsentBanner, ConsentDialogLink } from '@c15t/nextjs';

export function PrivacyControls() {
  return (
    <>
      <ConsentBanner.Root>
        <ConsentBanner.Card>
          <ConsentBanner.Title />
          <ConsentBanner.Description />
          <ConsentBanner.PolicyActions />
        </ConsentBanner.Card>
      </ConsentBanner.Root>
      <ConsentDialogLink>Privacy settings</ConsentDialogLink>
    </>
  );
}
```

Render within a provider alongside the preferences dialog. PolicyActions renders
the required choice or dismiss controls using resolved host presentation.
Accept and reject have equivalent default prominence and reachability.

`useHeadlessConsentUI` exposes resolved actions, constraints, rights and diagnostics
when you build controls yourself. Headless hosts own rendering, focus management
and persistent rights access. Inspect `promptRequirement`; a receipt alone never
hides a required notice. Saving preferences does not dismiss it.

Use `useConsentDraft` for editable unmasked choices and `useEffectivePermissions`
for processing. A stale draft requires review before saving. See the
[policy guide](/docs/frameworks/next/policy-packs) for provider configuration.
