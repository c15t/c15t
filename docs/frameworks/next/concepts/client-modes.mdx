title: Transport modes
description: Select a hosted backend or local rules with a transport factory.
---

## Hosted

```tsx
import { ConsentProvider, hosted } from '@c15t/nextjs';

<ConsentProvider
  options={{ mode: hosted({ url: 'https://consent.example.com' }) }}
>
  {children}
</ConsentProvider>;
```

## Offline

```tsx
import { ConsentProvider, offline } from '@c15t/nextjs';

<ConsentProvider
  options={{
    mode: offline({
      policyRules: [
        {
          id: 'default',
          match: { isDefault: true },
          model: 'opt-in',
          prompt: 'choice',
        },
      ],
    }),
  }}
>
  {children}
</ConsentProvider>;
```

Offline mode resolves local rules without network requests. Browser persistence
is independent of the transport. Cookie records can be used for server rendering;
offline mode does not provide central record storage or trusted identity linkage.

For a custom producer use `custom(transport)` with a `KernelTransport` that returns
the canonical policy and record contract. Old mode strings and endpoint-handler
bridges are removed. Initialization failure never becomes allow-by-default.
See [v3 migration](/docs/upgrade-v3) for deployment compatibility.
