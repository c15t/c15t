## Server-prepared initialization

Await `prefetchInitialConsent()` in a Server Component and pass its result to `ConsentBoundary`. The configuration contains a prepared policy resolution, raw stored records, and the request's evaluation clock. The server and first client render use that same input.

A successful hosted prefetch makes one server `/init` request and zero browser `/init` requests during hydration. A manifest prefetch resolves policy locally from the manifest. A prepared failed or no-match outcome is still authoritative and cannot retain a previous permissive policy.

See [Server-side consent](/docs/frameworks/next/server-side) for App Router, Pages Router, and static-route examples.

## Browser initialization

A boundary without a prepared policy initializes through its configured transport after mounting. If `C15tPrefetch` already started a matching browser request, hosted initialization consumes that request once. A failed early request falls back to a normal request.

While resolution is pending, optional categories stay denied. Network failure does not turn missing policy into permission. Use the public `usePolicyResolution`, `usePromptRequirement`, and `useEffectivePermissions` hooks to read those separate states.

## Choices, notices, and privacy signals

A `choice` prompt requests category choices. A `notice` prompt offers dismissal, which never records a category choice or sends a consent save. A `none` prompt stays hidden. Keep `ConsentDialogTrigger` or `ConsentDialogLink` outside the prompt so visitors can still open privacy preferences.

Hydration preserves receipt times and fingerprints. Receipt expiry and material policy changes can reopen a prompt without rewriting stored consent. Detected GPC and standing opt-out directives can restrict effective permissions while preserving the original explicit choice.

## Callbacks

Register callbacks on the boundary's `options`. `onChoiceRecorded` reports accepted explicit category choices. `onPermissionsChanged` reports effective permission changes, including changes caused by policy, expiry, or privacy signals. Registering a callback does not replay an earlier event.

```tsx
'use client';

import type { ReactNode } from 'react';
import { ConsentBoundary, type InitialConsentConfig } from '@c15t/nextjs';

export function Consent({
  config,
  children,
}: {
  config: InitialConsentConfig;
  children: ReactNode;
}) {
  return (
    <ConsentBoundary
      config={config}
      backendURL="/api/c15t"
      options={{
        callbacks: {
          onChoiceRecorded: ({ confirmed, actionAt }) => {
            console.log('Categories confirmed', confirmed, actionAt);
          },
          onPermissionsChanged: ({ snapshot }) => {
            console.log('Effective permissions', snapshot.effectivePermissions);
          },
        },
      }}
    >
      {children}
    </ConsentBoundary>
  );
}
```
