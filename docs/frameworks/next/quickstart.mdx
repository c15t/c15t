## Choose your rendering path

| Next.js deployment | Guide | Where consent initializes |
| --- | --- | --- |
| App Router with a server | [App Router](/docs/frameworks/next/app-router) | Request helper and client boundary |
| Pages Router with a server | [Pages Router](/docs/frameworks/next/pages-router) | `getServerSideProps` or browser initialization |
| `output: 'export'` | [Static export](/docs/frameworks/next/static-export) | Browser, using an external backend or local policy |

A Next.js application can mix dynamic and prerendered routes. Choose per route
whether you need visitor-specific consent in the initial HTML. Reading request
cookies in a layout requires a request context; do not put request helpers in a
layout that must remain fully static.

## What every path needs

Install a compatible v3 `@c15t/nextjs` package, import its stylesheet once, and
mount the banner, dialog and persistent preferences link inside one consent
boundary. Hosted examples require a reachable consent backend with policy rules
and your application's origin configured.

After setup, [register optional scripts](/docs/frameworks/next/script-loader)
and [verify requests and persistence](/docs/guides/verify-consent). A visible
banner alone does not establish that analytics wait for consent.
