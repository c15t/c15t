## Add rules to your ConsentRoot

The network blocker stops `fetch` and `XMLHttpRequest` calls to domains you
list until the visitor grants their category. Use it for beacons and API
calls that bypass script loading, such as a pixel fired by an SDK that is
already on the page.

Pass `networkBlocker` to the `ConsentRoot` in the client wrapper from the
[App Router](/docs/frameworks/next/app-router) or
[Pages Router](/docs/frameworks/next/pages-router) guide. Keep the rules in
the client file; `onRequestBlocked` is a function and cannot cross from a
Server Component.

```tsx title="components/consent.tsx"
'use client';

import type { ReactNode } from 'react';
import { ConsentBanner, ConsentDialog, ConsentRoot } from 'c15t/next';
import type { ConsentRootProps } from 'c15t/next';
import { consentConfig } from '../c15t.config';

const networkBlocker: NonNullable<ConsentRootProps['networkBlocker']> = {
  rules: [
    { id: 'google-analytics', domain: 'google-analytics.com', category: 'measurement' },
    { id: 'meta-pixel', domain: 'facebook.com', pathIncludes: '/tr', category: 'marketing' },
  ],
};

export function Consent({
  children,
  state,
}: {
  children: ReactNode;
  state: ConsentRootProps['state'];
}) {
  return (
    <ConsentRoot state={state} config={consentConfig} networkBlocker={networkBlocker}>
      {children}
      <ConsentBanner />
      <ConsentDialog />
    </ConsentRoot>
  );
}
```

Keep the page content inside `ConsentRoot`. Blocking starts when it renders,
so components outside it that send requests while rendering, or modules
evaluated before it, are not covered. See the limits below.
