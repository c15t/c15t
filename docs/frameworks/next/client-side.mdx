## When to initialize in the browser

This setup has the fewest files. The browser calls your Inth backend's `/init`
after the page loads, so the server does no consent work and every page can be
static. The HTML is the same for every visitor, and the banner appears after
hydration.

Use it when you do not need the banner in the server HTML and do not want a
manifest route. For a server app, the [App Router](/docs/frameworks/next/app-router)
and [Pages Router](/docs/frameworks/next/pages-router) guides resolve consent
on the server and make no `/init` request per visit. For `output: 'export'`,
follow [static export](/docs/frameworks/next/static-export).
[Rendering and deployment](/docs/frameworks/next/rendering) compares every
path.

Until the policy resolves, optional categories stay denied and the banner
stays hidden.

## Configure one backend URL

[Create an Inth project](https://inth.com), set its policy rules and add your
site's origin to its trusted origins. A self-hosted backend works the same way
with its own URL.

<CommandTabs command="c15t@alpha @c15t/scripts@alpha" mode="install" />

Set `NEXT_PUBLIC_C15T_BACKEND_URL` to the backend URL from your Inth project and
create `c15t.config.ts` at the project root:

```ts title="c15t.config.ts"
import { defineConsentConfig } from 'c15t/next';

const backendURL = process.env.NEXT_PUBLIC_C15T_BACKEND_URL;
if (!backendURL) {
	throw new Error('Set NEXT_PUBLIC_C15T_BACKEND_URL to your Inth backend URL');
}

export const consentConfig = defineConsentConfig({ backendURL });
```

A config with only `backendURL` initializes through `${backendURL}/init` and
posts choices to `${backendURL}/subjects`. It does not turn on manifest mode or
create routes.

## Optional same-origin rewrite

A [same-origin rewrite](/docs/frameworks/next/optimization#keep-browser-consent-requests-on-your-origin)
from `/api/c15t` to the backend saves the browser a separate connection to the
backend's domain. It needs a Next.js server or a proxy at your host.

## Verify browser initialization

Open the production build in a fresh browser session with DevTools open.

1. The browser calls `${backendURL}/init` once, then shows the banner. No
   PostHog or X Pixel request runs.
2. Click **Reject all** and reload. The banner stays closed and neither vendor
   loads.
3. Open **Privacy settings**. The rejection is still selected. Allow
   measurement only; PostHog loads and X Pixel stays blocked.
4. Block the backend's domain in DevTools and reload in a fresh session. No
   banner appears and no vendor loads. A hidden banner is not permission.
