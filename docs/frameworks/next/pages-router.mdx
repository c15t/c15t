## Choose how to manage consent

We recommend [Inth](/docs/guides/inth) for managed policy and consent records.
This guide uses cached manifests for request-time resolution and a Next.js
rewrite so browser consent requests stay on your origin.

| Mode | What you manage |
| --- | --- |
| Inth hosted | Configure policy and allowed app origins; Inth runs the backend and stores submissions. |
| [Self-hosted](/docs/self-host/quickstart) | Run the c15t backend and database. Use the same hosted transport and rewrite setup with your backend endpoint. |
| [Offline](/docs/frameworks/next/data-fetching#use-offline-mode-deliberately) | Bundle policy rules and keep choices in browser storage. No consent backend requests or backend records. |

This setup requires a Next.js server for the API routes and rewrite, including
when individual pages use static generation. For a deployment without that
server, use [static export](/docs/frameworks/next/static-export).

## Install c15t and configure your backend

[Create an Inth project](/docs/guides/inth), configure its policy rules and allow
your app's origin. Copy its backend endpoint for the upstream configuration.

If you chose self-hosting, complete the
[backend quickstart](/docs/self-host/quickstart) and use its public endpoint in
the steps below. Offline setups do not need an endpoint or rewrite; use the
[offline example](/docs/frameworks/next/data-fetching#use-offline-mode-deliberately).

## Keep browser requests on your origin

Set `C15T_BACKEND_URL` to the absolute endpoint supplied by Inth or your
self-hosted backend, including any path prefix. Add this fallback rewrite to your existing Next.js configuration:

```ts title="next.config.ts"
import type { NextConfig } from 'next';

const backendURL = process.env.C15T_BACKEND_URL;
if (!backendURL) throw new Error('Set C15T_BACKEND_URL');
const upstreamURL = backendURL.replace(/\/$/, '');

const config: NextConfig = {
  async rewrites() {
    return {
      fallback: [
        {
          source: '/api/c15t/:path*',
          destination: `${upstreamURL}/:path*`,
        },
      ],
    };
  },
};

export default config;
```

The local manifest and init routes below take precedence. Other requests,
including `POST /api/c15t/subjects`, pass through the rewrite to Inth. The browser
uses your site's origin for consent traffic. The backend URL is a public service
endpoint. This server environment variable configures the upstream destination;
the browser only needs the relative `/api/c15t` URLs.

Restart Next.js after changing the rewrite. Keep this catch-all in `fallback`,
not `beforeFiles`, so it cannot bypass the local route handlers.

## Share the consent URLs

Create this file at the project root. Server prefetch and the client boundary
share these first-party URLs:

```ts title="c15t.config.ts"
import { defineConsentConfig } from 'c15t/next';

export const consentConfig = defineConsentConfig({
  backendURL: '/api/c15t',
  manifestURL: '/api/c15t/manifest',
  initURL: '/api/c15t/init',
});
```

## Add the Pages API routes

Use the Pages Router adapter with the absolute upstream backend URL. Do not pass
the browser's `backendURL: '/api/c15t'` to these handlers: its derived manifest
URL would call the local manifest handler again.

```ts title="pages/api/c15t/manifest.ts"
import { createPagesApiHandlers } from 'c15t/next/pages';

const backendURL = process.env.C15T_BACKEND_URL;
if (!backendURL) throw new Error('Set C15T_BACKEND_URL');

export default createPagesApiHandlers({ backendURL }).manifest;
```

```ts title="pages/api/c15t/init.ts"
import { createPagesApiHandlers } from 'c15t/next/pages';

const backendURL = process.env.C15T_BACKEND_URL;
if (!backendURL) throw new Error('Set C15T_BACKEND_URL');

export default createPagesApiHandlers({ backendURL }).init;
```

The manifest route caches Inth policy data. The init route resolves that data
with the visitor's request inputs. The fallback rewrite handles the remaining
backend endpoints.

The following app and page imports assume `pages/` is at the project root.
Adjust them if you use `src/pages/`.

## Keep one boundary in the app

```tsx title="pages/_app.tsx"
import type { AppProps } from 'next/app';
import {
  ConsentBanner,
  ConsentBoundary,
  ConsentDialog,
  ConsentDialogLink,
} from 'c15t/next';
import type { ConsentBoundaryProps } from 'c15t/next';
import { consentConfig } from '../c15t.config';
import 'c15t/next/styles.css';

type ConsentPageProps = {
  consentConfig?: ConsentBoundaryProps['config'];
};

export default function App({ Component, pageProps }: AppProps<ConsentPageProps>) {
  return (
    <ConsentBoundary config={pageProps.consentConfig ?? {}} consent={consentConfig}>
      <Component {...pageProps} />
      <ConsentBanner />
      <ConsentDialog />
      <ConsentDialogLink>Privacy settings</ConsentDialogLink>
    </ConsentBoundary>
  );
}
```

Without page prefetch, the boundary initializes through `/api/c15t/init` in
the browser. That route resolves the cached manifest using the visitor request.
Consent submissions use `/api/c15t/subjects`, which the rewrite forwards to Inth.

## Prefetch for a server-rendered page

Use `c15t/next/pages` with the `req` from `getServerSideProps`. The App Router
helper reads a different request context and must not be used here.

```tsx title="pages/index.tsx"
import type { GetServerSideProps } from 'next';
import type { ConsentBoundaryProps } from 'c15t/next';
import { prefetchInitialConsent } from 'c15t/next/pages';
import { consentConfig } from '../c15t.config';

type PageProps = { consentConfig: ConsentBoundaryProps['config'] };

export const getServerSideProps: GetServerSideProps<PageProps> = async ({ req }) => {
  const prepared = await prefetchInitialConsent({ config: consentConfig, req });
  return { props: { consentConfig: prepared } };
};

export default function Home() {
  return <main>Your page</main>;
}
```

Repeat prefetch on pages that need request-specific initial HTML. Do not use
`getStaticProps` to resolve visitor cookies or geography: it runs without the
visitor's request. Keep the shared URL configuration consistent across pages.

## Verify entry and navigation

Load a server-rendered page directly, reject, and reload. Then navigate without
a full reload and reopen preferences. The mounted boundary should retain the
choice. Also test direct entry to a statically generated page; it uses browser
initialization through the local init route.

Confirm the server reads `/manifest` instead of the backend `/init` and choices
use `/api/c15t/subjects` and reach Inth through the rewrite. See
[data fetching](/docs/frameworks/next/data-fetching) for caching and transport
alternatives. For a deployment with no Next.js server, use
[static export](/docs/frameworks/next/static-export) and remove local API routes.
