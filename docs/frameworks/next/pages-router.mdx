## Before you start

This guide uses [Inth](https://inth.com) for policies and consent records. Your
Next.js build bundles the project's public policy manifest. The server resolves consent
for each visitor in `getServerSideProps`. The browser sends consent choices to
Inth.

A [self-hosted backend](/docs/self-host/quickstart) uses the same files with
its own URL. [Offline mode](/docs/frameworks/next/data-fetching-reference#offline-configuration)
keeps policy in your code and choices in the browser, with no consent records.
Not recommended for production environments.

This setup needs a Next.js server. For `output: 'export'`, follow
[static export](/docs/frameworks/next/static-export).
[Rendering and deployment](/docs/frameworks/next/rendering) compares every
path.

Location-based policies need trusted location headers from your host. Without
them, c15t applies your unknown-location rule. See
[Forward geography headers](/docs/frameworks/next/geography-headers) before
you deploy.

## Install c15t and configure your backend

[Create an Inth project](https://inth.com), set its policy rules and add your
site's origin to its trusted origins. Copy the project's backend URL.

## Share the consent URLs

Create `c15t.config.ts` at the project root, or in `src/` if your app uses a
`src` directory. `manifestURL` selects manifest
resolution; a backend URL alone uses backend `/init`.

<include src="../../shared/examples/nextjs/config.mdx" />

`https://example-inth.inth.app` is a demo project, so the snippets run as
they are. Set `NEXT_PUBLIC_C15T_BACKEND_URL` to your project's backend URL,
including any path prefix, in `.env.local` and in your host's build settings,
or replace the fallback with the URL. Next.js inlines `NEXT_PUBLIC_` variables
at build time, so the server and the browser use the same URL, and changing
the variable on a built app has no effect until you rebuild.

## Mount one root for every page

There is no c15t stylesheet to import. The components render their own rules
as `<style>` elements, so no stylesheet request holds back the first paint.
With Tailwind CSS 3, import `c15t/next/styles.css` yourself and set
`styles: false` in `ConsentRoot`'s `options`, as
[Customize](/docs/frameworks/next/customize#load-the-stylesheet-yourself)
shows.

Mount the wrapper in `_app.tsx`. It reads the state a page resolved on the
server from `pageProps.initialConsent`:

<include src="../../shared/examples/nextjs-pages-router/pages-app.mdx" />

A page with `getServerSideProps` supplies `initialConsent`. Any other page,
including static and `getStaticProps` pages, passes `{}`, and the browser
loads the manifest and resolves consent after hydration. Browser resolution
has no location input, so those pages follow your unknown-location rule unless
you add the
[optional local init route](/docs/frameworks/next/data-fetching-reference#do-i-need-the-local-init-route).

## Resolve consent in getServerSideProps

Import `resolveConsent` from `c15t/next/pages` and pass it `consentOptions`
with the `req` from `getServerSideProps`. The App Router helper in `c15t/next/server` reads
`next/headers`, which the Pages Router does not have.

<include src="../../shared/examples/nextjs-pages-router/pages-ssr.mdx" />

The JSON round trip removes `undefined` fields, such as an absent GPC signal,
because `next dev` rejects `undefined` in `getServerSideProps` props. The page renders the banner in the
server HTML, and the browser applies the same state without an `/init`
request.

Add this `getServerSideProps` to every page that should render consent on the
server, and return `initialConsent` from each. Do not resolve consent in
`getStaticProps`. It runs without the visitor's request, so it cannot read
their cookies or location. With runtime fetching, if the manifest request fails or takes longer than
`timeoutMs`, 500 ms by default, the page renders without a policy and the
browser retries after hydration.

## Use backend init instead of the manifest

Remove `withConsentManifest` from `next.config.ts`, and the `c15t/generated`
import and `manifest` line from `c15t.server.ts`. Delete the `manifestURL` line from
`c15t.config.ts` and delete `pages/api/c15t/manifest.ts`. `_app.tsx` and the pages stay the same.
`resolveConsent` and the browser now call `${backendURL}/init`, and consent
choices still go to `${backendURL}/subjects`. For a browser-only setup with no
server work, follow [client-side initialization](/docs/frameworks/next/client-side).

A same-origin [rewrite](/docs/frameworks/next/optimization) is optional with
either source.

## Verify the setup

Start the production build with `next build` and `next start`, then open a
page that has `getServerSideProps` in a fresh browser session with DevTools
open.

1. View the page source. It contains `data-testid="consent-banner-root"`.
2. Under an opt-in policy, the Network panel shows no PostHog request. Click
   **Reject All** and reload. The banner stays closed and PostHog does not
   load.
3. Open **Privacy settings** and turn on **Analytics** (the `measurement`
   category). PostHog loads.
4. Navigate to another page with a Next.js `Link` and reopen
   **Privacy settings**. The choice is still selected.
5. Open a static page directly. It shows the same choice, resolved in the
   browser.

The browser makes no `/init` request, and choices post to
`${backendURL}/subjects`. [Script loading](/docs/frameworks/next/scripts)
explains each vendor's loading and revocation behavior, and
[the consent checks](/docs/guides/verify-consent) cover the release checklist.
