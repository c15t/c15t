## Import server helpers only in server files

`@c15t/svelte/kit` holds the SvelteKit helpers and `@c15t/svelte/server` the
framework-free `resolveConsent`. Import them from `hooks.server.ts`,
`+layout.server.ts`, `+page.server.ts` and `+server.ts` only. Imported into a
component, they add the manifest resolver and every bundled translation to
the browser bundle.

| Export | From | Use it in | Page |
| --- | --- | --- | --- |
| `loadConsent(event, options)` | `@c15t/svelte/kit` | A server `load` | [Quickstart](./quickstart#resolve-consent-in-the-root-layout-load) |
| `c15tHandle(options)` | `@c15t/svelte/kit` | `hooks.server.ts` | [Rendering](./rendering#resolve-request-context-once-with-c15thandle) |
| `createSvelteKitConsentRouteHandlers(options)` | `@c15t/svelte/kit` | `+server.ts` | [Rendering](./rendering#serve-the-manifest-route) |
| `resolveConsent(options)` | `@c15t/svelte/server` | Any server code | [Rendering](./rendering#resolve-consent-in-other-server-code) |
| `c15tPreload()` | `@c15t/svelte/vite` | `vite.config.ts` | [Scripts](./scripts#preload-the-script-loader) |

Both entry points also re-export `hosted`, `offline` and `custom`, and the
`ConsentState` type.

## loadConsent

`loadConsent(event, options?)` returns a `Promise<ConsentState>` for the
provider's `prefetch` prop. It reads the consent cookie, the location and
language headers and Global Privacy Control, then resolves the policy from
one source:

1. With `initRoute`, it calls your own manifest route through `event.fetch`,
   inside the same process.
2. Otherwise, with `backendURL`, it calls the backend's `/init`.
3. With neither, it returns only what the request carries. The browser
   resolves the policy after hydration.

| Option | Type | Default | Behavior |
| --- | --- | --- | --- |
| `backendURL` | `string` | none | The backend's base URL, absolute or `/`-relative. See the note on relative URLs below. |
| `initRoute` | `string` | none | Your manifest route, such as `/api/c15t`. Wins over `backendURL`. |
| `timeoutMs` | `number` or `false` | `500` | Longest wait for the backend or route, in milliseconds. `false` or `Infinity` waits as long as it takes; any other value that is not a finite, non-negative number uses the default. |
| `shared` | `boolean` | the handle's `shared` | The page is served to every visitor, as a prerendered page is. Pass SvelteKit's `building` flag. See [prerendered pages](#prerendered-pages). |
| `cookieName` | `string` | `c15t`, or the handle's | The consent cookie. Match the provider's `storageConfig.storageKey`. |
| `country`, `region`, `language` | `string` | from headers | Forces one input for this call. |
| `forwardHeaders` | `string[]` | none | Extra request headers to send to the backend's `/init`, only over `https`, to a loopback host, or in-process. `cookie`, `forwarded` and `x-forwarded-*` cannot be named. |
| `trustForwardedHeaders` | `boolean` | `false` | Resolves a relative `backendURL` against the request's forwarding headers instead of `event.url`, and sends the visitor IP to the backend as `x-forwarded-for`. |
| `fetch` | `typeof fetch` | global `fetch` | The fetch for a backend on another origin. A URL on the request's own origin always goes through `event.fetch`. A custom fetch keeps the vendor list inline. |

`loadConsent` resolves a relative `backendURL` against `event.url`. Any URL
on the request's own origin, relative or absolute, is called with
`event.fetch`, so SvelteKit answers it in-process and the request never
leaves the server. A client's `x-forwarded-host` does not change it.
`adapter-node` builds that origin from `paths.origin` in SvelteKit 3 (the
`ORIGIN` variable in SvelteKit 2), or from its `PROTOCOL_HEADER` and
`HOST_HEADER` settings. SvelteKit 3's `adapter-node` ignores `ORIGIN` without
a warning; move it to `paths.origin` when you upgrade.
`trustForwardedHeaders: true` resolves against the forwarding headers
instead. Set it only when your proxy overwrites those headers.

The backend's `/init` gets the resolved location, language and GPC, the
`user-agent` and, while the visitor has no stored choice, the experiment arm.
A backend on another origin, over `https` or a loopback host, also gets the
consent cookie (`cookieName`, never the rest of the cookie jar) and any
`forwardHeaders`. Nothing identifying crosses plain HTTP to a remote host.
Your own init route reads no cookie, so none is sent to it.

For the manifest route, use `initRoute` instead of `backendURL`.

`loadConsent` never throws. When the backend fails, answers with an error or
takes longer than `timeoutMs`, it returns the stored choice without a policy.
The page then renders without a banner in the HTML, optional categories stay
denied, and the browser resolves the policy after hydration. A route request
that runs out of time keeps running in the background and fills the manifest
cache for the next request.

When `c15tHandle` ran for the request, `loadConsent` reuses the inputs it
normalized. Passing `country`, `region` or `language` makes it read the
headers again for that call.

### Prerendered pages

A prerendered page is one HTML file for every visitor. Pass SvelteKit's
`building` flag as `shared`, from `$app/environment` in SvelteKit 2 or
`$app/env` in SvelteKit 3. The prerender then carries no stored consent,
clock or GPC signal, and makes no backend request. Any stored records in the
page would stop the browser reading the visitor's own cookie, and a
build-time clock would age every record against it. The browser resolves the
visitor after hydration.

{/* example: fragment */}

```ts title="src/hooks.server.ts"
import { building } from '$app/environment';
import { c15tHandle } from '@c15t/svelte/kit';

export const handle = c15tHandle({ shared: building });
```

`loadConsent` reads the flag from the handle; pass `shared` to it directly
when you do not install the handle.

## c15tHandle

`c15tHandle(options?)` returns a SvelteKit `Handle`. For every request it:

1. reads the location, language and GPC inputs from the headers,
2. writes them back as `x-c15t-country`, `x-c15t-region`, `accept-language`
   and `sec-gpc`, so later code sees one normalized form,
3. reads the consent cookie,
4. stores the result on `event.locals.c15t`, and
5. on pages whose provider has `scripts` or network blocker rules, links
   the chunk that holds both with `<link rel="modulepreload">` once the
   [`c15tPreload()` Vite plugin](./scripts#preload-the-script-loader) has
   written its URL into the build.

| Option | Type | Default | Behavior |
| --- | --- | --- | --- |
| `cookieName` | `string` | `c15t` | The consent cookie. Match the provider's `storageConfig.storageKey`. |
| `country`, `region`, `language` | `string` | from headers | Forces the input for every request. |
| `shared` | `boolean` | `false` | Every render is shared between visitors, as during a prerender. Pass `building`. The handle then reads no cookie or headers. |

`event.locals.c15t` has this shape, exported as `C15tLocals`:

| Field | Value |
| --- | --- |
| `config` | The `ConsentState` from the cookie and request inputs, without a resolved policy. |
| `inputs` | `{ country?, region?, language?, gpc? }` for this request. |
| `cookieName` | The cookie name, when you passed one. |

Some runtimes refuse to change request headers. The handle then skips step
2, and `event.locals.c15t.inputs` still carries the values. Compose it with
your own handles through `sequence()` from `@sveltejs/kit/hooks`. Type
`event.locals.c15t` as shown in [rendering](./rendering#resolve-request-context-once-with-c15thandle),
or add `/// <reference types="@c15t/svelte/kit/locals" />` to `src/app.d.ts`.

## createSvelteKitConsentRouteHandlers

`createSvelteKitConsentRouteHandlers(options)` returns request handlers for
manifest mode. The options argument is required. Export them from a catch-all route such as
`src/routes/api/c15t/[...path]/+server.ts`.

| Returned | Serves |
| --- | --- |
| `GET` | `manifest` below the rest parameter to `manifest`, `init` or the route root to `init`. Any other path is forwarded with `proxy` on and answers `404` without it. On a route without a rest parameter, a path ending in `/manifest` goes to `manifest` and anything else to `init`. |
| `init` | The visitor's resolved policy, like the backend's `/init`, with `Cache-Control: private, no-store`. Under an IAB policy it also serves the Global Vendor List. |
| `manifest` | The cached policy manifest, with the backend's `Cache-Control` and `ETag`. Answers `If-None-Match` with `304`. |

With `proxy` on, it also returns `POST`, `PATCH`, `PUT`, `DELETE` and
`OPTIONS`, which forward writes to the backend.

| Option | Type | Default | Behavior |
| --- | --- | --- | --- |
| `backendURL` | `string` | none | The backend's base URL, absolute or `/`-relative. The manifest is at `<backendURL>/manifest`. See the note on relative URLs below. |
| `manifestURL` | `string` | none | A manifest URL of its own, such as a CDN. Wins over `backendURL`. Absolute or `/`-relative. |
| `proxy` | `true` or `{ paths?, cookieNames? }` | off | Forwards consent writes to `backendURL`. See [save consent through your own origin](./rendering#save-consent-through-your-own-origin). |
| `reportSessions` | `boolean` | `true` | Reports each resolved visit to the backend's `/sessions`, so Inth counts visitors it never served `/init` to. |
| `onBackgroundRevalidate` | `(promise, event) => void` | `event.platform.context.waitUntil`, when the adapter provides it | Keeps background manifest refreshes and session reports alive on runtimes that stop work after the response. SvelteKit 3's Cloudflare and Vercel adapters provide none; see [keep background work alive](./rendering#keep-background-work-alive-after-the-response). |
| `fetchGvl` | `({ reference, language, fetch }) => Promise<GlobalVendorList \| null>` | the shared server cache, with a five-second deadline | Fetches the Global Vendor List under an IAB policy. A rejection fails the init request instead of answering `gvl: null`. |
| `fetch` | `typeof fetch` | global `fetch` | The fetch used for an absolute `backendURL` or `manifestURL`, and for the vendor list. |

With an options object that sets neither `backendURL` nor `manifestURL`, each
request throws
`@c15t/svelte/kit: pass backendURL or manifestURL.` The handlers read no
environment variables.

An absolute `backendURL` or `manifestURL` is fetched over the network with
`fetch`. A `/`-relative one, such as `/api/self-host` for a backend mounted in
your app, names a route in this app. The handlers request it through
`event.fetch`, which SvelteKit answers in-process, so it is never resolved
against `event.url` or the request's `Host` header. The proxy forwards to a
relative `backendURL` the same way. Do not point it at the route the handlers
serve, such as `/api/c15t`, or the route requests itself. A relative
`backendURL` also turns off session reports, which need an absolute backend.

The manifest is cached in memory per server process for as long as its
`s-maxage` allows, then served stale while it refreshes in the background.
The `manifest` handler passes upstream only a `language` query parameter that
looks like a language tag; the visitor's other parameters never reach the
backend. When the manifest cannot be read and `backendURL` is set, `init` asks
the backend's own `/init`, which covers backends without `/manifest`.

These handlers are built on the consent route handler in `@c15t/core/server`,
shared with the Next.js, TanStack Start, Astro and Nuxt adapters. `init`
answers with `x-c15t-policy-contract: 1`. A browser that declares another
policy contract gets a failed `unsupported-contract` resolution, and a
resolution that did not match carries no snapshot token, vendor list, CMP ID
or custom vendors.

## resolveConsent

`resolveConsent(options)` from `@c15t/svelte/server` does what `loadConsent`
does without a SvelteKit event.

| Option | Type | Default | Behavior |
| --- | --- | --- | --- |
| `headers` | `Headers` | required | The incoming request's headers. |
| `backendURL` | `string` | none | Calls `<backendURL>/init`. Without it, only the cookie and headers are read. A relative URL resolves against `requestURL`, or the `host` header when there is none. |
| `requestURL` | `string` or `URL` | none | The URL the framework resolved the request under, such as SvelteKit's `event.url`. `loadConsent` passes it for you. |
| `trustForwardedHeaders` | `boolean` | `false` | Resolves a relative `backendURL` against `forwarded`, `x-forwarded-host` and `x-forwarded-proto`, and sends the visitor IP to the backend as `x-forwarded-for`. |
| `cookieName` | `string` | `c15t` | The consent cookie. |
| `cookieHeader` | `string` or `null` | `headers.get('cookie')` | A cookie header to read instead. |
| `country`, `region`, `language` | `string` | from headers | Forces one input. |
| `forwardHeaders` | `string[]` | none | Extra headers to send to `/init`, under the same rule as `loadConsent`. |
| `fetch` | `typeof fetch` | global `fetch` | The fetch for `/init`. |
| `timeoutMs` | `number` or `false` | `500` | Longest wait for `/init`, in milliseconds, with the same rule as `loadConsent`. |
| `now` | `number` | the current time | The request time, shared with the browser. |

It never throws; a failed or slow call returns the stored choice without a
policy.

## ConsentState

`loadConsent`, `resolveConsent` and `event.locals.c15t.config` return a
`ConsentState`: plain, serializable data a load can return. It holds the
stored records, the request's location, language and GPC, the resolved policy
and translations when the backend answered, and the IAB state for an IAB
policy. It holds no computed permissions. Pass it to the provider unchanged;
do not build one yourself or edit its fields.
