## Declare the vendors

Declare the vendors in the root layout, using the `vendor` slug each script
already carries, and pass them to `ConsentManagerProvider`:

{/* example: fragment */}

```svelte title="src/routes/+layout.svelte (partial)"
<script lang="ts">
  import type { ConsentManagerOptions } from '@c15t/svelte';

  const vendors: NonNullable<ConsentManagerOptions['vendors']> = [
    {
      id: 'x-pixel',
      name: 'X Pixel',
      category: 'marketing',
      privacyPolicyUrl: 'https://x.com/privacy',
    },
  ];
</script>

<ConsentManagerProvider {mode} prefetch={data.prefetch} {scripts} {vendors}>
```

The provider reads `vendors` once, when it is created.

## What the preference dialog shows

`ConsentDialog` and `ConsentWidget` list each declared vendor under its
category, with its own switch.

## Build your own vendor switch

`getConsentManager()` stages vendor switches on the same draft as the category
switches. `selectedVendors` has one value per declared vendor,
`setSelectedVendor(id, granted)` changes one, and `saveConsents('custom')`
records the draft:

{/* example: fragment */}

```svelte title="src/lib/x-pixel-switch.svelte (partial)"
<script lang="ts">
  import { getConsentManager } from '@c15t/svelte';

  const consent = getConsentManager();
</script>

<input
  type="checkbox"
  checked={consent.selectedVendors['x-pixel'] ?? true}
  onchange={(event) =>
    consent.setSelectedVendor('x-pixel', event.currentTarget.checked)}
/>
<button type="button" onclick={() => consent.saveConsents('custom')}>Save</button>
```

`saveConsents('custom')` throws when the policy changed since the draft
started. `vendorChoice.denied` lists the vendors the visitor recorded as off,
and `getDisplayedVendors(category)` returns the vendors to list under one
category. [Context getters](/docs/frameworks/sveltekit/getters) covers the draft.
