## Mount the provider in the root layout

Resolve consent in the root layout's server load, then pass the result to the
provider as `prefetch` in the root layout:

<include src="../../../shared/examples/sveltekit/layout-server.mdx" />

<include src="../../../shared/examples/sveltekit/layout.mdx" />

Pass `data.prefetch` through unchanged. The provider starts from it on the
server and in the browser, so both render the same banner, and the browser
makes no second policy request. The [quickstart](../quickstart) explains
`loadConsent`, the bundled policy in `consentOptions`, the `/api/c15t` route
and `shared: building` for prerendered pages.

Keep the provider in the root `+layout.svelte`. A layout stays mounted across
client-side navigation, so the runtime, the loaded scripts and the dialog
survive page changes. A provider in a page component would start again on
every navigation.

Create `scripts` and `callbacks` in the layout component, not in
`+layout.server.ts`. They hold functions, which a server load cannot send to
the browser.
