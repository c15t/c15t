## Register scripts in the root layout

Pass the array from `src/lib/scripts.ts` to `ConsentRoot`
as the `scripts` prop in `src/routes/+layout.svelte`. The
[quickstart](/docs/frameworks/sveltekit/quickstart) sets up both files:

<include src="../../shared/examples/sveltekit/scripts.mdx" />

Create the scripts in the layout component, not in `+layout.server.ts`. Script
configurations hold functions, which a server load cannot send to the
browser. The script loader runs only in the browser, after hydration. A
returning visitor's allowed entries can start earlier, from the server HTML;
see
[Rendering](/docs/frameworks/sveltekit/rendering#resolve-request-context-once-with-c15thandle).

## Preload the script loader

The provider loads the script loader only on pages whose `scripts` array is
not empty or that have [network blocker](./network-blocker) rules. The loader
and the blocker share one separate chunk. Pages with neither never download
it. On a page with either, the browser would otherwise request the chunk after
the app's JavaScript has run, and a returning visitor's consented scripts and
held requests would wait for that extra request.

`consentManifest()` from `@c15t/svelte/vite`, already in `vite.config.ts`
from the quickstart, lets `c15tHandle` link the chunk from the page's
`<head>` with `<link rel="modulepreload">`. It does this whenever the
`sveltekit()` plugin is present; there is nothing else to add.

SvelteKit builds the server before the client, so the server cannot know the
chunk's file name. After the client build, `consentManifest()` writes the chunk URL
into the server output, before SvelteKit prerenders pages and before the
adapter copies the build. Then `c15tHandle` adds one link to every page whose
provider has scripts or blocker rules, prerendered pages included. The link
carries the provider's `nonce`, or else the nonce SvelteKit put on its own
scripts. It asks for low priority (`fetchpriority="low"`): the
runtime needs the chunk only after hydration, so the browser fetches your
app's own chunks first. It does nothing in `vite dev`.

Without the plugin, or without `c15tHandle` in `hooks.server.ts`, scripts
still load, one request later.

For a returning visitor whose stored consent already allows an entry, a page
rendered for that request starts the entry before hydration, and the loader
adopts its tag. See
[Rendering](/docs/frameworks/sveltekit/rendering#resolve-request-context-once-with-c15thandle).

## Send your own analytics events

`getEventDispatcher()` from `@c15t/svelte` returns the provider's event
dispatcher. It sends to the provider's `scripts` and checks consent when an
event goes out. Call it in a component rendered inside `ConsentProvider`, and
send a pageview when `page.url` changes:

<include src="../../shared/examples/sveltekit/pageviews.mdx" />

Call `events.track('sign_up', { method: 'email' })` from an event handler for
your own events. `track` sends to every registered script with an event API and drops the
event while measurement is denied. `pageview` sends only to the integrations
named in `pageviews`, and the first call records the path without sending.
Every dispatcher shares one pageview history for the provider's lifetime.
See [send events only to allowed integrations](/docs/integrations/overview#send-events-only-to-allowed-integrations)
for the supported vendors.
