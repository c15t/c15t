## Register scripts in the root layout

Pass the array from `src/lib/example-scripts.ts` to `ConsentManagerProvider`
as the `scripts` prop in `src/routes/+layout.svelte`. The
[quickstart](/docs/frameworks/sveltekit/quickstart) sets up both files:

<include src="../../shared/examples/sveltekit-demo/scripts.mdx" />

Create the scripts in the layout component, not in `+layout.server.ts`. Script
configurations hold functions, which a server load cannot send to the
browser. Scripts load only in the browser, after hydration, so they never
appear in server HTML.

## Preload the script loader

The provider loads the script loader only on pages whose `scripts` array is
not empty, as a separate chunk. Pages without scripts never download it. On a
page with scripts, the browser would otherwise request the chunk after the
app's JavaScript has run, and a returning visitor's consented scripts would
wait for that extra request.

Add the `c15tPreload()` Vite plugin so `c15tHandle` can link the chunk from
the page's `<head>` with `<link rel="modulepreload">`:

{/* example: fragment */}

```ts title="vite.config.ts (partial)"
import { c15tPreload } from '@c15t/svelte/vite';

export default defineConfig({ plugins: [sveltekit(), c15tPreload()] });
```

SvelteKit builds the server before the client, so the server cannot know the
chunk's file name. After the client build, the plugin writes the chunk URLs
into the server output, before SvelteKit prerenders pages and before the
adapter copies the build. Then `c15tHandle` adds the link to every page whose
provider has scripts, prerendered pages included, and to every page with
[network blocker](./network-blocker) rules, whose chunk loads the same way.
The link carries the provider's `nonce`, or else the nonce SvelteKit put on
its own scripts. It does nothing in `vite dev`.

Without the plugin, or without `c15tHandle` in `hooks.server.ts`, scripts
still load, one request later.
