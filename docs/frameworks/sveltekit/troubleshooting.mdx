## Why is the banner missing from the server HTML?

View the page source and search for `consent-banner-root`. If the banner only
appears after hydration:

1. **The provider has no `prefetch`.** Check that the root
   `+layout.server.ts` returns `prefetch` and that `+layout.svelte` passes
   `prefetch={data.prefetch}`.
2. **`loadConsent` fell back.** It returns the stored choice without a policy
   when the backend fails or takes longer than `timeoutMs`, 500 ms by default.
   Check the server logs and the backend's response time, and raise
   `timeoutMs` if it is slow.
3. **The page is prerendered.** Prerendered pages never carry a visitor's
   consent. See
   [prerender some pages](/docs/frameworks/sveltekit/rendering#prerender-some-pages).
4. **No banner is due.** The policy for the visitor's location may ask for no
   prompt, or the visitor already chose. Clear site data and check the policy.

## The banner flashes, or the stored choice is ignored on the server

The server reads the choice from the `c15t` cookie. If you changed
`storageConfig.storageKey` on the provider, pass the same name as
`cookieName` to `loadConsent` or `c15tHandle`, or the server reads nothing and
renders the banner for every visitor. Pass `data.prefetch` to the provider
unchanged; rebuilding it from booleans loses the policy and the stored record.

## Saving fails with 405 from /api/c15t

The manifest route handlers answer `GET` only. If the provider's `hosted()`
mode points at `/api/c15t`, saving a choice sends a `POST` there and fails.
Point `hosted({ url })` at the backend URL, as the quickstart layout does.
See [serve the manifest route](/docs/frameworks/sveltekit/rendering#serve-the-manifest-route).

## The manifest route times out or calls itself

`createSvelteKitConsentRouteHandlers` needs the absolute backend URL. A
relative `backendURL` resolves against your own origin; if it points at
`/api/c15t`, the route requests itself. Pass the Inth URL, or set
`C15T_BACKEND_URL` in the server environment.

## The build fails while prerendering a page

The root layout reads `PUBLIC_C15T_BACKEND_URL` while SvelteKit prerenders,
and throws when it is empty. Set the variable in the build environment, not
only where the server runs.

## Your own `:root` token rules are ignored

A theme from `generateThemeCSS()` uses `:root:root`, which outranks a plain
`:root` rule wherever each one sits in the page. If you also set `--c15t-*`
variables on `:root` in a stylesheet, the generated theme wins for every token
both set. Move those values into the theme, or write the rule on `:root:root`.
See [customize](/docs/frameworks/sveltekit/customize).

## Server code in the browser bundle

`@c15t/svelte/kit` and `@c15t/svelte/server` are for server files:
`hooks.server.ts`, `+layout.server.ts`, `+page.server.ts` and `+server.ts`.
Imported from a component, they pull the manifest resolver and every bundled
translation into the browser bundle. Import `hosted` and the components from
`@c15t/svelte` in components.
