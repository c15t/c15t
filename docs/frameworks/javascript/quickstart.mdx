## Installation

<PackageCommandTabs mode="install" command="c15t" />

The root `c15t` entry point is the headless engine; the same package also provides `c15t/react` and `c15t/next`. Only need the engine? See [Granular Installs](/docs/granular-installs) for installing the scoped `@c15t/core` package alone.

## Create the Kernel

`createConsentKernel()` creates an isolated consent state container. Add the
persistence module in browser code, then initialize the selected transport.

```ts
import { createConsentKernel, createHostedTransport } from 'c15t';
import { createPersistence } from 'c15t/modules/persistence';

const kernel = createConsentKernel({
  transport: createHostedTransport({
    backendURL: 'https://your-instance.c15t.dev',
  }),
});

const persistence = createPersistence({ kernel });
await kernel.commands.init();
```

<Callout type="info">
  Hosted mode is the recommended production setup because the backend resolves jurisdiction and translations, stores consent decisions outside the current browser, and replays failed consent saves after temporary outages.
</Callout>

<Callout type="warn">
  You can switch to `createOfflineTransport()` for local-only storage, demos, or static previews, but that removes backend audit history, automatic jurisdiction detection, and server-side consent awareness. Review [Client Modes](/docs/frameworks/javascript/concepts/client-modes) before using offline mode in production.
</Callout>

## Subscribe to State Changes

Use `subscribe()` for state updates and `getSnapshot()` to read the current
immutable snapshot:

```ts
// React to every state change
const unsubscribe = kernel.subscribe((snapshot) => {
  console.log('Consent state:', snapshot.consents);
  console.log('Show banner?', snapshot.activeUI === 'banner');
});

// Read current state at any time
const snapshot = kernel.getSnapshot();
console.log('Measurement consent:', snapshot.consents.measurement);

// Stop listening during teardown
unsubscribe();
persistence.dispose();
```

## Check and Set Consent

```ts
import { has } from 'c15t';

const snapshot = kernel.getSnapshot();

// Check if a category has consent
if (has('measurement', snapshot.consents)) {
  // Safe to load analytics
}

// Accept all categories
await kernel.commands.save('all');

// Accept only necessary categories
await kernel.commands.save('none');

// Set a specific category
kernel.set.consent({ marketing: true });
```

## Minimal Consent Prompt

Here's a bare-bones example using the kernel to drive a consent prompt — no framework required:

```ts
import { createConsentKernel, createHostedTransport } from 'c15t';

const kernel = createConsentKernel({
  transport: createHostedTransport({
    backendURL: 'https://your-instance.c15t.dev',
  }),
});

// Subscribe to show/hide the banner
kernel.subscribe((snapshot) => {
  const banner = document.getElementById('consent-banner');
  if (banner) {
    banner.style.display = snapshot.activeUI === 'banner' ? 'block' : 'none';
  }
});

// Wire up buttons
document.getElementById('accept-all')?.addEventListener('click', () => {
  void kernel.commands.save('all');
});

document.getElementById('reject')?.addEventListener('click', () => {
  void kernel.commands.save('none');
});

await kernel.commands.init();
```

## Verify It Works

Open the browser console and inspect the kernel snapshot:

```ts
const snapshot = kernel.getSnapshot();
console.log('Consents:', snapshot.consents);
console.log('Has consented:', snapshot.hasConsented);
console.log('Location:', snapshot.location);
```

<Callout type="info">
  **No UI included** — the `c15t` core package is fully headless. See [Building UI](/docs/frameworks/javascript/building-ui) for creating your own components, or use [`c15t/react`](/docs/frameworks/react/quickstart) / [`c15t/next`](/docs/frameworks/next/quickstart) for pre-built UI.
</Callout>
