## Headless by Design

The `c15t` core package provides no pre-built UI components. It gives you a
framework-neutral kernel with immutable snapshots, subscriptions, setters, and
async commands. You bring the rendering layer.

## Vanilla DOM Example

Here's a complete consent banner built with plain JavaScript and DOM APIs:

```ts
import { createConsentKernel, createHostedTransport } from 'c15t';

const kernel = createConsentKernel({
  transport: createHostedTransport({
    backendURL: 'https://your-instance.c15t.dev',
  }),
});

await kernel.commands.init();

// Create banner element
function createBanner() {
  const banner = document.createElement('div');
  banner.id = 'consent-banner';
  banner.setAttribute('role', 'dialog');
  banner.setAttribute('aria-label', 'Cookie consent');
  banner.innerHTML = `
    <p>We use cookies to improve your experience.</p>
    <div>
      <button id="consent-accept">Accept All</button>
      <button id="consent-reject">Reject</button>
      <button id="consent-customize">Customize</button>
    </div>
  `;
  document.body.appendChild(banner);

  banner.querySelector('#consent-accept')?.addEventListener('click', () => {
    void kernel.commands.save('all');
  });

  banner.querySelector('#consent-reject')?.addEventListener('click', () => {
    void kernel.commands.save('none');
  });

  banner.querySelector('#consent-customize')?.addEventListener('click', () => {
    kernel.set.activeUI('dialog');
  });

  return banner;
}

// Mount and subscribe
const banner = createBanner();

kernel.subscribe((snapshot) => {
  banner.style.display = snapshot.activeUI === 'banner' ? 'block' : 'none';
});
```

## Reactive State Subscriptions

The kernel publishes every snapshot change. Keep the previous value when a
binding only needs one field:

```ts
let previous = kernel.getSnapshot();

kernel.subscribe((snapshot) => {
  // React to activeUI changes (banner / dialog / none)
  if (snapshot.activeUI !== previous.activeUI) {
    document.getElementById('consent-banner')!.style.display =
      snapshot.activeUI === 'banner' ? 'block' : 'none';
    document.getElementById('consent-dialog')!.style.display =
      snapshot.activeUI === 'dialog' ? 'block' : 'none';
  }

  previous = snapshot;
});
```

Analytics SDKs can compare the consent record by reference:

```ts
let previousConsents = kernel.getSnapshot().consents;

kernel.subscribe((snapshot) => {
  if (snapshot.consents !== previousConsents) {
    analytics.syncConsent(snapshot.consents);
    previousConsents = snapshot.consents;
  }
});
```

## Building Policy-Aware UI

If you use policy packs, your custom UI should render from the resolved runtime policy instead of hard-coding a fixed banner shape.

That matters when different visitors may resolve to different experiences, for example:

- a banner in one region and no banner in another
- different action sets such as accept/customize without reject
- different category scopes depending on the active policy

You can preview that locally with `createOfflineTransport()`:

```ts
import { createConsentKernel, createOfflineTransport, policyPackPresets } from 'c15t';

const kernel = createConsentKernel({
  initialOverrides: {
    country: 'US',
    region: 'CA',
  },
  transport: createOfflineTransport({
    policyPacks: [
      policyPackPresets.californiaOptOut(),
      policyPackPresets.europeOptIn(),
      policyPackPresets.worldNoBanner(),
    ],
  }),
});

await kernel.commands.init();
const state = kernel.getSnapshot();
console.log(state.policy?.id, state.policyDecision?.matchedBy);
```

When building custom UI, prefer these runtime values:

- `activeUI` to decide whether to show banner, dialog, or nothing
- `policy` to inspect the resolved mode and UI hints
- `policyDecision` to debug why a policy was selected
- `policyCategories` to decide which categories should render

<Callout type="info">
  See [Policy Packs](/docs/frameworks/javascript/policy-packs) for offline preview setup and [Policy Packs Concept](/docs/frameworks/javascript/concepts/policy-packs) for matcher precedence and fallback behavior.
</Callout>

## Key Snapshot Properties for UI

| Property | Type | Use |
|----------|------|-----|
| `activeUI` | `'none' \| 'banner' \| 'dialog'` | Which consent UI is currently visible |
| `consents` | `Record<string, boolean>` | Current consent state per category |
| `model` | `string \| null` | Current consent model (opt-in, opt-out, iab) |
| `location` | `LocationResponse \| null` | Detected location (country, region) |
| `policyCategories` | `string[]` | Categories allowed by the resolved policy |

## Key Kernel Actions for UI

| Action | Signature | Use |
|--------|-----------|-----|
| `commands.save` | `(input?: Partial<ConsentState> \| 'all' \| 'none') => Promise<SaveResult>` | Update and persist consent choices |
| `set.consent` | `(input: Partial<ConsentState>) => void` | Update consent synchronously without saving |
| `set.activeUI` | `(ui: 'none' \| 'banner' \| 'dialog' \| null) => void` | Show or hide consent UI |
| `subscribe` | `(listener) => unsubscribe` | Bridge snapshots into framework state |

## Using `@c15t/ui` for Theming

The `@c15t/ui` package provides a framework-agnostic theme and style system. It defines design tokens, slot-based styling, and CSS primitives that you can use in any rendering layer.

<PackageCommandTabs mode="install" command="@c15t/ui" />

### Theme Tokens

Use the token types to build a consistent theme system:

```ts
import type {
  ColorTokens,
  TypographyTokens,
  SpacingTokens,
  BorderTokens,
  ShadowTokens,
} from '@c15t/ui/theme';

// Define a theme matching the token structure
const theme = {
  colors: {
    primary: '#2563eb',
    background: '#ffffff',
    text: '#1a1a1a',
    border: '#e5e7eb',
  } satisfies Partial<ColorTokens>,
  typography: {
    fontFamily: 'Inter, system-ui, sans-serif',
    fontSize: '14px',
  } satisfies Partial<TypographyTokens>,
};
```

### Style Utilities

`@c15t/ui` exports DOM utilities for working with class names and styles:

```ts
import { cn, resolveStyles, sanitizeDOMStyleProps } from '@c15t/ui/utils';

// Merge class names conditionally
const className = cn(
  'consent-banner',
  isVisible && 'consent-banner--visible',
  isDark && 'consent-banner--dark'
);

// Strip internal style metadata before binding to DOM
const domProps = sanitizeDOMStyleProps(resolveStyles('consentBannerCard', theme));
```

When building framework adapters, treat `noStyle` as internal control flow only. Always sanitize resolved slot styles before binding them to DOM elements, and prefer subtree-inherited CSS variables over hard-coded `:root` assumptions for token-driven primitives like switches.

### CSS Primitives

Import style primitives for consent UI elements:

```ts
import { buttonVariants, switchVariants, accordionVariants } from '@c15t/ui/styles/primitives';

// Generate class names for styled buttons
const btn = buttonVariants({ variant: 'primary', mode: 'filled', size: 'medium' });
document.getElementById('accept-btn')!.className = btn.root();

// Generate class names for styled switches
const sw = switchVariants({ size: 'medium' });
toggleEl.className = sw.root();
```

These functions return CSS module class name generators. To apply the associated styles, import the stylesheet from your app-level CSS entrypoint:

```css title="src/index.css"
@import "@c15t/ui/styles.css";
```

## Building a Framework Library

<Callout type="info">
  **Building a Vue, Svelte, or other framework library?** Use `c15t` for the consent logic and `@c15t/ui` for the theme/style system. Library authors can depend on the scoped `@c15t/core` package directly instead of the `c15t` umbrella — see [Granular Installs](/docs/granular-installs) for the trade-offs. See the [`@c15t/react` source code](https://github.com/c15t/c15t/tree/main/packages/react) for a reference implementation of how to wrap the core kernel in a framework-specific API.
</Callout>

The pattern for building a framework wrapper:

1. **Create a provider** — Create one kernel and expose it through your framework's context system (Vue `provide`/`inject`, Svelte context, etc.)
2. **Build reactive bindings** — Subscribe to kernel snapshots and bridge them to your framework's reactivity system
3. **Wrap UI components** — Use `@c15t/ui` tokens and slots for consistent theming, render with your framework's component model
4. **Export hooks/composables** — Expose kernel actions through framework-idiomatic APIs (Vue composables, Svelte stores, etc.)

```ts
// Pseudocode for a framework wrapper
import { createConsentKernel, has } from 'c15t';
import type { KernelConfig } from 'c15t';

export function createConsentPlugin(options: KernelConfig) {
  const kernel = createConsentKernel(options);

  return {
    kernel,
    has: (condition) => has(condition, kernel.getSnapshot().consents),
    saveConsents: (input) => kernel.commands.save(input),
    subscribe: kernel.subscribe,
  };
}
```
