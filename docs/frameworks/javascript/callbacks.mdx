## Subscribe to events

```ts
const stopChoices = kernel.events.on(
  'choice:recorded',
  ({ confirmed, actionAt, snapshot }) => {
    console.log(confirmed, actionAt, snapshot.explicitChoice);
  }
);
const stopPermissions = kernel.events.on(
  'permissions:changed',
  ({ snapshot }) => {
    console.log(snapshot.effectivePermissions);
  }
);
```

Register these on a kernel created as shown in the [quickstart](/docs/frameworks/javascript/quickstart).
Call the returned cleanup functions when the integration stops.

Explicit accept, reject and nonempty save actions emit `choice:recorded`.
Reconfirmation emits once even when values stay unchanged. Hydration, initialization,
expiry, GPC and retry replay never create a choice. Permission events fire when
effective values change. Notice dismissals emit `notice:dismissed`; detected
standing privacy directives emit `privacy:opt-out`. Late registration does not
replay a choice event.

React, Next.js, Vue and Svelte expose `onChoiceRecorded` and
`onPermissionsChanged` provider callbacks with the corresponding event payload
minus `type`.

A successful save may replace a provisional subject ID with the server's canonical
ID. That identity change emits `subject:resolved` with the current snapshot.
Persistence updates the stored choice envelope without renewing receipt timestamps
or emitting another choice event. Failed or stale acknowledgements do neither.
