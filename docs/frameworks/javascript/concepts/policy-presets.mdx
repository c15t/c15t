## Inspect the active policy

Call this helper with the kernel from your existing
[JavaScript setup](/docs/frameworks/javascript/quickstart). It logs the current
state and later changes without recording a choice.

```ts title="src/observe-consent-policy.ts"
import type { ConsentKernel } from 'c15t';

export function observeConsentPolicy(kernel: ConsentKernel) {
  const report = () => {
    const snapshot = kernel.getSnapshot();
    const resolution = snapshot.resolution;

    console.log({
      status: resolution.status,
      policy: resolution.status === 'matched' ? resolution.policy.id : null,
      prompt: snapshot.promptRequirement,
      permissions: snapshot.effectivePermissions,
      location: snapshot.location,
      privacySignals: snapshot.privacySignals,
    });
  };

  report();
  return kernel.subscribe(report);
}
```

The helper returns an unsubscribe function. Call it when you remove the
diagnostic or dispose the app. Production gates should read
`kernel.getSnapshot().effectivePermissions` at the point where an optional
feature would run.

## Build UI from the resolved policy

The JavaScript kernel does not render consent controls. Follow
[building UI](/docs/frameworks/javascript/building-ui) to render the required
prompt and expose persistent preferences. Keep notice dismissal separate from
accepting categories. Resolve policy before displaying controls so a failed
initialization does not look like a visitor's consent decision.

## Verify policy behavior

Use a fresh browser profile to check the intended location, then repeat with a
saved rejection and GPC enabled. Confirm that the expected prompt and
preferences controls appear, and that denied scripts and embeds make no
requests. Test missing location inputs too. Follow
[verify consent](/docs/guides/verify-consent) for the full flow.
