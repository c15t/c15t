## Run an example from the c15t repository

The examples live in the [`examples` directory](https://github.com/c15t/c15t/tree/v3/examples)
of the c15t repository. They build against the packages in the repository, not
against npm, so you clone the repository and build the packages first:

```sh
git clone --branch v3 https://github.com/c15t/c15t.git
cd c15t
bun install
bun run build:libs
```

You need [Bun](https://bun.sh). Each example has a README with its environment
variables. To add c15t to your own app, follow your
[framework quickstart](/docs/frameworks) instead; its setup code comes from
these examples.

## Framework examples

Each of these registers PostHog on measurement and X Pixel on marketing, gates a
YouTube video on measurement, and keeps a privacy settings link after the banner
closes. A Branded design switch shows the same consent flow with different
styling. Set the backend URL variable from `.env.example` to the URL from your
Inth project, and add the example's origin to the project's trusted origins.
PostHog and X Pixel stay unregistered until you set their IDs.

| Framework | Directory | Run | Open |
| --- | --- | --- | --- |
| Next.js, App Router and Pages Router | `examples/nextjs` | `bun run --cwd examples/nextjs dev` | `http://localhost:3011/app-router` and `/pages-router` |
| TanStack Start | `examples/tanstack-start` | `bun run --cwd examples/tanstack-start dev` | `http://localhost:3010/consent-example` |
| React with Vite | `examples/react` | `bun run --cwd examples/react dev` | The URL Vite prints |
| Nuxt | `examples/nuxt` | `bun run --cwd examples/nuxt dev` | `/consent-example` on the URL Nuxt prints |
| Vue with Vite | `examples/vue` | `bun run --cwd examples/vue dev` | The URL Vite prints |
| Astro | `examples/astro-demo` | `bun run --cwd examples/astro-demo dev` | `http://localhost:4321/consent-example` |
| Svelte with Vite | `examples/svelte` | `bun run --cwd examples/svelte dev` | The URL Vite prints |
| SvelteKit | `examples/sveltekit-demo` | `bun run --cwd examples/sveltekit-demo dev` | `/consent-example` on the URL Vite prints |
| HTML, script tag | `examples/script-tag` | `bun run --cwd examples/script-tag dev` | `http://localhost:4173/consent-example` |
| JavaScript with a bundler | `examples/javascript` | `bun run --cwd examples/javascript dev` | The URL Vite prints for the stock UI, and `/headless/` for custom markup |

The TanStack Start, Nuxt and SvelteKit examples also mount a
self-hosted backend at `/api/self-host`; the
[backend quickstart](/docs/self-host/quickstart#mount-the-request-handler)
publishes those routes.

## Other examples

| Example | Directory | What it shows | Run |
| --- | --- | --- | --- |
| Script tag showcase | `examples/script-tag` | Offline pages for the headless build with custom markup, theming inside a shadow root, and the IAB entry. | `bun run --cwd examples/script-tag dev`, then open `http://localhost:4173` |
| Next.js showcase | `examples/demo` | Policy scenarios, a self-hosted backend, IAB and development playgrounds. It needs a PostgreSQL `DATABASE_URL` for the backend. | `bun run dev` from the repository root |

The script-tag showcase pages run offline, so they need no backend. Offline mode keeps
choices in the browser and records nothing on a server. Not recommended for
production environments.

## What to try

In any framework example, open a private window with DevTools Network open:

1. Before you choose, no PostHog, X Pixel or YouTube requests appear.
2. Reject optional categories and reload. The banner stays closed and those
   requests stay absent.
3. Open **Privacy settings** and turn on **Analytics** (the `measurement` category) only. PostHog and the video
   load; X Pixel waits for marketing.
4. Allow marketing, then withdraw it. The video iframe is removed and PostHog
   receives an opt-out. Removing a script cannot undo code that already ran.
5. Switch to the Branded design and reload. The styling changes and your choice
   stays the same.

## Run the acceptance suite

The same journeys run automatically. The suite builds each example, serves it
against a fixture backend and intercepts vendor requests, so it needs no Inth
project:

```sh
bunx playwright@1.61.1 install chromium
EXAMPLE_TARGET=nextjs bun run --cwd examples/shared test
```

`EXAMPLE_TARGET` takes a comma-separated list of example IDs, such as
`react,tanstack-start`, or `all`. It defaults to `nextjs`. See the [verification guide](/docs/guides/verify-consent) for the checks
to run against your own backend and vendor accounts before you ship.
