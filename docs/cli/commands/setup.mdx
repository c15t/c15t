## Usage

```bash
inth c15t [scaffold | prompt | --codex | --claude | --cursor | --grok | --fx] [options]
```

Without an action, `inth c15t` asks in the terminal. Every action needs an
Inth project, because the project supplies the backend URL. Without
`--project` or `--name`, it asks you to pick or create one. With `--json` or
`--non-interactive`, it fails with `interaction_required` instead.

## Actions

| Action | Result |
| --- | --- |
| `--codex`, `--claude`, `--cursor`, `--grok`, `--fx` | Start that coding agent in this directory with the c15t setup prompt. The agent must be installed on this machine. |
| `prompt` | Print the setup prompt for any other agent. |
| `scaffold` | Write the framework's quickstart files and install the c15t packages. |

The setup prompt tells the agent to inventory the app, then install c15t,
upgrade it or replace another consent manager. It keeps an existing v2 app on
v2 unless you ask for the upgrade. The agent moves analytics, pixels, tag
managers and embeds behind consent and checks the result in a browser. It does
not provision a backend or migrate a database. Review the diff and the agent's
report before you deploy.

## Options

| Option | Purpose |
| --- | --- |
| `--project <id, name or organization/name>` | Use an existing Inth project. |
| `--name <name>` | Create a project with this name. |
| `--region <id>` | Region for a new project. `inth region list` lists them. |
| `--organization <id>` | Organization to list or create projects in. |
| `--framework <name>` | `next-app`, `next-pages`, `react`, `javascript`, `tanstack-start`, `vue`, `nuxt`, `svelte`, `sveltekit`, `solid`, `astro`, `astro-static` or `html`. |
| `--yes` | Write files without confirming. |
| `--dry-run` | Show the files `scaffold` would write. |
| `--skip-install` | Write files without installing packages. |
| `--resume` | Undo an interrupted `scaffold`, then write again. |
| `--json` | Print the result as JSON and turn off prompts. |

Run `inth c15t --help` for the options your installed version supports.

## What scaffold writes

`scaffold` writes the files from the framework's quickstart. For a React app
built with Vite, that is `.env`, `src/consent.tsx`, `src/main.tsx` and
`vite.config.ts`. The backend URL goes into `.env` under the framework's public
variable, such as `NEXT_PUBLIC_C15T_BACKEND_URL` or `VITE_C15T_BACKEND_URL`.

```bash
inth c15t scaffold --project my-project --framework react --dry-run --json
```

The JSON result lists each file under `data.plan.files`, with `exists` set
when the app already has it, the packages to install under
`data.plan.dependencies`, and steps to finish by hand under
`data.plan.instructions`. `data.project` holds the project ID, name and
backend URL.

`scaffold` installs c15t packages from the v3 release line, such as `c15t@3`.
Add `--skip-install` when your workspace tooling installs dependencies.

`scaffold` leaves the rest of the app unchanged. To fit c15t into an existing
layout and move your vendor scripts behind consent, use an agent action
instead.
