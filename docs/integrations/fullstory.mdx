## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `orgId` | Required | FullStory organization ID. |
| `host` | `fullstory.com` | FullStory host. |
| `script` | `edge.fullstory.com/s/fs.js` | FullStory script host and path. |
| `elementConsent` | `false` | Also set consent for elements marked capture with consent. |
| `category` | `measurement` | Consent condition for the whole loader. |
| `scriptUrl` | HTTPS URL from `script` | Custom or proxied loader URL. Blank values use the default. |

Missing or blank required values log an error and never load.

## Loading and revocation

After consent, the helper creates FullStory's v2 callable queue with six-field command records. Async commands such as `FS('getSessionAsync')` return promises while the SDK loads and after its dispatcher is ready. It configures `captureOnStartup: false` and downloads the SDK. After loading it calls `start`; revocation calls `shutdown`, and regrant calls `restart`. Optional element consent follows the mapped permission through `setIdentity`.

Equivalent registrations share one download and recorder. Each registration must grant the mapped consent before capture can start or resume, including registrations that have never loaded. Initial denial creates no FullStory globals or requests. Removing the last registration shuts down capture. Mounting the same configuration again resumes the retained recorder with `restart` without downloading the SDK again.

Keep `orgId`, `host`, `script` and `scriptUrl` fixed for the page. After bootstrap begins, c15t requires a page reload to change these settings and rejects incompatible configurations explicitly. Removing an async script does not guarantee that its pending download cannot execute, so c15t retains the pending bootstrap too. Remounting the same configuration waits for that download instead of inserting another script. FullStory documents `init` before capture starts; c15t does not support replacing an initialized recorder in place. `scriptUrl` chooses the downloaded file, while `script` configures the SDK's environment. An existing `FS` from another installer must be removed from the site's setup before using this helper.

Shutdown stops capture, but does not erase cookies or unload the SDK. Keep `reloadOnConsentRevoked` enabled when your policy also requires a fresh page without loaded vendor code. Capture state is reapplied on every page.

FullStory can set `fs_uid` and `fs_cid` cookies for one year, `fs_lua` for 30 minutes, and `_fs_tab_id` in sessionStorage. Inspect your account configuration for additional storage.

## Verify FullStory

Check for no FullStory request, `FS`, FullStory configuration globals, cookies or browser storage before consent and after unrelated consent. Grant measurement and verify the real v2 dispatcher installed. With your own account, verify capture starts, shutdown stops it, and regrant restarts it once.
