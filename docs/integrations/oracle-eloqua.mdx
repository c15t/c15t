## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `siteId` | Required | Eloqua site ID. |
| `firstPartyCookieDomain` | Unset | First-party tracking hostname configured in Eloqua. |
| `category` | `marketing` | Consent condition for the whole loader. |
| `scriptUrl` | `https://img.en25.com/i/elqCfg.min.js` | Custom or proxied loader URL. Blank values use the default. |

Missing or blank required values log an error and never load.

Custom loaders must preserve Eloqua's consent response scripts, including `pps=41` for opt-in, `pps=42` for opt-out, and the matching `siteid` query parameter. If a proxy changes this response format, the helper reports a load error and does not send a page view.

## Loading and revocation

After consent, the helper creates `_elqQ`, sets the site ID and optional first-party cookie domain, and downloads the SDK. After loading, it queues `elqOptIn` and waits for its response script before `elqTrackPageView`. The page view uses the full current page URL, including its path, query and fragment, when the response completes.

The helper sends one consent request at a time. If consent changes while a response is pending, it waits for completion and then sends the latest choice. Withdrawal or disposal during opt-in therefore sends `elqOptOut` after that response finishes and suppresses the page view. Regrant waits for any pending opt-out before opting in again. Failed responses do not trigger automatic retries or page views. Regrant preserves Eloqua's installed dispatcher.

Calling `eloquaTracking` again with equivalent options preserves the active consent lifecycle, including pending response handling across disposal and remount. Consent responses for the same site stay serialized when a provider is replaced, even if its category or loader URL changes. When providers share that configuration, every registered provider must allow the category and vendor before tracking starts. A denied provider that has never loaded still participates in this decision. SDK setup waits while a registered provider denies consent.

Keep `reloadOnConsentRevoked` enabled. Eloqua's opt-in and opt-out commands make asynchronous requests; opt-out does not disable every SDK request method or cancel requests already in flight. The helper orders its own consent requests and waits for the first-party opt-in response so a regrant page view does not run while the opt-in cookie still reads `0`. A request that never completes can hold up a later choice until reload. The loader stays in the DOM for same-page regrant because Eloqua replaces its array queue with a dispatcher. Reload gives the next page a fresh tracking lifecycle. Removing a script tag cannot unload the SDK.

Eloqua can set `ELOQUA`, `ELQSTATUS`, `ELQOPTOUT` and first-party `OPTIN` cookies. Oracle documents 13-month tracking cookie lifetimes. Reload does not erase every vendor cookie.

## Verify Oracle Eloqua

Before consent and after unrelated consent, check for no `elqCfg.min.js`, `_elqQ`, Eloqua cookies or browser storage. Grant marketing, confirm the real dispatcher replaces the array, then revoke and inspect the opt-out request. Regrant with your configured account and verify page tracking after the asynchronous opt-in completes.
