## Configure Sentry

`sentry` loads the Sentry browser SDK from Sentry's CDN, calls `Sentry.init`
and applies consent:

- Error monitoring runs for every visitor. Set `loadMode: 'after-consent'` to
  wait for `measurement`.
- Session Replay loads and records only once `measurement` is allowed.
- While `measurement` is denied, events and sessions carry no user, and Sentry
  infers no IP address. Feedback contact emails and names are removed while
  its message is preserved.

The helper loads SDK 11.4.0 with subresource integrity: `bundle.min.js`, or
`bundle.tracing.min.js` when you sample traces. It loads `replay.min.js` only
once Replay is allowed and a Replay sample rate is above 0. Remove Sentry's
Loader Script or CDN tags from the page, or Sentry can start twice.

With `replaysOnErrorSampleRate` above 0, Replay buffers recordings even for
sessions that never send an error. Adding Replay directly to `Sentry.init`
can therefore record visitors before c15t applies consent. The setup here
loads Replay after consent. While Replay is denied or the adapter is removed,
its `start()` and `startBuffering()` methods cannot restart recording.
Confirm your categories with your advisers.

## Use your own Sentry SDK

If your app installs Sentry from npm, such as `@sentry/nextjs`, pass its
functions instead of a DSN. Move `Sentry.init` into a module of its own, without
`replayIntegration()`, and let c15t call it through `init`:

```ts title="src/instrument.ts"
import { init } from '@sentry/browser';

init({
	dsn: 'https://your-key@o0.ingest.sentry.io/0',
	replaysSessionSampleRate: 0.1,
	replaysOnErrorSampleRate: 1,
});
```

```ts title="src/sentry-replay.ts"
import { replayIntegration } from '@sentry/browser';

export const createReplay = () =>
	replayIntegration({ maskAllText: true, blockAllMedia: true });
```

Then pass your SDK's functions to `sentry` in `src/consent-scripts.ts`, in
place of `dsn`:

{/* example: fragment */}

```ts
import { getClient, setUser } from '@sentry/browser';

sentry({
	getClient,
	setUser,
	init: () => import('./instrument'),
	replay: {
		load: () => import('./sentry-replay').then((m) => m.createReplay()),
	},
});
```

Without `init`, Sentry starts before c15t and can send its first session with
the visitor's IP address before consent. In that case, set
`dataCollection: { userInfo: false }` in `Sentry.init`. Requires `@sentry/*`
10.67.0 or later.

The adapter installs its filters after it finds the client. It keeps checking
every 100 ms if initialization happens later. Use `init` to let c15t apply
the current permissions as soon as initialization finishes.

`dataCollection.userInfo: false` does not remove users assigned by your app.
If Sentry must initialize independently, remove `event.user` in `beforeSend`
to protect events captured before the adapter registers. This conservative
filter keeps user data out of error events even after consent:

{/* example: fragment */}

```ts
// Include these options in your app's Sentry.init call.
dataCollection: { userInfo: false },
beforeSend(event) {
	delete event.user;
	return event;
},
```

To permit event users after consent, your `beforeSend` filter must check the
effective c15t permission too. Avoid assigning scope users or capturing logs
and metrics until c15t has registered the adapter. Filters cannot retract data
sent before registration.

Import from the same Sentry package everywhere and use named imports. Next.js
and Vite then move Replay, about 39 KB gzipped, into its own chunk; esbuild and
Bun keep it in the main bundle. A `Sentry.replayIntegration` reference through
`import * as Sentry` anywhere in the main bundle also keeps it there.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `dsn` | Required to load Sentry | Your project's DSN. c15t loads the SDK and calls `Sentry.init`. |
| `initOptions` | `{}` | Passed to `Sentry.init`. `integrations` runs after Sentry loads, so it can read `window.Sentry`. |
| `version` | `'11.4.0'` | SDK version to load. Another version loads without subresource integrity. |
| `tracing` | `true` when traces are sampled | Loads the tracing bundle and adds `browserTracingIntegration()`. |
| `replay` | Loads Replay when sampled | `{ category, options }`, where `options` go to `replayIntegration()`. `false` never loads Replay. |
| `getClient` | Required for your own SDK | `getClient` from your Sentry SDK. Works when c15t starts before `Sentry.init`. |
| `setUser` | None | `setUser` from your Sentry SDK. Called with `null` while user data is not allowed. Required with `pii.user`. |
| `init` | None | Starts your Sentry SDK. Called once, when `loadMode` allows. Required with `loadMode: 'after-consent'` and your own SDK. |
| `replay.load` | None | With your own SDK, returns a new `replayIntegration()`. Called once, the first time Replay is allowed. |
| `loadMode` | `'always'` | `'after-consent'` starts Sentry only once `measurement` is allowed. |
| `replay.category` | `'measurement'` | Consent condition for Replay. |
| `pii.category` | `'measurement'` | Consent condition for user data. `'necessary'` permits it while the Sentry vendor is enabled. |
| `pii.user` | None | Returns the user to set when user data becomes allowed. |
| `onError` | Report to Sentry | Receives Sentry start and Replay load, start and stop failures. |

## Loading and revocation

| `loadMode` | When Sentry runs | On withdrawal without a reload |
| --- | --- | --- |
| `'always'` | On every page, before consent | Replay stops; errors keep reaching Sentry without user data |
| `'after-consent'` | Only while `measurement` is allowed | Sentry stops sending anything |

On withdrawal the adapter calls `replay.stop({ flush: false })` before c15t's
reload, so the pending segment is never sent; segments already sent stay in
Sentry. A later grant restores the original sampling decision rather than
recording in full. If `Sentry.init` already includes Replay, the adapter warns
in development and stops it while `measurement` is denied.

The final envelope filter also drops queued Replay events and recordings while
Replay is denied, stopping, or removed.

While user data is not allowed, the adapter removes `user` from events and
feedback, the user and IP address from sessions, and SDK user attributes from
root spans, child spans, logs and metrics. A final envelope filter also removes
users added by later event processors or `beforeSend`. The adapter switches Sentry's IP inference off for
events, spans, logs and metrics. When the permission is allowed, your own
`dataCollection` setting applies again. Tracing itself is not gated.

Removing the integration stops Replay without flushing, cancels pending starts
and denies user data. With `loadMode: 'after-consent'`, removal also disables
the client. Recreating the integration reuses the client's Replay instance and
sampling decision. An app-initiated `Sentry.close()` stays closed after re-grant.

Recreating `sentry()` with equal option values and the same callback functions
keeps the SDK bundle and current Replay recording. Keep `getClient`, `setUser`,
`init`, `replay.load`, `pii.user` and `onError` functions stable across renders. A changed
configuration starts a new adapter lifecycle; removing it still stops Replay
without flushing.

If multiple loaders share the same configuration, Sentry stays active until
the last loader removes it. Replay and user data require consent from every
active loader; a denial in one loader applies to the shared SDK.

The vendor slug is `sentry`; turning that vendor off denies Replay and user
data, and error monitoring with `loadMode: 'after-consent'`. See
[vendor consent for your framework](/docs/integrations/overview#vendor-switches-and-cookie-cleanup).
Replay compresses in a `blob:` worker, so allow `worker-src blob:`. With `dsn`,
allow `https://browser.sentry-cdn.com` in `script-src`.
Allow your SDK's ingest endpoint in `connect-src`: the DSN host for Sentry SaaS,
your configured host for self-hosted Sentry, or your tunnel endpoint when using
a proxy.

## Verify Sentry

Test in a private window with an opt-in policy and
`replaysSessionSampleRate: 1`. Filter DevTools Network by `sentry`.

1. Load the page. `bundle.min.js` loads and errors reach Sentry, without `user`.
   No `replay.min.js` or `replay_recording` request is sent. With
   `loadMode: 'after-consent'`, nothing loads.
2. Allow measurement. Without a reload, Replay loads and `replay_recording`
   requests start.
3. Turn measurement off and save. c15t reloads the page, and no replay request
   follows.

See the [consent verification guide](/docs/guides/verify-consent) for
navigation, expiry and hosting checks.
