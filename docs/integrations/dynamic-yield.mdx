The c15t `dynamicYield` helper loads Dynamic Yield after `experience` consent.
It sets `DY.userActiveConsent` before loading `api_dynamic.js`, then loads
`api_static.js` after the first script finishes. No Dynamic Yield global,
preconnect, loader request or storage is created before the helper's consent
gate opens.

Dynamic Yield recommends synchronous scripts directly in the page's `<head>`
to avoid flicker. Waiting for consent and loading the scripts in sequence
changes that timing. Check your campaigns and page rendering with Dynamic
Yield before using this helper for experiments that need to run before paint.

## Configure Dynamic Yield

Copy the section ID and data center from your section's
[installation snippet](https://dy.dev/docs/implement-script). Enable
[Active Cookie Consent](https://dy.dev/docs/active-cookie-consent) with Dynamic
Yield Support. Preview mode lets you check it first. Dynamic Yield ignores the
consent API until this setting is enabled for your section.

Remove existing Dynamic Yield snippets, tag-manager tags and preconnects.
c15t gates only the scripts registered with it.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `sectionId` | Required | Public section ID. Surrounding whitespace is trimmed. Missing or blank values log an error and skip the integration. |
| `region` | `'us'` | `'us'` uses `cdn.dynamicyield.com`; `'eu'` uses `cdn-eu.dynamicyield.com`. Match the section's data center. |
| `recommendationContext` | Not set | Page context assigned before either loader runs. Omit to preserve a context your app already set. |
| `category` | `'experience'` | c15t consent category or condition that gates both loaders and the consent signal. |
| `nonce` | None | CSP nonce for both loaders. A nonce supplied by your consent provider is forwarded to the second loader too. |

`recommendationContext.type` accepts `HOMEPAGE`, `CATEGORY`, `PRODUCT`, `CART`,
`POST` and `OTHER`. `data` contains the category hierarchy, product SKUs, post ID
or page identifier. `lng` selects a feed locale such as `en_GB`. Match values
to the section's product or content feed. See Dynamic Yield's
[page context guide](https://dy.dev/docs/page-context).

The helper seeds the initial context. Your application owns context updates
on client-side navigation. Follow Dynamic Yield's
[context implementation guide](https://dy.dev/docs/code-context) and check
consent before making your own Dynamic Yield calls.

## Loading and revocation

Before consent, neither loader runs and `window.DY` stays absent unless another
part of your app created it. Granting the mapped consent creates `DY` if needed,
sets `DY.userActiveConsent = { accepted: true }`, and starts the dynamic loader.
The static loader starts after the dynamic loader finishes. Registrations that
share the dynamic loader also share its static loader. Removing one registration
keeps both elements for any remaining owner. If consent is withdrawn while the
dynamic loader is downloading, the helper skips the static loader.

On withdrawal, the helper assigns `DY.userActiveConsent = { accepted: false }`
and removes both loader elements. The SDK's consent setter applies only when
Active Cookie Consent is enabled for the section. It changes data collection
and personalization behavior. It does not unload the SDK or guarantee zero
requests from code that already ran. Keep c15t's default
`reloadOnConsentRevoked` behavior enabled.

Dynamic Yield's denied mode can serve limited experiences. This helper waits
for consent before loading either script, so it does not use denied-mode
campaign delivery before consent. There is no `alwaysLoad` option.

## Cookies and storage

Dynamic Yield's [cookie and storage inventory](https://dy.dev/docs/cookie-management)
includes these cookies. Your section and campaigns determine which appear.

| Cookie | Documented lifetime |
| --- | --- |
| `_dyid` | 30 days |
| `_dyjsession` | Browser session |
| `_dy_soct` | 1 year |
| `dy_fs_page` | Browser session |
| `_dy_cs_storage_items` | 30 days |
| `_dy_cs_cookie_items` | 30 days |

Dynamic Yield caps cookie storage at 365 days. Its browser storage also
includes `_dyuss_`, `_dy_tsrc`, `_dyaud_nchc`, `_dyaud_page`, `_dy_device`,
`_dycst`, `_dy_csc`, `_dyrc`, `_dybatch`, `_dy_cs_session_items` and
`_dy_cs_local_items`. `_dyaud_sess` uses session storage. Check the vendor
inventory and your browser for the keys used by your section.

The helper does not delete previously stored cookies or browser storage.
Configure cleanup for your deployment and verify it after withdrawal.

## Verify the integration

Filter DevTools Network by `dynamicyield.com`. Grant `experience` and check
that `api_dynamic.js` finishes before the helper appends `api_static.js`.
Inspect `DY.userActiveConsent.accepted` and your page context. Revoke consent
and check the next page makes no Dynamic Yield request. Test vendor-specific
switches and the category override if your app uses them.
