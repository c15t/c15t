Each helper below loads its vendor only after the visitor allows the listed consent category. For setup, see [Integrations overview](/docs/integrations/overview).

## Attentive

Attentive shows SMS and email signup units and tracks on-site events for its marketing messages. Waits for `marketing` consent.

<include src="../shared/examples/javascript/attentive-configuration.mdx" />

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `siteSlug` | `string` | Yes | Site slug from your Attentive tag URL, `https://cdn.attn.tv/<siteSlug>/dtag.js`. Ask your Attentive contact if you don't have it. |
| `scriptUrl` | `string` | No | Exact tag URL from Attentive or your proxy. |

**When consent is withdrawn:** c15t reloads the page, and the next page does not load the tag. Attentive has no supported way to stop a running tag, so keep `reloadOnConsentRevoked` on.

- Some Attentive identifiers, such as `__attentive_id`, last up to 390 days. The reload does not delete them.

## Customer.io

Customer.io collects events and visitor identity on your site through its Data Pipelines JavaScript source, for use in its messaging. Waits for `marketing` consent.

<include src="../shared/examples/javascript/customer-io-configuration.mdx" />

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `writeKey` | `string` | Yes | Write key of your Data Pipelines JavaScript source. |
| `region` | `'us'` or `'eu'` | No | Region of the source. Defaults to `us`. |
| `loadOptions` | `Record<string, unknown>` | No | Options for the Customer.io loader, such as destination settings. |
| `cdnUrl` | `string` | No | Origin of a proxy for the loader, source settings and SDK files. |

**When consent is withdrawn:** the helper calls `cioanalytics.reset()` to clear the stored identity, and c15t reloads the page. `reset()` is not an opt-out. It does not stop the SDK or destination SDKs from sending, so keep `reloadOnConsentRevoked` on.

- The helper sends the first `page()` call itself. It always sets `initialPageview` to `false`, even if you pass `true`.
- `cdnUrl` moves only the loader, settings and SDK files to your proxy. To proxy collected events too, set `apiHost` for the `Customer.io Data Pipelines` integration in `loadOptions`:

## Insider One

Insider One runs personalized web campaigns and builds customer profiles from on-site behavior. Waits for `marketing` consent.

<include src="../shared/examples/javascript/insider-scripts.mdx" />

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `partnerName` | `string` | Yes | Public partner name from Insider. |
| `partnerId` | `string` | Yes | Public partner ID from Insider. |
| `user` | `Record<string, unknown>` | No | Current user attributes, such as `email`, `phone_number` and `custom`. Must be JSON-serializable. |
| `currency` | `string` | No | Current currency, such as `'GBP'`. Set it on multi-currency sites. |
| `pageType` | `InsiderPageType` | No | Page definition from Insider's Web SDK guide. Defaults to `{ type: 'other' }`. |

**When consent is withdrawn:** the helper pushes `gdpr_optin: false`, a neutral `other` page and `init`, then c15t reloads the page. Insider has no unload method, so keep `reloadOnConsentRevoked` on.

- The helper sets `gdpr_optin` from consent and overrides any value in `user`. If you push `user` data to `InsiderQueue` yourself, set `gdpr_optin` too, because Insider treats a missing value as `true`.
- The helper does not deduplicate purchases. Set `pageType: { type: 'purchase', ... }` only when your backend claims that order ID for the first time. Use `{ type: 'other' }` when the confirmation page reloads or opens again.

## Marketo Munchkin

Munchkin is Adobe Marketo's script for tracking known and anonymous leads on your site. Waits for `marketing` consent.

<include src="../shared/examples/javascript/marketo-configuration.mdx" />

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `munchkinId` | `string` | Yes | Account ID from Marketo's installation snippet. |
| `initOptions` | `Record<string, unknown>` | No | Passed to `Munchkin.init`, for example `cookieAnon` or `anonymizeIP`. |
| `category` | consent condition | No | Replaces the default `marketing` condition. |
| `scriptUrl` | `string` | No | Custom or proxied loader URL. |

**When consent is withdrawn:** c15t removes the loader and reloads the page. Munchkin has no API to stop tracking, so keep `reloadOnConsentRevoked` on.

- `cookieAnon: false` stops Munchkin from creating cookies for new anonymous visitors. It is not a consent switch: visitors who already have a cookie are still tracked.
- The `_mkto_trk` cookie lasts two years by default and survives the reload. The next page does not load Munchkin while consent is denied.

## Salesforce Account Engagement

Account Engagement, formerly Pardot, tracks visitors and prospects for Salesforce B2B marketing. Waits for `marketing` consent.

<include src="../shared/examples/javascript/salesforce-pardot-configuration.mdx" />

Replace `pi.pardot.com` in the example with your verified tracker domain.

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `piAId` | `string` or `number` | Yes | Account ID from the tracking snippet. |
| `piCId` | `string` or `number` | Yes | Campaign ID from the tracking snippet. |
| `piDomain` | `string` | In consent mode | Verified tracker domain, without a scheme or path. |
| `mode` | `'consent'` or `'classic'` | No | `consent`, the default, uses the Tracking and Consent API. `classic` loads the older `pd.js` snippet. |
| `piHostname` | `string` | No | Tracker hostname in classic mode. Defaults to `pi.pardot.com`. |

**When consent is withdrawn:** in consent mode, the helper calls `pdt('revokeConsent')`. Classic mode has no revoke call. Keep `reloadOnConsentRevoked` on in both modes, because the reload is what stops the running tracker.

- Turn on the Tracking and Consent API in Account Engagement before you use consent mode.
- Copy `piAId` and `piCId` from the generated snippet as they are. They already include Salesforce's +1000 offset, and the helper does not add it again.
- Do not call `clearTrackingCookies` after `revokeConsent`. It also deletes the cookie that records the refusal, so later page views can be tracked.
