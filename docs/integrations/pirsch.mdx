## Configure Pirsch

Copy the identification code from your Pirsch installation. The helper also initializes Pirsch event bindings when consent is granted after `DOMContentLoaded`.

<CommandTabs command="@c15t/scripts" mode="install" />

```ts title="src/consent-scripts.ts"
import { pirsch } from '@c15t/scripts/pirsch';

export const scripts = [pirsch({ identificationCode: 'YOUR_IDENTIFICATION_CODE' })];
```

## Options

| Option | Behavior |
| --- | --- |
| `identificationCode` | Required non-empty code. |
| `domain` | Optional domain string or array, serialized as a comma-separated value. |
| `dev` | Optional hostname override for localhost testing. |
| `hitEndpoint / eventEndpoint` | Optional collection endpoint overrides. |
| `disablePageViews / extended` | Disable automatic page views or select the extended script. |
| `scriptUrl` | Optional loader override. |

## Consent behavior

The script waits for measurement permission. No vendor stop callback runs on revocation. Check application events and vendor-installed event bindings after a later denial.

## Verify the integration

Grant consent after the page has finished loading and test a custom event. In local development, configure `dev` deliberately before expecting the dashboard to show test traffic.

Use a fresh session with an opt-in policy to check initial denial. Then grant
`measurement`, revoke it, and reload. Inspect both network requests and future
application events. Removing a script cannot undo code or requests that already
ran. Follow the [consent verification guide](/docs/guides/verify-consent).
