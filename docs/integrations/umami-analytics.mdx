## Configure Umami Analytics

Copy the website ID from your Umami tracking code. The helper passes it to the
script as `data-website-id`. For a self-hosted Umami instance, set `scriptUrl`
to your instance's tracker script.

<CommandTabs command="@c15t/integrations" mode="install" />

```ts title="src/consent-scripts.ts"
import { umamiAnalytics } from '@c15t/integrations/umami-analytics';

export const scripts = [umamiAnalytics({ websiteId: 'YOUR_WEBSITE_ID' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `websiteId` | Required | Set as `data-website-id`. Empty or whitespace-only values throw. |
| `hostUrl` | None | Host that receives events, set as `data-host-url`. |
| `autoTrack` | None | `false` sets `data-auto-track="false"` and stops automatic tracking. |
| `domains` | None | Domains to track, set as `data-domains`. Pass a comma-separated string or an array; the helper joins an array with commas. |
| `tag` | None | Tag attached to events, set as `data-tag`. |
| `beforeSend` | None | Name of a global function, set as `data-before-send`. Function values are not supported. |
| `scriptUrl` | `https://cloud.umami.is/script.js` | Loader URL override. |

## Loading and revocation

`umamiAnalytics` uses the `measurement` category. The tracker loads only while
measurement is allowed. On revocation the helper removes the script element and
calls no Umami API. Umami sets no cookies, but c15t still waits for measurement
permission before loading it.

A `beforeSend` hook can change events before Umami sends them. It is not a
consent check. Define the named global before the tracker loads.

## Verify Umami Analytics

After you allow measurement, the tracker script loads with your
`data-website-id`, and a request to `/api/send` goes to Umami or to your
`hostUrl`. If your code calls `window.umami.track`, check measurement
permission before each call.
