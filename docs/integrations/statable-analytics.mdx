The c15t `statableAnalytics` helper waits for `measurement` consent before
loading Statable's tracker. Statable describes its analytics as cookieless;
the helper still blocks its network requests until consent allows it. When a
visitor withdraws consent, c15t reloads the page by default to stop the running
tracker.

## Configure Statable

Copy the numeric site ID from **Site settings > Tracking Code** in Statable.
Replace `12345` in the example with that ID. This helper uses the standalone
`/js/<siteId>/s.js` tracker, which Statable provides on paid plans. Statable's
Hobby plan bundles tracking inside a widget and uses a different loader.

Remove any existing Statable script tag or tag-manager installation so it
cannot load outside c15t.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `siteId` | Required | Positive integer as a string or number. Whitespace is trimmed. Blank, fractional, negative, non-decimal or unsafe integer values log an error and the script does not load. |
| `scriptUrl` | `https://statable.com/js/{siteId}/s.js` | Loader URL override. Each `{siteId}` is replaced with the validated ID. Blank values use the default. |
| `trackingApi` | Loader origin plus `/api/event` | Complete ingestion endpoint, forwarded as `data-tracking-api`. The tracker posts to this URL as supplied. Blank values leave Statable's default in place. |

When serving the tracker through your own CDN, also supply the complete
ingestion endpoint if the CDN does not serve or proxy `/api/event`. Replace
both example hosts with your own configured hosts:

A custom `scriptUrl` only changes where the browser fetches the tracker. It
does not proxy event requests. Statable uses the visitor's connection to the
ingestion server for its reports; check Statable's guidance before proxying
collection.

## Loading and revocation

`statableAnalytics` appends a deferred script with your site ID in its path
and `data-id` attribute. It does not create `window.statable` or queue custom
events. The real tracker initializes `window.statable.t` after loading.
Check measurement permission and wait for that API before sending an event;
early events are not replayed.

The helper calls no Statable consent or stop API. Revocation removes the
loader element, but the tracker's event listeners and timers remain active
until the page unloads. Keep `reloadOnConsentRevoked` enabled. Turning it off
allows tracking to continue on the current page.

Statable says that it sets no cookies and stores no persistent visitor ID in
the browser. Its tracker reads the `analytics_ignore` localStorage flag and
sends the full page URL, including its query and fragment, to ingestion.
Statable says it strips queries and fragments when processing URLs. Avoid
putting sensitive information in URLs regardless.

Allow `https://statable.com` in your Content Security Policy's `script-src`
and `connect-src`, or the corresponding custom loader and ingestion hosts.

## Verify Statable

With measurement denied, filter DevTools Network by `statable.com` and check
that no loader or event request appears. Check Cookies, Local Storage and
Session Storage in DevTools Application for vendor entries. Allowing only
marketing must leave Statable blocked too.

After granting measurement, expect one `/js/<siteId>/s.js` script element and
`typeof window.statable?.t === 'function'`. With a configured site, its events
post to `/api/event` or your complete `trackingApi` URL. Statable suppresses
collection for automation, Do Not Track, Global Privacy Control and the
`analytics_ignore` flag, so an initialized API alone does not prove that an
event reached your dashboard.
