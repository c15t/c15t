## Configure LogRocket

Copy the app ID from LogRocket Project Setup. It has the form
`org-slug/app-slug`. Remove the original LogRocket install.

<CommandTabs command="@c15t/scripts@alpha" mode="install" />

```ts title="src/consent-scripts.ts"
import { logRocket } from '@c15t/scripts/logrocket';

export const scripts = [logRocket({ appId: 'your-org/your-app' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `appId` | Required | App ID passed to `LogRocket.init`. The helper trims it. Values that are not two non-empty segments separated by `/` throw. |
| `initOptions` | `{}` | Second argument to `LogRocket.init`. Use JSON-serializable values only, so functions such as request sanitizers cannot pass through. |
| `scriptUrl` | `https://cdn.logrocket.io/LogRocket.min.js` | Loader URL override. A blank value falls back to the default. |
| `asyncScriptUrl` | None | Proxied URL for LogRocket's logger bundle, set as `window._lrAsyncScript` before the loader runs. Set it only when you proxy LogRocket through your own domain. |

## Loading and revocation

`logRocket` uses the `measurement` category. When measurement becomes allowed,
the helper loads `LogRocket.min.js` with `crossorigin="anonymous"` and calls
`LogRocket.init(appId, initOptions)` after the script loads.

On revocation the helper removes the script element and calls no LogRocket
API, because LogRocket documents no consent or stop-recording call for the web
SDK. Recording continues until the page unloads, so c15t's default reload on
revocation is what stops it. Configure LogRocket's privacy and sanitization
settings before you deploy, so recordings leave out sensitive DOM, input and
network data.

## Verify LogRocket

Filter DevTools Network by `logrocket`. After you allow measurement,
`LogRocket.min.js` loads and `window.LogRocket` exists. With `asyncScriptUrl`,
check that the logger bundle loads from your proxy URL.
