The c15t `clearbit` helper keeps the Clearbit tag, `tags.js`, off the page until
the visitor gives consent for `marketing`. The category is `marketing`, not
`measurement`, because Clearbit identifies visitors and their companies. The
helper sends no consent signal to Clearbit. If the visitor withdraws consent,
c15t removes the script element. By default, c15t also reloads the page.

## Configure Clearbit

Use the publishable key from your Clearbit tag installation. Do not put a
secret Clearbit API key in browser code.

<CommandTabs command="@c15t/integrations@alpha" mode="install" />

```ts title="src/consent-scripts.ts"
import { clearbit } from '@c15t/integrations/clearbit';

export const scripts = [clearbit({ publishableKey: 'YOUR_PUBLISHABLE_KEY' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `publishableKey` | Required | Publishable key. The helper trims it and URL-encodes it into the default loader URL. Empty or non-string values throw. |
| `scriptUrl` | `https://tag.clearbitscripts.com/v1/<publishableKey>/tags.js` | Loader URL override. A blank value falls back to the default. |

## Loading and revocation

`clearbit` uses the `marketing` category, not `measurement`. Clearbit
identifies visitors and their companies for enrichment, so c15t treats it as
marketing even though these docs list it with analytics. The `tags.js` script
loads with `referrerpolicy="strict-origin-when-cross-origin"` only while
marketing is allowed. On revocation the helper removes the script element and
calls no Clearbit API.

## Verify Clearbit

Filter DevTools Network by `clearbitscripts.com`. After you allow marketing,
the `tags.js` request carries your publishable key in its path. Allowing
measurement alone loads nothing from Clearbit.
