The c15t `microsoftUet` helper loads Microsoft Advertising UET, `bat.js`, on
every page, before the visitor chooses. Before the script loads, the helper
calls `uetq.push('consent', 'default', { ad_storage })`. The `ad_storage` value
is `granted` or `denied`, from the consent for `marketing`. When that consent
changes, the helper sends an `update`. After the visitor withdraws consent, UET
stays on the page and gets `denied`. By default, c15t also reloads the page.

## Configure Microsoft UET

Copy your UET tag ID from Microsoft Advertising. Remove the UET snippet and
any tag-manager entry that loads the same tag, because the helper creates the
`uetq` queue and constructs UET itself.

<CommandTabs command="@c15t/integrations@alpha" mode="install" />

```ts title="src/consent-scripts.ts"
import { microsoftUet } from '@c15t/integrations/microsoft-uet';

export const scripts = [microsoftUet({ id: 'YOUR_UET_TAG_ID' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `id` | Required | UET tag ID, passed to UET as `ti`. The helper trims it. Empty or whitespace-only values throw. |
| `scriptSrc` | `//bat.bing.com/bat.js` | Loader URL override. A blank value falls back to the default. |

## Loading and revocation

`microsoftUet` uses the `marketing` category and `alwaysLoad`, so `bat.js`
loads on every page whether or not marketing is allowed. Before the script
loads, the helper calls `uetq.push('consent', 'default', { ad_storage })` with
`granted` or `denied` from the current marketing permission. After `bat.js`
loads, it constructs UET with `enableAutoSpaTracking: true` and pushes
`pageLoad`. This is consent signaling, not a request gate. Microsoft's consent
mode decides what UET does while `ad_storage` is denied.

The helper never removes UET. When marketing changes, it calls
`uetq.push('consent', 'update', { ad_storage })` with the new value. Automatic
SPA tracking sends page loads on client-side navigation, so do not push
`pageLoad` from your router.

## Verify Microsoft UET

1. In a private window with an opt-in policy, load the page. The `bat.js`
   request goes to `bat.bing.com` before you choose, and UET sends its page
   load.
2. Click Reject, then reload. `bat.js` still loads, and the page starts with
   `ad_storage` denied.
3. Open Privacy settings and allow marketing. No second `bat.js` request
   appears, because the helper sends a consent update to the running tag
   instead of reloading it.
4. Navigate to another route in a single-page app. UET sends one page load for
   the route change, not two.
5. Turn marketing off again and save. c15t reloads the page, and the new page
   starts with `ad_storage` denied.

See the [consent verification guide](/docs/guides/verify-consent) for
navigation and hosting checks.
