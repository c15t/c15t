## Configure Databuddy

Copy the client ID from your Databuddy project. The helper passes it to the
script as `data-client-id`. Remove any existing Databuddy script and any code
that sets `window.databuddyConfig`. The helper seeds that global only when it
is absent, so an existing value overrides your initial state.

<CommandTabs command="@c15t/integrations@alpha" mode="install" />

```ts title="src/consent-scripts.ts"
import { databuddy } from '@c15t/integrations/databuddy';

export const scripts = [
  databuddy({
    clientId: 'YOUR_CLIENT_ID',
    configWhenGranted: { disabled: false },
    configWhenDenied: { disabled: true },
  }),
];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `clientId` | Required | Set as `data-client-id`. The helper does not validate it. |
| `configWhenGranted` | Required | Object set as `window.databuddyConfig` while measurement is allowed. |
| `configWhenDenied` | Required | Object set as `window.databuddyConfig` while measurement is denied. |
| `apiUrl` | `https://basket.databuddy.cc` | Collection endpoint, set as `data-api-url`. |
| `scriptUrl` | `https://cdn.databuddy.cc/databuddy.js` | Loader URL override. |

## Loading and revocation

`databuddy` uses the `measurement` category with `alwaysLoad`, so the
Databuddy script loads on every page, before the visitor chooses. Before the
script loads, the helper sets `window.databuddyConfig` to `configWhenDenied` or
`configWhenGranted`, unless that global already exists. After the script
loads, the helper sets `window.databuddy.options.disabled` to `true` without
measurement permission and to `false` with it. On each later consent change,
the helper replaces `window.databuddyConfig` with the matching object and
updates `disabled` again. c15t never removes the script.

The Databuddy SDK decides what `disabled` stops. The helper cannot prevent the
script request before consent. If Databuddy must receive no request before
consent, write a
[custom gated integration](/docs/integrations/building-integrations) instead.

## Verify Databuddy

1. In a private window with an opt-in policy, load the page. `databuddy.js`
   loads from `cdn.databuddy.cc` with your `data-client-id`. In the console,
   `window.databuddyConfig` matches `configWhenDenied` and
   `window.databuddy.options.disabled` is `true`.
2. Click Reject, then reload. `disabled` is still `true`, and DevTools Network
   shows no event request to your `apiUrl`.
3. Open Privacy settings and allow measurement. Without a reload, `disabled`
   becomes `false`, `window.databuddyConfig` matches `configWhenGranted`, and
   event requests reach your `apiUrl`.
4. Turn measurement off again and save. c15t reloads the page, and the new
   page starts with `disabled` set to `true`.

See the [consent verification guide](/docs/guides/verify-consent) for
navigation and hosting checks.
