## Configure Amplitude

Use your Amplitude project API key. The `amplitude` helper initializes Browser
SDK 2 for you, so remove any existing Amplitude snippet or `init` call.

<CommandTabs command="@c15t/scripts@alpha" mode="install" />

```ts title="src/consent-scripts.ts"
import { amplitude } from '@c15t/scripts/amplitude';

export const scripts = [amplitude({ apiKey: 'YOUR_PROJECT_API_KEY' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `apiKey` | Required | Project API key passed to `amplitude.init`. The helper trims it. Empty or whitespace-only values throw. |
| `initOptions` | `{}` | Browser SDK 2 options passed as the second argument to `init`. Use JSON-serializable values only. |
| `scriptUrl` | `https://cdn.amplitude.com/libs/analytics-browser-2.44.4-min.js.gz` | Loader URL override. The default pins Browser SDK 2 version `2.44.4`. A blank value falls back to the default. |

## Loading and revocation

`amplitude` uses the `measurement` category. Before measurement is allowed,
c15t defines no `window.amplitude` and loads nothing from Amplitude. When
measurement becomes allowed, the helper creates the Browser SDK 2 queue stub,
queues `init(apiKey, initOptions)`, then loads the SDK, which replays the
queue.

On revocation the helper removes the loader script and calls
`amplitude.setOptOut(true)` on the SDK that already loaded. If the visitor
allows measurement again before the page reloads, c15t adds the loader again
and queues another `init`. It does not call `setOptOut(false)` on that path.

## Verify Amplitude

After you allow measurement, the `analytics-browser-2.44.4-min.js.gz` request
loads and a test event reaches your Amplitude project. Revoke measurement, then
allow it again on a later page and check that events reach Amplitude again.
