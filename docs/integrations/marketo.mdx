The `marketoMunchkin` helper waits for `marketing` consent before requesting
Munchkin or initializing tracking. Rejecting consent creates no Munchkin global,
cookie or browser storage through this integration.

## Configure Marketo Munchkin

Copy your Munchkin account ID from Marketo's installation snippet. Remove any
existing Munchkin tag so that c15t controls when it loads.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `munchkinId` | Required | Public account ID. Whitespace is trimmed. Missing or blank IDs log an error and never load. |
| `initOptions` | `{}` | Passed to `Munchkin.init`, including `cookieAnon`, `anonymizeIP`, `apiOnly` and `cookieLifeDays`. |
| `category` | `marketing` | Consent condition that gates the whole loader. |
| `scriptUrl` | `https://munchkin.marketo.net/munchkin.js` | Custom or proxied loader URL. Blank values use the default. Other vendor requests need separate proxy configuration. |

`cookieAnon: false` prevents tracking new anonymous visitors. It is not a
runtime consent switch for visitors who already have a tracking cookie.

## Loading and revocation

After consent, c15t downloads the SDK and calls `Munchkin.init` once with the
account ID and options. Revocation during the download skips initialization.
Unrelated consent changes do not initialize Munchkin again.

Munchkin has no documented runtime stop API. Keep `reloadOnConsentRevoked`
enabled. Removing the loader does not stop the running SDK. The next page
will not load Munchkin while its mapped consent is denied.

Munchkin can set `_mkto_trk` for two years by default. Reloading does not
remove it. Marketo's separate `marketo_opt_out=true` URL flow sets
`mkto_opt_out` and disables tracking. This helper does not set that persistent
opt-out because it would also affect a later consent grant.

## Verify Marketo Munchkin

Filter Network by `munchkin.marketo.net`. Before consent, check that no loader
request, `window.Munchkin`, `_mkto_trk` or vendor browser storage appears.
Grant marketing and check that the SDK loads and initializes. Reject marketing
again and check that the reloaded page makes no Munchkin request.

The implementation follows Adobe's [async installation snippet](https://experienceleague.adobe.com/en/docs/marketo-developer/marketo/javascriptapi/leadtracking/lead-tracking)
and [configuration reference](https://experienceleague.adobe.com/en/docs/marketo-developer/marketo/javascriptapi/leadtracking/configuration).
