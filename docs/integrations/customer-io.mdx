## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `writeKey` | Required | Data Pipelines JavaScript source key. |
| `region` | `us` | `us` uses `cdp.customer.io`; `eu` uses `cdp-eu.customer.io`. |
| `loadOptions` | Unset | Vendor loader options, including destination integration settings. |
| `category` | `marketing` | Consent condition for the whole loader. |
| `scriptUrl` | Region-specific snippet URL | Custom or proxied loader URL. Blank values use the default. |

Missing or blank required values log an error and never load.

## Loading and revocation

After consent, the helper creates Customer.io's array queue and method stubs, sets `_writeKey` and `_loadOptions`, and loads the region-specific SDK. The script carries the namespace attribute required by Customer.io. Page tracking starts only after the load completes with consent still granted.

Revocation calls `reset()` to clear identity. It does not stop SDK dispatch, retries or destination SDKs. Keep `reloadOnConsentRevoked` enabled. The SDK loads once per page; regrant reuses it instead of injecting another copy. On the next denied page the helper creates no queue or vendor requests.

Customer.io can use analytics identity cookies and localStorage keys including `ack`, `reclaimStart`, `reclaimEnd`, `inProgress` and `queue`. Destination integrations can add storage of their own. Reset is not a promise to erase all destination data.

## Verify Customer.io

Check for no Customer.io snippet request, `cioanalytics`, vendor cookies or browser storage before consent and after unrelated consent. Grant marketing and verify the real SDK initialized, then revoke and check identity reset. Keep withdrawal reload enabled and confirm the next denied page stays quiet. A 200 JSON response for an invalid key is not evidence of SDK initialization.
