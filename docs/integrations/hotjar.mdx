The c15t `hotjar` helper keeps Hotjar off the page until the visitor gives
consent for `measurement`. Before consent, c15t does not define
`window._hjSettings` or `window.hj`. The helper sends no consent signal to
Hotjar. If the visitor withdraws consent, c15t removes the loader script
element. By default, c15t also reloads the page. The reload stops Hotjar.

## Configure Hotjar

Copy the site ID from your Hotjar tracking code, where it is the `hjid` value.
Remove the original tracking code.

<CommandTabs command="@c15t/integrations@alpha" mode="install" />

```ts title="src/consent-scripts.ts"
import { hotjar } from '@c15t/integrations/hotjar';

export const scripts = [hotjar({ siteId: 1234567 })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `siteId` | Required | Site ID as a number or string. Set as `window._hjSettings.hjid` and used in the default loader URL. Missing, empty and `0` values throw. |
| `version` | `6` | Script version, set as `window._hjSettings.hjsv` and the `sv` query parameter of the default loader URL. |
| `scriptUrl` | `https://static.hotjar.com/c/hotjar-<siteId>.js?sv=<version>` | Loader URL override. |

## Loading and revocation

`hotjar` uses the `measurement` category. When measurement becomes allowed,
the helper sets `window._hjSettings` and a queue-backed `window.hj` stub, each
only when the global is undefined, then loads the Hotjar loader.

On revocation the helper removes the loader script element and calls no Hotjar
API. A recording in progress continues until the page unloads, so c15t's
default reload on revocation is what ends it.

## Verify Hotjar

Filter DevTools Network by `hotjar`. After you allow measurement, the
`hotjar-<siteId>.js` request loads from `static.hotjar.com`, and
`window._hjSettings.hjid` holds your site ID. Review a recording of a real
screen in your app to check that Hotjar masks the fields you expect.
`window.hj` still exists after revocation, so check measurement permission
before your own `hj` calls.
