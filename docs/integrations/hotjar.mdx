Hotjar records what visitors do on your pages, so it should load only when
consent allows analytics. The c15t `hotjar` helper waits until the
`measurement` category is allowed before it adds the Hotjar loader. Until then,
c15t doesn't define `window._hjSettings` or `window.hj`, and it loads nothing
from Hotjar. Under an opt-in policy, that wait lasts until the visitor allows
analytics.

Withdrawal needs more care. c15t sends Hotjar no consent signal, so it can't
tell a running recording to stop. By default it reloads the page instead, and
the reload ends the recording.

## Configure Hotjar

Find your site ID in the Hotjar tracking code. It's the `hjid` value. Then
delete the tracking code from your app. If it stays, Hotjar loads whatever the
visitor chooses.

<CommandTabs command="@c15t/integrations" mode="install" />

```ts title="src/consent-scripts.ts"
import { hotjar } from '@c15t/integrations/hotjar';

export const scripts = [hotjar({ siteId: 1234567 })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `siteId` | Required | Site ID as a number or string. Set as `window._hjSettings.hjid` and used in the default loader URL. If it's missing, empty or `0`, c15t logs an error and never loads Hotjar. |
| `version` | `6` | Script version, set as `window._hjSettings.hjsv` and the `sv` query parameter of the default loader URL. |
| `scriptUrl` | `https://static.hotjar.com/c/hotjar-<siteId>.js?sv=<version>` | Loader URL override. |

## Loading and revocation

`hotjar` uses the `measurement` category. When `measurement` is allowed, the
helper sets `window._hjSettings` and a `window.hj` stub that queues calls, then
loads the Hotjar script. If your page already defines either global, the helper
leaves it alone.

When the visitor withdraws, the helper removes the script element. Hotjar is
already running by then, so removing the element doesn't stop it. The default
page reload does. If you set `reloadOnConsentRevoked: false`, Hotjar keeps
recording until the visitor leaves the page.

## Verify Hotjar

Filter the DevTools Network panel by `hotjar`. After you allow measurement,
the loader appears and `window._hjSettings.hjid` holds your site ID. If it
holds a different ID, other code on the page set `_hjSettings` before c15t, and
the helper left it alone. Find and remove that code. By default
the loader is `hotjar-<siteId>.js` from `static.hotjar.com`. If you set
`scriptUrl`, look for that URL instead.

Then watch one recording of a real screen in your app. Hotjar decides what to
mask, not c15t, so check that it hides the fields you expect.

`window.hj` stays defined after withdrawal. If your own code calls `hj()`,
check the measurement permission first.
