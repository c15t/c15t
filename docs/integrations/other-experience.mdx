## Adobe Target

Adobe Target runs A/B tests and personalizes page content. Waits for
`experience` consent. Pick one mode per page: your self-hosted at.js file, or
Adobe Experience Platform Web SDK.

<include src="../shared/examples/javascript/adobe-target-atjs.mdx" />

<include src="../shared/examples/javascript/adobe-target-websdk.mdx" />

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `mode` | `'atjs' \| 'websdk'` | Yes | Which Adobe SDK to load. |
| `scriptUrl` | `string` | at.js | URL of your self-hosted at.js file. |
| `targetGlobalSettings` | `object` | No | at.js settings such as `cookieDomain`, `secureOnly`, `bodyHidingEnabled` and `bodyHiddenStyle`. The helper always sets `optinEnabled: true`. |
| `datastreamId` | `string` | Web SDK | ID of a Target-enabled datastream. |
| `orgId` | `string` | Web SDK | Organization ID, including `@AdobeOrg`. |
| `version` | `string` | Web SDK | Exact Web SDK version, `2.21.0` or later. |
| `category` | `HasCondition` | No | Consent condition to wait for. Defaults to `'experience'`. |

**When consent is withdrawn:** with at.js, the helper calls
`adobe.optIn.deny(adobe.OptInCategories.TARGET)` if the Opt-in service is on
the page. With Web SDK, it sends `setConsent` with `'out'`. Neither undoes
content Target already changed, so keep `reloadOnConsentRevoked` on.

Remove Adobe's prehiding snippet when you use this helper. Without it, visitors
see the original page first, then Target's changes once consent allows the
SDK to load.

- at.js has no Adobe CDN, so host the file yourself. Its opt-in API comes from
  the Experience Cloud ID (ECID) Opt-in service, which the helper doesn't load.
  Without it, only the page reload stops at.js.
- Web SDK needs version 2.21 or later. The helper configures the SDK and sends
  consent but never calls `sendEvent`. Gate your own `sendEvent` calls behind
  the same consent.
- Web SDK can be configured only once per page. Reload the page before you
  mount the helper again or change its IDs, version or mode.

## Appcues

Appcues shows onboarding flows, tooltips and checklists inside your app. Waits
for `experience` consent.

<include src="../shared/examples/javascript/appcues-scripts.mdx" />

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `accountId` | `string` | Yes | Account ID from your [Appcues install snippet](https://docs.appcues.com/install-appcues-web/install-the-appcues-sdk). A blank ID logs an error and skips loading. |
| `region` | `'us' \| 'eu'` | No | Account region. Defaults to `'us'`. |
| `settings` | `object` | No | `AppcuesSettings` to set before the SDK loads. Defaults to `{ enableURLDetection: true }`. |
| `onReady` | `() => void` | No | Runs once after the SDK loads, while consent still allows it. Call `identify`, `group` and `track` here. |

**When consent is withdrawn:** the helper calls `Appcues.reset()` and removes
the loader, then c15t reloads the page. Keep `reloadOnConsentRevoked` on.
`reset()` clears the user and any flow in progress, but the SDK keeps running
until the reload.

- Set `region: 'eu'` for an EU account. The SDK then loads from
  `fast.eu.appcues.com` instead of `fast.appcues.com`.
- Call `identify` from `onReady`, using the signed-in user's real, stable ID.
  If the user signs in later, call `identify` from your auth handler, but first
  check that `window.Appcues` exists and consent still allows Appcues.

## Dynamic Yield

Dynamic Yield personalizes pages and serves product recommendations. Waits for
`experience` consent.

<include src="../shared/examples/javascript/dynamic-yield-scripts.mdx" />

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `sectionId` | `string` | Yes | Section ID from your [installation snippet](https://dy.dev/docs/implement-script). A blank ID logs an error and skips loading. |
| `region` | `'us' \| 'eu'` | No | Data center for the section. Defaults to `'us'`. |
| `recommendationContext` | `object` | No | [Page context](https://dy.dev/docs/page-context) set before the scripts load, such as `{ type: 'PRODUCT', data: ['SKU-1'] }`. Your app updates it on client-side navigation. |
| `category` | `HasCondition` | No | Consent condition to wait for. Defaults to `'experience'`. |

After consent, the helper sets `DY.userActiveConsent = { accepted: true }`,
loads `api_dynamic.js`, then loads `api_static.js`.

**When consent is withdrawn:** the helper removes both scripts and sets
`DY.userActiveConsent = { accepted: false }`. The SDK that already ran stays
loaded, so keep `reloadOnConsentRevoked` on.

- Ask Dynamic Yield Support to enable
  [Active Cookie Consent](https://dy.dev/docs/active-cookie-consent) for your
  section. Until they do, Dynamic Yield ignores the consent signal.
- Use one section and region per page. Dynamic Yield keeps its consent and page
  context on the page-wide `window.DY`.
- Expect flicker. Dynamic Yield wants synchronous scripts in `<head>`. Loading
  after consent, one script after the other, can show the original page before
  a campaign applies.

## Optimizely Web Experimentation

Optimizely Web runs A/B tests and personalization by changing the page in the
browser. Waits for `experience` consent.

<include src="../shared/examples/javascript/optimizely-web-scripts.mdx" />

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `projectId` | `string \| number` | Yes | The number before `.js` in your snippet URL, from **Settings > Implementation**. Invalid IDs log an error and skip loading. |
| `category` | `HasCondition` | No | Consent condition to wait for. Defaults to `'experience'`. |
| `scriptSrc` | `string` | No | Custom or proxied snippet URL. Defaults to `https://cdn.optimizely.com/js/<projectId>.js`. |

**When consent is withdrawn:** c15t removes the snippet and reloads the page.
Keep `reloadOnConsentRevoked` on. The running SDK can't be unloaded, so
without the reload it keeps changing the page and sending events.

- Expect flicker. Optimizely wants a parser-blocking snippet at the top of
  `<head>`. c15t injects it with `async: false` after consent, which doesn't
  block the parser, so visitors can see the original page before a variation
  applies.
- `optOutOptimizely()` from `@c15t/integrations/optimizely` sets Optimizely's
  `optimizelyOptOut` cookie for ten years. Granting consent later in c15t
  doesn't clear it, so the helper never calls it on revoke. Call it only for a
  deliberate permanent opt-out, and clear the cookie yourself to undo it.
