Each helper below loads its vendor only after the visitor allows the listed consent category. For setup, see [Integrations overview](/docs/integrations/overview).

## Dynamic Yield

Dynamic Yield personalizes pages and serves product recommendations. Waits for
`experience` consent.

<include src="../shared/examples/javascript/dynamic-yield-scripts.mdx" />

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `sectionId` | `string` | Yes | Section ID from your [installation snippet](https://dy.dev/docs/implement-script). A blank ID logs an error and skips loading. |
| `region` | `'us' \| 'eu'` | No | Data center for the section. Defaults to `'us'`. |
| `recommendationContext` | `object` | No | [Page context](https://dy.dev/docs/page-context) set before the scripts load, such as `{ type: 'PRODUCT', data: ['SKU-1'] }`. Your app updates it on client-side navigation. |
| `category` | `HasCondition` | No | Consent condition to wait for. Defaults to `'experience'`. |

After consent, the helper sets `DY.userActiveConsent = { accepted: true }`,
loads `api_dynamic.js`, then loads `api_static.js`.

**When consent is withdrawn:** the helper removes both scripts and sets
`DY.userActiveConsent = { accepted: false }`. The SDK that already ran stays
loaded, so keep `reloadOnConsentRevoked` on.

- Ask Dynamic Yield Support to enable
  [Active Cookie Consent](https://dy.dev/docs/active-cookie-consent) for your
  section. Until they do, Dynamic Yield ignores the consent signal.
- Use one section and region per page. Dynamic Yield keeps its consent and page
  context on the page-wide `window.DY`.
- Expect flicker. Dynamic Yield wants synchronous scripts in `<head>`. Loading
  after consent, one script after the other, can show the original page before
  a campaign applies.

## Optimizely Web Experimentation

Optimizely Web runs A/B tests and personalization by changing the page in the
browser. Waits for `experience` consent.

<include src="../shared/examples/javascript/optimizely-web-scripts.mdx" />

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `projectId` | `string \| number` | Yes | The number before `.js` in your snippet URL, from **Settings > Implementation**. Invalid IDs log an error and skip loading. |
| `category` | `HasCondition` | No | Consent condition to wait for. Defaults to `'experience'`. |
| `scriptSrc` | `string` | No | Custom or proxied snippet URL. Defaults to `https://cdn.optimizely.com/js/<projectId>.js`. |

**When consent is withdrawn:** c15t removes the snippet and reloads the page.
Keep `reloadOnConsentRevoked` on. The running SDK can't be unloaded, so
without the reload it keeps changing the page and sending events.

- Expect flicker. Optimizely wants a parser-blocking snippet at the top of
  `<head>`. c15t injects it with `async: false` after consent, which doesn't
  block the parser, so visitors can see the original page before a variation
  applies.
- `optOutOptimizely()` from `@c15t/integrations/optimizely` sets Optimizely's
  `optimizelyOptOut` cookie for ten years. Granting consent later in c15t
  doesn't clear it, so the helper never calls it on revoke. Call it only for a
  deliberate permanent opt-out, and clear the cookie yourself to undo it.
