The c15t `ada` helper waits for `functionality` consent before importing Ada's
Messaging Web SDK. It keeps the Messaging interface private and calls Ada's
`stop()` action when consent is revoked. Stopping the widget does not delete
stored conversations or cookies. Keep c15t's default reload on revocation
for an import that is still in progress.

## Configure Ada Messaging

Get your AI Agent's public `handle` from your Ada team. Most installations
need only the handle. Set `cluster` or `domain` only when Ada gives you a
regional configuration.

Remove any existing Ada module snippet, `embed2.js` script tag, or tag-manager
installation. A separate Ada installation can load before c15t grants consent.
Ada permits only one active Messaging interface per page.

This helper targets the Messaging Web SDK. It does not load the legacy Chat
SDK or expose a `legacy` option.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `handle` | Required | Public AI Agent handle passed to `start()`. The helper trims surrounding whitespace. A missing or blank handle logs an error and skips loading. |
| `cluster` | Ada's default region | Regional segment, such as `eu`, `us2`, or `maple`, or a full cluster domain supplied by Ada. Blank values are omitted. |
| `domain` | Ada's default domain | Ada base-domain segment. Use only the value supplied by Ada. Blank values are omitted. |

The helper imports `https://messaging-assets.ada.support/sdk.js`. It does not
provide a custom SDK URL or bundle the runtime into your application. Ada's
entry resolves and imports the current runtime from its CDN.

If your site has a Content Security Policy, allow
`https://messaging-assets.ada.support` in `script-src`, `connect-src`, and
`frame-src`. Also allow your Agent's API origin in `connect-src`. Follow
[Ada's CSP instructions](https://docs.ada.cx/messaging/web/getting-started#content-security-policy)
for the origin derived from your handle and region.

## Loading and revocation

The helper returns a callback-only c15t script. Once the script's mapped
consent is granted, it dynamically imports the SDK, calls the module's named
`createAdaEmbedInterface()` export, and awaits `start({ handle, cluster,
domain })`. The helper creates no `window.adaEmbed` or `window.adaSettings`
global. Repeated consent updates do not start a second widget. Keep one Ada helper
in your scripts array. Repeated helper configurations share the private
interface, and the first active configuration supplies its settings.

The helper checks the permission supplied by c15t, so changing the script's
category also changes its gate. A visitor's Ada vendor switch applies within
an allowed category.

When the last granted loader registration revokes consent or disposes the
script, the helper calls `stop()` on its private interface. Ada documents
that `stop()` removes SDK frames and interrupts a pending `start()`. A later
grant waits for the previous startup and stop work. The helper reuses the
interface for unchanged settings. A changed handle, cluster or domain creates
a fresh interface so Ada cannot retain settings from the previous Agent.

If revocation occurs while the SDK import is pending, the helper skips
creating and starting the interface when that import completes. Browsers
cannot cancel a dynamic import that has already begun. The SDK can finish
fetching its dependencies or writing its own bootstrap storage during that
time. Keep `reloadOnConsentRevoked` enabled to end the page's pending SDK
work. Already imported code remains in memory until the page unloads.

Ada does not document a consent signal or opt-out action. `stop()` does not
promise to erase conversation history, stored tokens, or cookies. The helper
does not call `deleteHistory()`, which permanently deletes the conversation
and resets the session. It reports import, startup, and stop failures through
`console.error`.

## Cookies and storage

[Ada's client-side storage list](https://static.ada.support/ada-web-storage-list.html)
covers multiple SDK generations and optional integrations. Entries include:

| Name | Purpose and retention |
| --- | --- |
| `__Host-ada-session-[session ID]-[generation]` | Server-set HttpOnly refresh credential on the Agent's Ada subdomain. Ada lists a session duration of up to seven days. |
| `ada-embed_*`, `ada-embed-*`, `ada-functional-storage` | SDK state, session values, and version caches. Ada lists these as persistent Web Storage. |
| `chatter`, `created`, `inLiveChat`, `messagingAuthState` | Conversation, session, handoff, and authentication state. Ada lists persistent Web Storage, including entries on the Ada domain. |

The current hosted SDK bootstrap also stores rollout assignments under
`ada-messaging-sdk-rollout:*` in the host page's local storage. This work
begins during module evaluation, which is why c15t gates the import itself.
Rollout assignments can remain after `stop()`.

Your Agent can embed other services, such as Calendly, YouTube, or a live
support platform. Their storage depends on your configuration. Inspect the
widget's frames as well as the host page. Host-page JavaScript cannot read or
clear Ada's HttpOnly cookies on another origin.

## Verify Ada Messaging

Use a private window with an opt-in policy and your real Ada handle. In
DevTools, disable the Network cache and filter for `ada.support`:

1. Load the page without granting functionality. No Ada module, manifest,
   iframe, or API request should appear. Check that no Ada storage has been
   created in the fresh browser context.
2. Reject optional consent and reload. Ada should still make no request.
3. Allow functionality. Check for `sdk.js`, the rollout manifest, the versioned
   SDK module, and the Ada launcher. The interface should remain absent from
   `window.adaEmbed`.
4. Revoke functionality or turn off the Ada vendor switch. The helper requests
   `stop()`, and c15t reloads by default. The new page should make no Ada
   request. Previously stored conversation data can remain.
5. Allow functionality again. The widget should start once. Repeat the grant
   and revoke steps with a slow network to check pending startup.
