Each helper below loads its vendor only after the visitor allows the listed consent category. For setup, see [Integrations overview](/docs/integrations/overview).

## Gorgias Chat

Gorgias Chat adds the Gorgias support chat widget to your store or site. Waits
for `functionality` consent.

<include src="../shared/examples/javascript/gorgias-scripts.mdx" />

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `appKey` | `string` | Yes | Public app key from your Gorgias installation snippet. A blank key logs an error and nothing loads. |
| `version` | `2` or `3` | No | Installation snippet version. Defaults to `3`. |

Remove any other Gorgias snippet or store app installation, or Gorgias can load
before consent. Without `measurement` consent, the helper calls
`GorgiasChat.disableSegment()` when the widget is ready.

**When consent is withdrawn:** c15t removes the loader and calls
`disableSegment()` if the widget is ready. Gorgias has no shutdown API, so keep
`reloadOnConsentRevoked` enabled. The page reload stops the widget.

- Segment stays off for the rest of the page after `disableSegment()`, even if
  the visitor then grants `measurement`. Gorgias has no call to turn it back on.
  A reload with `measurement` allowed turns it back on.
- The v3 snippet has the key at the end of
  `https://config.gorgias.chat/bundle-loader/YOUR_APP_KEY`. A v2 snippet uses
  `applicationId` instead. Pass that value as `appKey` with `version: 2`.
- A placeholder or deleted key still returns HTTP 200, with only a warning
  that the installation is incorrect. Check that the widget appears to confirm
  the key works.

## Zendesk Messaging

Zendesk Messaging adds the Zendesk support chat widget to your site. It doesn't
cover Web Widget Classic. Waits for `functionality` consent.

<include src="../shared/examples/javascript/zendesk-scripts.mdx" />

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `key` | `string` | Yes | Widget key from **Admin Center > Channels > Messaging and social > Messaging**, on the widget's **Installation** page. A blank key logs an error and nothing loads. |
| `category` | Consent condition | No | Consent needed to load the widget. Defaults to `functionality`. |

The helper passes consent to Zendesk's
[cookie setting](https://developer.zendesk.com/api-reference/widget-messaging/web/core/#set-cookies)
before the widget loads, and again on every consent change:

| Consent | Zendesk cookie setting |
| --- | --- |
| `functionality` and `measurement` | `all` |
| `functionality` only | `functional` |
| `functionality` withdrawn | `none` |

**When consent is withdrawn:** the helper sends `none`. Zendesk hides the
widget and deletes its local and session storage. c15t then reloads the page to
stop the widget code that already ran.

- Use one widget key per page. Zendesk has one global `zE` API, so two widgets
  on the same page control each other.
- Removing the helper from your configuration doesn't clear the conversation.
  It sends no `none`. Revoke consent first if you need the widget storage
  cleared.
