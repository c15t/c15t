## Configure the Snapchat Pixel

Copy the pixel ID from Snapchat Ads Manager. The helper passes it to
`snaptr('init', ...)`.

<CommandTabs command="@c15t/integrations@alpha" mode="install" />

```ts title="src/consent-scripts.ts"
import { snapchatPixel } from '@c15t/integrations/snapchat-pixel';

export const scripts = [snapchatPixel({ pixelId: 'YOUR_PIXEL_ID' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `pixelId` | Required | Pixel ID passed to `snaptr('init', ...)`. The helper trims it. Empty or whitespace-only values log an error and the script does not load. |
| `initOptions` | None | Object passed as the third argument to `snaptr('init', ...)`, such as `user_email`. Pass user data only when your app has the permission it needs. |
| `trackPageView` | `true` | Queues `snaptr('track', 'PAGE_VIEW')` after `init`. Set `false` to send page views yourself. |
| `scriptUrl` | `https://sc-static.net/scevent.min.js` | Loader URL override. A blank value falls back to the default. |

## Loading and revocation

`snapchatPixel` uses the `marketing` category. Before marketing is allowed,
c15t defines no `snaptr` function and loads nothing from Snapchat. When
marketing becomes allowed, the helper queues `init` and `PAGE_VIEW`, then loads
`scevent.min.js`.

On revocation the helper removes the script element and calls no Snapchat API,
so the page reload is what stops the pixel. `window.snaptr` stays defined
until then.

## Guard your own snaptr calls

The helper sends the page view. Events your code sends, such as `PURCHASE` or
`SIGN_UP`, need their own check. After revocation `window.snaptr` still
exists, so its presence does not mean marketing is allowed. Check the
permission first, then that the pixel has loaded:

```ts title="src/track-purchase.ts"
export function trackPurchase(marketingAllowed: boolean, orderId: string) {
	if (!marketingAllowed || typeof window.snaptr !== 'function') return;
	window.snaptr('track', 'PURCHASE', {
		client_dedup_id: orderId,
		currency: 'USD',
		price: 99,
		transaction_id: orderId,
	});
}
```

Pass the current marketing permission from your framework, for example
`useConsent('marketing')` in React. Set `client_dedup_id` to deduplicate
against the Conversions API. `@c15t/integrations/snapchat-pixel` also exports
`snapchatPixelEvent`, a typed wrapper around `snaptr('track', ...)`. It does
nothing until `snaptr` exists and does not check permission, so apply the same
guard before calling it.

## Verify the Snapchat Pixel

After you allow marketing, `scevent.min.js` loads from `sc-static.net` and the
pixel sends one `PAGE_VIEW`. If your router also sends `PAGE_VIEW`, check that
the first page sends one, not two. Trigger one guarded event and check that
its request appears. Then revoke marketing. Until the page reloads, calling
`trackPurchase` sends nothing.
