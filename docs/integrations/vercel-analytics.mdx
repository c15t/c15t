## Configure Vercel Analytics

Enable Web Analytics for the project in Vercel. Remove the `Analytics`
component or `inject()` call from `@vercel/analytics` so c15t loads the
script once.

<CommandTabs command="@c15t/integrations@alpha" mode="install" />

```ts title="src/consent-scripts.ts"
import { vercelAnalytics } from '@c15t/integrations/vercel-analytics';

export const scripts = [vercelAnalytics()];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `dsn` | None | Project DSN for deployments outside Vercel, set as `data-dsn`. |
| `disableAutoTrack` | None | `true` sets `data-disable-auto-track="1"` and stops automatic page views. |
| `mode` | None | `'development'` loads the debug script. `'auto'` and `'production'` load the production script. The helper does not detect your environment. |
| `debug` | None | `true` loads `https://va.vercel-scripts.com/v1/script.debug.js`. |
| `endpoint` | None | Custom ingestion endpoint, set as `data-endpoint`. |
| `scriptUrl` | `https://va.vercel-scripts.com/v1/script.js` | Loader URL override. Takes precedence over `mode` and `debug`. |

The helper also sets `data-sdkn="c15t"` on the script element.

## Loading and revocation

`vercelAnalytics` uses the `measurement` category. When measurement becomes
allowed, the helper defines the `window.vaq` queue and a `window.va` stub,
unless they exist, then loads the script. Calls to `window.va` made before the
script finishes loading wait in `window.vaq`.

On revocation the helper removes the script element and calls no Vercel API.

## Verify Vercel Analytics

After you allow measurement, `script.js` loads from `va.vercel-scripts.com`
with `data-sdkn="c15t"`, and each client-side navigation sends one page view.
With `debug` or `mode: 'development'` the helper loads `script.debug.js`
instead, so a working debug build does not prove your production settings.
After revocation `window.va` still exists, so if your code sends custom events
through it, check measurement permission before each call.
