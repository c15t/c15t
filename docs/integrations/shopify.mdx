The c15t Shopify bridge sends each consent choice to Shopify's Customer
Privacy API. Shopify's analytics, and the apps and pixels that read that API,
then follow your c15t banner instead of Shopify's own. The bridge loads no
script. Hydrogen's script tags load the Customer Privacy API, and the
bridge's `setup` function holds Hydrogen's analytics events until Shopify has
the visitor's choice.

The [Shopify example](https://github.com/c15t/c15t/tree/v3/examples/shopify-nextjs)
runs the Next.js code on this page against mock.shop.

## Before you start

- A storefront on Hydrogen 2026.10 or later, which added `ShopifyScripts`
  and the framework bindings. Older storefronts use Hydrogen's analytics
  components; follow [Shopify's migration guide](https://shopify.dev/docs/storefronts/hydrogen/migrate#migrate-analytics)
  first.
- c15t set up with your [framework quickstart](/docs/frameworks).
- Hydrogen's `handleShopifyRoutes` in your server. It serves
  `/api/<version>/graphql.json`, where the Customer Privacy API saves each
  choice. Hydrogen's templates and setup steps add it. Without it, Shopify
  rejects every choice, and under an opt-in policy Hydrogen keeps holding
  events.

## Connect Hydrogen to c15t

Every framework makes the same three changes:

1. Pass the bridge's `setup` to Hydrogen's consent settings with
   `mode: 'custom-banner'`, in place of `default-banner`.
2. Send each c15t snapshot to the bridge.
3. Declare the `measurement`, `marketing` and `functionality` categories.
   Shopify's scripts load outside c15t's `scripts` option, so c15t can't find
   them. Without the declaration, the dialog offers only Necessary and Shopify
   receives a denial for everything. The categories must also be in your
   policy's scope.

Change your storefront's root or layout; don't replace it with the code
below. Each example shows the whole file so the changes are easy to see,
minus what your storefront already has, such as its loader, route middleware
and other Hydrogen props. `shop` and `i18n` stand for the values your
storefront already passes to Hydrogen.

Hydrogen allows one analytics bus per page. A second set of Shopify tags
throws `Analytics bus already initialized`, and the first keeps its consent
mode. Where your storefront already renders the tags, through
`ShopifyScripts`, or `getShopifyScriptTags()` or `renderShopifyScriptTags()`
with `initializeShopifyScripts()`, change the consent settings it passes and
keep everything else, such as `analytics`, `routes`, `navigate` and `nonce`.

Hydrogen writes the consent mode into its inline analytics script. If your
Content Security Policy allows inline scripts by hash rather than by nonce,
update that script's hash after you change the mode, or the browser blocks
the analytics bus.

## How categories map

| Shopify consent | c15t category |
| --- | --- |
| `analytics` | `measurement` |
| `marketing` | `marketing` |
| `preferences` | `functionality` |
| `sale_of_data` | `marketing` |

Each Shopify value is `true` only while its c15t category is allowed in the
effective permissions, which include policy restrictions. Pass `categories`
to change the mapping:

{/* example: fragment */}

```ts
const shopifyPrivacy = createShopifyCustomerPrivacy({
	categories: { sale_of_data: 'measurement' },
});
```

`toShopifyConsent(permissions, categories)` returns the same four values for
your own code.

## When the bridge sends

Shopify records consent only when the visitor makes a choice, so the bridge
sends nothing until then, or while the policy is pending.

- **Opt-in or IAB policy:** `setup` waits until the visitor answers the
  banner, including with Reject All, so Hydrogen holds events until then.
- **Opt-out policy:** `setup` resolves without recording a choice, and
  Shopify applies its region defaults, including Global Privacy Control,
  until the visitor saves a choice in c15t. A stale grant is the exception,
  below.

After the first choice, the bridge sends each change once. When a visitor
revokes a category, c15t reloads the page and the bridge sends the stored
choice on load.

While the visitor has no current choice, Shopify may still hold grants from
an earlier one, for example after that choice expired or a policy change
asks again. If c15t now denies any of them, the bridge sends `false` for
those grants only, so Shopify keeps the other signals, including unset ones.
It counts grants the bridge sent and each `yes` from Shopify's
`currentVisitorConsent()`, and sends the revocation again if Shopify reports
a dropped grant again, for example after another tab granted it. If that
function isn't available, it assumes a choice c15t stored may have granted
anything. Under an opt-in or IAB policy, Hydrogen keeps holding events until
the visitor answers. Under opt-out, `setup` resolves once Shopify accepts the
revocation.

If the Customer Privacy API hasn't loaded yet, the bridge waits for
Shopify's `consentTrackingApiLoaded` or `shopifyCustomerPrivacyApiLoaded`
event.

`setup` resolves once Shopify has accepted the visitor's latest choice, and
Hydrogen then delivers the events that choice allows. If the visitor changes
their mind while the first request is in flight, `setup` waits for the newer
one. It never rejects, because Hydrogen stops calling `setup` after a
rejection. When Shopify rejects a choice, the bridge keeps events blocked and
sends it again after 1, 2 and 4 seconds, then on the next update. If the
policy turns pending meanwhile, the bridge drops those retries.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `categories` | The table above | Overrides the c15t category for any of the four Shopify values. |
| `onSync` | None | Called with what Shopify accepted: the four values for a choice, or the dropped grants for a revocation. |
| `onError` | Logs to the console | Called when Shopify rejects a choice or `onSync` throws. |

The bridge returns `update(snapshot)`, `connect(source)` and `setup()`.
`connect` follows anything with `getSnapshot` and `subscribe`, such as a c15t
kernel, and returns a function that stops following it.

## Limits

- Checkout runs on Shopify's domain and doesn't render your storefront code.
  Shopify reads the stored choice there.
- Shopify's analytics need a real shop. mock.shop accepts the consent request
  but sets no consent cookie, so `currentVisitorConsent()` stays empty.
- The bridge maps categories only; it doesn't translate IAB TCF choices.

## Verify the bridge

1. In a private window with an opt-in policy, load the page. The network panel
   shows no `graphql.json` request with `visitorConsent`.
2. Click Reject All. One request goes out with every value `false`.
3. Open the dialog, allow Marketing and save. One request goes out with
   `marketing` and `saleOfData` set to `true`.
4. On a real shop, run `window.Shopify.customerPrivacy.currentVisitorConsent()`
   in the console and check it matches your choice.
