## Configure Microsoft Clarity

Copy the project ID from your Clarity tracking code, where it follows
`https://www.clarity.ms/tag/`. The helper builds the loader URL from it.

<CommandTabs command="@c15t/integrations@alpha" mode="install" />

```ts title="src/consent-scripts.ts"
import { clarity } from '@c15t/integrations/microsoft-clarity';

export const scripts = [clarity({ id: 'YOUR_PROJECT_ID' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `id` | Required | Clarity project ID. Surrounding whitespace is trimmed. An empty ID throws unless you set `scriptUrl`. |
| `defaultConsent` | c15t state | Consent V2 value queued once, before the loader. `true` or `false` sets both channels. An object sets `ad_Storage` or `analytics_Storage`, also accepted as `marketing` and `measurement`; channels you leave out follow c15t. Later updates always follow c15t. `true` grants ad storage even while marketing is denied. |
| `scriptUrl` | `https://www.clarity.ms/tag/<id>` | Loader URL override. |

## Loading and revocation

`clarity` uses the `measurement` category, so Clarity loads only while
measurement is allowed. Before the loader runs, the helper queues
`clarity('consentv2', ...)` with `analytics_Storage` taken from measurement and
`ad_Storage` taken from marketing. While Clarity is on the page, every
permission change sends a new `consentv2` call, so allowing marketing later
grants `ad_Storage` without reloading Clarity.

On measurement revocation the helper keeps the Clarity script and sends
`consentv2` with `analytics_Storage` set to `denied`. If the visitor allows
measurement again before the page reloads, it sends `granted`. A visitor who
turns off the `microsoft-clarity` vendor gets both channels denied. Denied
storage limits what Clarity stores; it does not mean Clarity sends no requests.
See Microsoft's
[Consent V2 API](https://learn.microsoft.com/en-us/clarity/setup-and-installation/clarity-consent-api-v2).

## Verify Microsoft Clarity

Allow only marketing first. Clarity does not load, because it waits for
measurement. Then allow measurement. The request to
`www.clarity.ms/tag/<id>` appears without a page reload.
