## Configure Matomo Analytics

Copy the site ID and your Matomo URL from the Matomo tracking code. For Matomo
Cloud, pass `cloudId`, for example `'your-site.matomo.cloud'`, instead of
`matomoUrl`.

<CommandTabs command="@c15t/scripts@alpha" mode="install" />

```ts title="src/consent-scripts.ts"
import { matomoAnalytics } from '@c15t/scripts/matomo-analytics';

export const scripts = [
  matomoAnalytics({
    matomoUrl: 'https://analytics.example.com',
    siteId: 1,
  }),
];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `matomoUrl` | None | Self-hosted Matomo base URL. The helper loads `<matomoUrl>/matomo.js` and sends hits to `<matomoUrl>/matomo.php`. |
| `cloudId` | None | Matomo Cloud ID, used when `matomoUrl` is not set. A value ending in `.matomo.cloud` becomes `https://<cloudId>`. Any other value becomes `https://cdn.matomo.cloud/<cloudId>`. |
| `trackerUrl` | `matomo.php` on the Matomo origin | Tracker endpoint override. |
| `scriptUrl` | `matomo.js` on the Matomo origin | Loader URL override. Without `matomoUrl` or `cloudId`, set both `trackerUrl` and `scriptUrl`, or the helper throws. |
| `siteId` | `1` | Site ID queued with `setSiteId`. |
| `trackPageView` | `true` | Queues `trackPageView`. The table below shows when. |
| `enableLinkTracking` | `false` | Queues `enableLinkTracking`. |
| `disableCookies` | `false` | Queues `disableCookies`. It does not change when Matomo loads. |
| `defaultConsent` | None | `'required'` or `'given'` switches to Matomo consent mode. |

## Loading and revocation

`matomoAnalytics` uses the `measurement` category. `defaultConsent` picks the
mode:

| `defaultConsent` | Loads | When measurement is allowed | On revocation |
| --- | --- | --- | --- |
| Omitted | After measurement is allowed, with `trackPageView` queued | Loads `matomo.js` | Removes the script element and calls no Matomo API |
| `'required'` | On every page, with `requireConsent` queued | Queues `setConsentGiven` and `trackPageView` | Keeps the script and queues `forgetConsentGiven` |
| `'given'` | On every page, with `setConsentGiven` and `trackPageView` queued | Queues `setConsentGiven` and `trackPageView` | Keeps the script and queues `forgetConsentGiven` |

In `'required'` mode Matomo holds tracking until `setConsentGiven`. `'given'`
queues `setConsentGiven` and a page view on every page load before the helper
checks c15t, including for a visitor who rejected measurement. Use `'given'`
only when your policy lets Matomo track without a choice. In both consent
modes, each consent change while measurement is allowed queues another
`trackPageView`, for example when the visitor later allows marketing. Matomo
separates
[tracking consent from cookie consent](https://developer.matomo.org/guides/tracking-consent).

## Verify Matomo Analytics

Without `defaultConsent`, allowing measurement loads `matomo.js`, and a
`matomo.php` request carries the page view.

<include src="../shared/integrations/vendor-revocation-and-verify.mdx" />

With `defaultConsent: 'required'`, Matomo loads before the choice, so test it
separately in a private window with an opt-in policy:

1. Load the page. `matomo.js` loads, and no `matomo.php` request follows.
2. Open Privacy settings and allow measurement. Without a reload, a
   `matomo.php` request carries the page view.
3. Turn measurement off and save. c15t reloads the page, and the new page
   loads `matomo.js` without a `matomo.php` request.

With `'given'`, step 1 already sends a `matomo.php` page view. See the
[consent verification guide](/docs/guides/verify-consent) for navigation and
hosting checks.
