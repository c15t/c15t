## How vendor consent works

A visitor allows marketing, then switches off Meta Pixel. Other marketing
scripts load; Meta Pixel does not. c15t loads a script, network request or
iframe that names a vendor only when both are true:

- Its category is allowed.
- The visitor has not switched its vendor off.

A vendor switch never grants a category. With marketing denied, Meta Pixel
stays blocked whatever its own switch says. Under an `iab` policy, vendor slugs
are ignored and IAB vendor consent comes from the TC string instead.

## Declare the vendors

List each vendor with an `id`, `name`, `category` and `privacyPolicyUrl`. The
preference dialog only lists vendors that have a name and a privacy policy URL.

```ts title="src/consent-vendors.ts"
import type { Vendor } from 'c15t';

export const vendors: Vendor[] = [
  {
    id: 'meta-pixel',
    name: 'Meta Pixel',
    category: 'marketing',
    privacyPolicyUrl: 'https://www.facebook.com/privacy/policy/',
    description: 'Ad conversion measurement and audiences.',
  },
  {
    id: 'gtag',
    name: 'Google Analytics',
    category: 'measurement',
    privacyPolicyUrl: 'https://policies.google.com/privacy',
  },
];
```

The `id` must match the `vendor` slug on the script. Every `@c15t/integrations`
helper except `cloudflareZaraz` sets `vendor` to its script ID, so `metaPixel()` is `meta-pixel` and
`gtag()` is `gtag`. Each vendor guide names its slug.

| Field | Required | Behavior |
| --- | --- | --- |
| `id` | Yes | Lowercase slug of up to 64 characters: letters, digits, `.`, `_` and `-`. |
| `name` | Yes | Name shown in the preference dialog. |
| `category` | Yes | A category, or a condition such as `{ or: ['measurement', 'marketing'] }`. |
| `privacyPolicyUrl` | Yes | Link shown next to the vendor. |
| `description`, `legalName`, `homepageUrl` | No | Extra detail shown on the vendor card. |
| `disabled` | No | List the vendor without a switch. A stored denial for it no longer applies. |

Pass `vendors` where you already pass `scripts`:

| Framework | Registration point |
| --- | --- |
| Next.js, TanStack Start | `vendors` prop on `ConsentRoot` |
| React | `ConsentProvider options={{ ...options, vendors }}` |
| Nuxt, Vue | `vendors` in the c15t config next to `scripts` |
| Svelte, SvelteKit | `vendors` in the `ConsentManagerProvider` options |
| JavaScript | `createConsentRuntime({ ...options, vendors })` |

A self-hosted backend can declare vendors too. `/init` returns them and c15t
merges them with the vendors in code. When both declare the same `id`, the
code declaration wins.

## Gate your own scripts, requests and iframes

Put the vendor slug on each target:

| Target | Field |
| --- | --- |
| Script configuration | `vendor: 'meta-pixel'` |
| Network blocker rule | `vendor: 'meta-pixel'` |
| Iframe blocker | `data-vendor="meta-pixel"` on the `<iframe>` |

An iframe with `data-vendor` and no `data-category` is gated on the vendor
alone. A script with `alwaysLoad` still loads when its vendor is off; its
callbacks receive `info.vendor.granted` so the SDK can stop itself. The Google
Consent Mode and RudderStack helpers do this for you. While their vendor is
off, they send every optional category as denied.

## What the preference dialog shows

`ConsentDialog` and `ConsentWidget` in React, Vue and Svelte list each declared
vendor under its category, with its own switch. A vendor's switch is disabled
while its category is off. Save records the vendors the visitor changed. The
labels come from `consentManagerDialog.vendors` in the translations: `title`,
`privacyPolicy`, `disabledByCategory` and `switchLabel`.

For a custom dialog in React, `useVendorDraft()` from `c15t/react` reads and
stages vendor switches, and `useVendorAllowed('meta-pixel')` returns whether
one vendor may run now. In Vue, `useConsentDraft()` returns a `vendors` map and
`setVendor`. In Svelte, `getConsentManager()` exposes `selectedVendors`,
`setSelectedVendor` and `getDisplayedVendors(category)`.

## Record a vendor choice without the dialog

With the headless runtime, stage a vendor and confirm it with the next save,
or pass vendors with the categories:

```ts
// Records only the staged vendor. save() with no argument would also
// reconfirm every displayed category.
runtime.stageVendorConsent('meta-pixel', false);
await runtime.kernel.commands.save({});

// Confirm categories and vendors in one action.
await runtime.kernel.commands.save({
  marketing: true,
  measurement: true,
  vendors: { 'meta-pixel': false },
});
```

c15t stores only the vendors a visitor switched off, and sends the full vendor
map to the backend with the consent record. Accept all and Reject all clear
that list, so every vendor follows its category again. Under an opt-out policy,
every vendor starts on.

## What switching a vendor off does not do

- It does not delete cookies the vendor already set.
  [Clear on revocation](/docs/integrations/clear-on-revocation) does not run,
  because the category stays allowed. Delete the vendor's cookies from the
  script's `onConsentChange` when `info.vendor.granted` is `false`.
- It does not expire. The switch stays off until the visitor changes it or
  uses Accept all or Reject all, even across a policy change.
- Adding a vendor does not ask returning visitors again. A new vendor starts
  on inside an allowed category. Change the policy's `copyRevision` if a new
  vendor should prompt again.

## Verify vendor consent

1. Declare `meta-pixel` and register `metaPixel()`. Open Privacy settings. The
   marketing row lists Meta Pixel with a switch.
2. Allow marketing and save. In DevTools Network, `fbevents.js` loads.
3. Open Privacy settings, switch Meta Pixel off and save. c15t reloads the
   page. After the reload there is no `fbevents.js` request, and other
   marketing scripts still load.
4. Reload again. The Meta Pixel switch is still off.
5. Turn marketing off. The Meta Pixel switch is disabled.
6. Open Privacy settings and click Accept all. `fbevents.js` loads again.
