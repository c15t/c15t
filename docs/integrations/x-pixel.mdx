## Configure the X Pixel

Copy your X Pixel ID. The helper passes it to `twq('config', ...)`. Conversion
event IDs, which look like `tw-xxxx-xxxx`, are separate from the pixel ID.

<CommandTabs command="@c15t/integrations@alpha" mode="install" />

```ts title="src/consent-scripts.ts"
import { xPixel } from '@c15t/integrations/x-pixel';

export const scripts = [xPixel({ pixelId: 'YOUR_PIXEL_ID' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `pixelId` | Required | Pixel ID passed to `twq('config', ...)`. The helper trims it. Empty or whitespace-only values throw. |
| `scriptSrc` | `https://static.ads-twitter.com/uwt.js` | Loader URL override. A blank value falls back to the default. |

## Loading and revocation

`xPixel` uses the `marketing` category. Before marketing is allowed, c15t
defines no `twq` function and loads nothing from X. When marketing becomes
allowed, the helper queues `twq('config', pixelId)`, then loads `uwt.js`.

On revocation the helper removes the script element and calls no X API. X
exposes no consent update call, so the page reload is what stops the pixel.
`window.twq` stays defined until then.

## Guard your own twq calls

Conversion events come from your code, and each one needs its own check.
After revocation `window.twq` still exists, so its presence does not mean
marketing is allowed. Check the permission first, then that the pixel has
loaded:

```ts title="src/track-purchase.ts"
export function trackPurchase(marketingAllowed: boolean, orderId: string) {
	if (!marketingAllowed || typeof window.twq !== 'function') return;
	window.twq('event', 'tw-xxxx-xxxx', {
		conversion_id: orderId,
		currency: 'USD',
		value: 99.99,
	});
}
```

Pass the current marketing permission from your framework, for example
`useConsent('marketing')` in React. Set `conversion_id` to deduplicate the
event. `@c15t/integrations/x-pixel` also exports `xPixelEvent`, a typed wrapper
around `twq('event', ...)`. `xPixelEvent` does nothing while `twq` is
undefined, which is the case before marketing is first allowed. It does not
check permission, so apply the same guard before calling it.

## Verify the X Pixel

After you allow marketing, `uwt.js` loads from `static.ads-twitter.com`.
Trigger one guarded event and check that its request to X appears. Then revoke
marketing. Until the page reloads, calling `trackPurchase` sends nothing.
