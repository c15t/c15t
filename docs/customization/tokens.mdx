## Load the stock stylesheet once

React, Next.js and Svelte provide `styles.css`. Import the adapter's stylesheet
at the app's global entry point. Vue includes styles in its components; Astro
adds styles through its integration.

The stylesheet blocks rendering, so it carries only what a first paint can
show: the default tokens, every c15t CSS variable, and the rules for the
banner, `ConsentDialogTrigger` and the `ConsentGate` placeholder. The consent
dialog and preference widget bring their own rules. Each rule reaches the page
once.

```tsx
import 'c15t/react/styles.css';
```

| File | Holds | Loaded by |
| --- | --- | --- |
| `styles.css` or `styles.tw3.css` | Default tokens, all variables, banner, trigger and `ConsentGate` rules | Your app, once |
| `@c15t/ui/styles/dialog.css` | Dialog and preference widget rules | The dialog component, with its lazy chunk |
| `@c15t/ui/styles/primitives.css` | Rules for the `@c15t/ui/styles/primitives` class maps | Svelte's `styles.css`, or your app if it renders those class maps |
| `iab/styles.css` | IAB TCF banner and dialog rules and variables | Your app, after `styles.css` |

In React, Next.js and TanStack Start, the dialog's module imports
`@c15t/ui/styles/dialog.css`. The bundler emits it with the dialog's chunk and
loads it before that chunk runs, so the dialog never renders unstyled. The
chunk loads after first paint, by the time the dialog first opens. Do not
import `dialog.css` yourself. The `@c15t/react/components/consent-dialog`,
`/components/consent-widget`, `/primitives`, `/primitives/*` and `/iab` entry
points import it as soon as you import them, because they render dialog parts
outside the lazy chunk.

These modules import the stylesheet through `@c15t/ui/styles/dialog`. Under
the `node` export condition that module imports nothing, so server code that
loads `@c15t/react` with plain Node, such as the Pages Router or an SSR build
that keeps dependencies external, does not fail on the `.css` file. In your
own components, import `@c15t/ui/styles/dialog` rather than the `.css` file
if the module can run on the server.

Svelte loads its dialog in a separate chunk too, but
`@c15t/svelte/styles.css` already includes the dialog and primitive rules, so
Svelte apps import that one stylesheet. Astro injects the banner rules on every
page and links the dialog's stylesheets when a visitor first points at, focuses
or opens a control that opens the dialog, so in Astro the dialog rules do not
block rendering. Vue components import their own stylesheets.

The dialog rules sit in `@layer components` and declare no variables, so
tokens from `theme`, variables you override in your own CSS, and Tailwind 4
utilities still win over them even though they load later. If you import
`styles.css` into a named layer, such as `@import 'c15t/react/styles.css'
layer(c15t)`, the dialog rules still join the top-level `components` layer.
List `components` in your layer order statement, for example
`@layer c15t, components, app;`, so it does not land after your own layers.

The standard stylesheet places rules in `@layer components`. For Tailwind 3,
use the `styles.tw3.css` entry instead of the standard stylesheet, between the
components and utilities directives in your Tailwind entry:

```css
@tailwind base;
@tailwind components;
@import 'c15t/react/styles.tw3.css';
@tailwind utilities;
```

Tailwind 3 also processes the dialog stylesheet the bundler loads, and it
rejects a stylesheet that uses `@layer components` without its own
`@tailwind components` directive. Add the c15t plugin before `tailwindcss` in
your PostCSS config. It removes the layer wrapper from c15t's stylesheets so
Tailwind 3 accepts them and its preflight does not override them:

```js title="postcss.config.mjs"
export default {
  plugins: ['@c15t/ui/postcss-tailwind3', 'tailwindcss', 'autoprefixer'],
};
```

Do not load both c15t stylesheet variants. For Tailwind 4 or unlayered CSS,
inspect layer order before reaching for `!important`.

## Set semantic values together

This React theme changes the brand color and large corner radius. Include
hover and foreground colors when overriding raw variables so the button remains
readable in each state.

```ts
import { defineTheme } from '@c15t/ui/theme';

export const theme = defineTheme({
  colors: { primary: '#2f6f4e' },
  radius: { lg: '4px' },
  consentActions: {
    primary: { variant: 'primary', mode: 'filled' },
    dismiss: { variant: 'neutral', mode: 'stroke' },
  },
});
```

Install `@c15t/ui` if importing its theme helper directly. The browser does
not turn tokens into CSS. In React and Next.js, render
`<ConsentTheme theme={theme} />` where the app renders on the server, and pass
`theme` in your provider options for `consentActions`. Elsewhere, call
`generateThemeCSS(theme)` from `@c15t/ui/theme` on the server or at build time
and put the result in a `<style>` element or your stylesheet. See
[React customization](/docs/frameworks/react/customize) and
[Next.js customization](/docs/frameworks/next/customize).

`consentActions` selects styling by action role. A per-action entry overrides
`primary`, which overrides `default`.

## Combine a generated theme with your own CSS

`generateThemeCSS` writes its variables on `:root:root` and
`.c15t-theme-root.c15t-theme-root`, one step more specific than the defaults
in `styles.css`. The theme therefore overrides the defaults whether its
`<style>` element comes before or after the stylesheet. The same output backs
`ConsentTheme` in React, Next.js and TanStack Start, Astro's `theme` option and
the script tag's `ui.theme`.

A `--c15t-*` variable you set on plain `:root` in your own CSS loses to a
generated theme that sets the same variable, even when your rule loads later.
Put the value in the theme, or raise your selector:

```css
:root:root {
  --c15t-primary: #2f6f4e;
}
```

Scoped rules such as `[data-prompt] { --c15t-primary: ... }` set the variable
on the banner element itself, so they still apply inside it.

## Every token

Every framework uses the same tokens. React, Next.js, TanStack Start and
Astro take the theme key, such as `radius.lg`, in a `theme` object. Vue and
Nuxt take the CSS variable name without the leading `--`, such as
`c15t-radius-lg`, in `tokens`. Svelte and the HTML script tag set the CSS
variable in a stylesheet. Your framework's customize page shows where each one
goes.

<include src="../shared/reference/theme-tokens.mdx" />

The radius tokens round different parts. `radius.lg` rounds the banner card,
the preference dialog, `ConsentGate` placeholders and the floating trigger.
`radius.md` rounds buttons, accordions, tabs and the vendor list.
`radius.sm` rounds small parts inside the banner and dialog. To give the banner
and its buttons the same 4px corners, set both `lg` and `md`.

## Target a prompt with CSS

```css
[data-prompt][data-model='opt-in'] {
  --c15t-primary: #2f6f4e;
  --c15t-primary-hover: #24563c;
  --c15t-text-on-primary: #fff;
}
```

Use attributes exposed by the rendered component, not guessed class names.
Test the prompt and the preferences dialog separately because tokens scoped to
one prompt do not automatically reach a portaled dialog.

| Size variable | Default | Target |
| --- | --- | --- |
| `--consent-banner-max-width` | `440px` | Floating card |
| `--consent-banner-widget-max-width` | `20rem` | Widget |
| `--consent-banner-wall-max-width` | `30rem` | Choice wall |

The banner footer lays out its actions by the card's width, not the
viewport's. With the default `compact` profile, a card narrower than 22rem
puts Reject and Accept on one row and Customize on a full-width row below
them, on any screen size.

Test long translations and small screens after changing width or typography.
A compact banner must still fit the required actions.

## Restyle the "Secured by" tag

The tag sits on the edge of the banner and dialog cards and uses the primary
color by default. Set these variables on `:root`, or on an element that
contains the tag. The dialog renders in a portal, so a variable set on the
banner does not reach the dialog's tag.

| Variable | Default | Target |
| --- | --- | --- |
| `--consent-branding-tag-background-color` | `var(--c15t-primary)` | Tag background |
| `--consent-branding-tag-border-color` | `--c15t-primary` mixed 14% toward black | Tag border |
| `--consent-branding-tag-text-color` | `var(--c15t-text-on-primary, #fff)` | "Secured by" and the wordmark |
| `--consent-branding-tag-mark-color` | The text color | c15t mark or inth logo |
| `--consent-branding-tag-shadow` | Inset highlight and a 1px drop shadow | Tag shadow |
| `--consent-branding-tag-attached-edge-width` | `0px` | Border on the edge that meets the card |

The stylesheet does not declare these variables. Each default resolves on the
tag, so a `--c15t-primary` you scope to a banner still colors the tag.

This makes the tag look like a tab of the card:

```css
:root {
  --consent-branding-tag-background-color: var(--c15t-surface);
  --consent-branding-tag-border-color: var(--c15t-border);
  --consent-branding-tag-text-color: var(--c15t-text-muted);
  --consent-branding-tag-mark-color: var(--c15t-primary);
  --consent-branding-tag-shadow: none;
}
```

The edge that meets the card has no border by default. Above the banner the
tag overlaps the card's top border by 1px and covers it. Below the dialog the
tag starts under the card's bottom border. Set
`--consent-branding-tag-attached-edge-width: 1px` to draw that edge. It is
drawn over the card's border, so the two borders do not stack.
