c15t is the better choice for most production sites. It applies consent rules by region, so visitors outside opt-in regions do not wait behind a banner. Inth keeps your consent records. c15t also supports IAB TCF 2.4, IAB GPP and Global Privacy Control. Silktide Consent Manager documents none of these.

Silktide Consent Manager is a free browser script from Silktide, with an MIT licence. You add one JavaScript file and one CSS file, then define consent types. It adds scripts after consent and sends Google Consent Mode updates. It keeps each visitor's choices only in that visitor's browser.

Start on Inth's [free plan](https://inth.com/pricing) and follow the [framework guide](/docs/frameworks) for your app.

## c15t vs Silktide Consent Manager feature comparison

| What you need | c15t | Silktide Consent Manager |
| --- | --- | --- |
| Apply different rules by region | Policy rules by country and US state. Inth or your backend finds the location | One default for each consent type, for all visitors. No location detection |
| Keep consent records on a server | Inth hosts the backend and keeps records in its database. Self-hosting is optional | Not included. Choices stay in browser storage |
| Use IAB TCF | TCF 2.4 with the `@c15t/iab` add-on. Inth is a registered IAB Europe CMP, ID 490 | Not documented |
| Respect privacy signals | Reads Global Privacy Control. IAB GPP API for US state opt-outs | Not documented |
| Use Google Consent Mode v2 | Google tag and GTM integrations send the default and each update | Consent Mode updates for each consent type, and a dataLayer event |
| Use consent in framework components | Native adapters and reactive consent state | Browser global with callbacks |
| Resolve consent in Next.js | Server, streamed and browser paths | Browser setup only |
| Translate the interface | Built-in copy in 53 languages, with your own [i18n messages](/docs/customization/translations) | Configurable text |
| Show preferences | Category and vendor controls | Configurable consent types and a preferences modal |
| Control scripts | Integration helpers, network request rules and embeds | Script injection for each consent type, and callbacks |
| Handle withdrawal | Reload by default. Optional cleanup of declared data | Reload after the visitor withdraws consent for injected scripts |
| Change the interface | Themes, component parts and headless APIs | Configurable text, position and CSS variables |
| Licence and price | Apache 2.0, with no licence fee. Inth has a free plan and paid plans | MIT and free, with no traffic or domain limits |
| Install | `c15t` from npm, or `@c15t/browser` as a script tag | One JavaScript file and one CSS file, self-hosted or from a CDN |

Sources: [Silktide product scope](https://silktide.com/consent-manager/) and [configuration and source](https://github.com/silktide/consent-manager).

## What you build yourself with Silktide Consent Manager

Silktide Consent Manager gives you a banner, preferences and script injection in the browser. Your team builds and runs the rest:

1. **A location lookup**, to apply different rules by region.
2. **A consent record endpoint and its storage**, to prove what each visitor chose.
3. **Code that connects choices to your application state**, because it has no framework adapters.

c15t and Inth include all three. Silktide documents no IAB TCF support. If ad partners need a TC string from your site, Silktide cannot supply one.

## Ask for consent only where your policy needs it

When your policy lets scripts run before a choice in a region, c15t runs them there. You keep the analytics and ad data from those visitors. Visitors in opt-in regions still see the banner before optional scripts run.

c15t picks a [policy rule](/docs/concepts/policies) for each visitor from their location. The `recommendedPolicyRules()` pack uses opt-in rules for Europe and Québec. It uses opt-out rules for supported US privacy states. Other known locations get no banner. A visitor from an unknown country gets strict opt-in.

Inth or your own backend finds the location. Browser-only mode does not find the visitor's country.

Silktide Consent Manager does not find the visitor's location. Each consent type has one `defaultValue`, and the same default applies to all visitors. The banner shows to all visitors, also where your policy lets optional scripts run before a choice. Until those visitors accept, you lose their analytics and ad data.

Before you let categories run by default, compare the preset with how you use the data. A country match does not give a legal basis for a vendor's use of data.

## Keep consent records without a backend project

You do not need to design a consent record system. Inth runs the [c15t backend](/docs/self-host/overview) and keeps each consent record in its database. If your team must operate the service, you can self-host the same backend.

Silktide saves choices in the visitor's browser storage. It documents no record service. If you need proof of consent, your team must build the endpoint and the storage.

c15t applies the visitor's choice in the browser before the backend confirms it. c15t keeps each choice in a queue in browser storage. If the page closes before the backend answers, c15t sends the choice again on the next page. A permanent rejection, such as a stale policy, removes the choice from the queue. If browser storage is unavailable, c15t cannot keep an interrupted request for the next page.

A choice in the browser does not prove that the backend saved a consent record. Check the saved record in Inth. The [consent state guide](/docs/concepts/consent-state) gives all of these conditions.

## Fit consent to the application

When a visitor changes a choice, each c15t component that reads the consent state gets the change. A settings screen reads the same state that controls a vendor or a video embed. Use [framework components](/docs/frameworks), or build your own interface with [headless APIs](/docs/frameworks/react/headless).

For Next.js, c15t supports [streamed, awaited and browser paths](/docs/frameworks/next/rendering). In the App Router, the default streamed path shows the page first. It sends the banner in a later chunk of the same response, before hydration.

Silktide exposes a browser global and callbacks. Your team writes the code that connects them to the application.

## Silktide Consent Manager questions

### Is Silktide Consent Manager free?

The script is free, with an MIT licence and no traffic or domain limits. The parts that it leaves out are not free. You build and host a consent record endpoint and a location lookup. c15t has no licence fee. Inth has a [free plan](https://inth.com/pricing) that includes the backend.

### Does Silktide Consent Manager store consent records?

Not on a server. Silktide saves choices in the visitor's browser storage and documents no record service. c15t sends consent records to Inth or to a [self-hosted backend](/docs/self-host/overview).

### Does Silktide Consent Manager support IAB TCF?

Silktide documents no IAB TCF support. Its source has no TCF API. c15t supports TCF 2.4 with the [`@c15t/iab` add-on](/docs/self-host/guides/iab-tcf). IAB Europe lists Consent Management Inc., the company behind Inth, as a CMP with ID 490. IAB Europe registration is separate from Google's CMP certification.

### Does Silktide Consent Manager support Google Consent Mode v2?

Yes. You map each consent type to Consent Mode parameters, such as `analytics_storage` or `ad_user_data`. After a change, Silktide calls `gtag('consent', 'update', ...)`. It also pushes a dataLayer event. c15t's [Google tag integration](/docs/integrations/google-tag) sends the default before `config`. It sends an update after each change. c15t also has a [GTM integration](/docs/integrations/google-tag-manager).

### Does Silktide Consent Manager work with React or Next.js?

Yes, from client code. Silktide gives a browser global, `window.silktideConsentManager`. It documents no framework adapters. c15t has native adapters for [React, Next.js, Vue, Svelte, Astro and TanStack Start](/docs/frameworks). In Next.js, c15t can resolve consent on the server.

### Can I move from Silktide Consent Manager to c15t?

Yes. Map each Silktide consent type to a c15t category. Move its `scripts` entries to registered integrations. Then remove the Silktide files. c15t does not read Silktide's stored choices. Decide if you carry them over or ask visitors again.

## What to plan for with c15t

- **Register your vendors.** c15t controls the scripts and embeds that you register. Remove their old loaders.
- **Check requests made with denied signals.** With Consent Mode, some integrations load before consent and send denied signals.
