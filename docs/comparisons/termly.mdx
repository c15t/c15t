## Make consent part of the application you own

c15t is the stronger fit when your developers need consent inside product features and control over the record backend. You can change the interface and engine with the rest of your application.

[Inth](https://inth.com) is the official hosting platform for c15t. It runs the consent backend and stores consent records in a database. Your consent interface and vendor controls stay in your application.

Termly suits teams that want consent and legal-policy tools in one hosted product. Its scanner, banner settings and policy generators address work outside the c15t packages.

## Compare what you get

| What you need | c15t | Termly |
| --- | --- | --- |
| Connect to application code | Native framework components and reactive state | Hosted script, browser events and consent APIs |
| Own the interface | Themes, component parts and headless APIs | Custom banner layouts, languages and display settings |
| Control vendor code | Declared category and vendor rules for scripts, requests and embeds | Auto Blocker with custom rules and manual controls |
| Read choices on the server | Backend APIs and framework server paths | Consent API for category and cookie choices |
| Store records | Inth hosts the backend and stores records in its database. Self-hosting is optional | Termly's hosted consent records |
| Find cookies | **No automatic scanner in the packages** | Site scans and classification |
| Generate legal documents | **Not included** | Privacy, cookie policy and other document generators |
| Collect privacy requests | **No bundled case management suite** | Embeddable data-subject request form |

Sources: [Termly consent platform](https://termly.io/products/consent-management-platform/), [consent data flow](https://support.termly.io/hc/en-us/articles/50231234862865-How-Consent-Data-Flows-from-the-Website-Banner-to-Termly) and [Consent API](https://support.termly.io/hc/en-us/articles/30710543895697-Consent-API-documentation).

## Control the behaviour behind each choice

With c15t, consent can control an embed, an analytics integration or an application feature. Declare the relevant categories and vendors beside the code that uses them.

The [headless APIs](/docs/frameworks/react/headless) let your team build privacy controls into product screens. [Vendor consent](/docs/frameworks/react/vendor-consent) supports a choice about one service within a category.

Termly also exposes consent state and events. Its server API can retrieve a visitor's category and cookie choices. Developer access alone is not a reason to prefer c15t.

c15t adds a native component workflow and source code for both the engine and backend. That combination matters when your team needs to change how the system works.

## Separate consent code from legal-document work

c15t gives you control of the consent system. It does not generate your privacy policy or discover the cookies already on your site.

Termly can be the better fit when one team wants scans, generated policies and banner administration together. Check the selected plan and the site's custom integrations.

Choose c15t when application ownership is the main requirement and you have a separate process for site inventories and legal documents.

## What c15t does not include

- The packages do not include a cookie scanner, policy generator or privacy-request case management.
- Script and vendor rules need configuration. They do not automatically cover every tag already on the site.
- Backend helpers do not prove that a visitor accepted a legal document without an acceptance flow.
- Connect to Inth to store consent records in its database. Local state alone is not a saved remote record.

Some integrations load with denied signals. Withdrawal normally reloads the page, and optional cleanup cannot remove all vendor data.

The release covered here is an alpha. Include setup, backend operation and separate legal services in your cost comparison.
