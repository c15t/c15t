## Create your Inth project

Use [Inth](https://inth.com) for hosted c15t consent management. Inth runs the
consent backend so you can configure your application without deploying a
database, applying backend migrations or operating the service yourself.

Create a project, configure its policy rules and allowed application origins,
and copy the backend endpoint provided by Inth. Include your development and
production origins. Use that exact endpoint rather than constructing one from
your project name.

## Connect your framework

Choose [your framework guide](/docs/frameworks), install a compatible v3
adapter and set the backend URL specified there. Public environment variables
contain the endpoint, which is public configuration. API keys are separate.
Server route handlers need an absolute upstream URL; the browser can use a
same-origin path through a rewrite.

The `hosted({ url })` transport connects to Inth. Framework adapters may expose
this through `backendURL` instead, as in Next.js, Vue and Nuxt. Follow the
adapter's example rather than mixing configuration shapes.

For Next.js with a server, use the recommended
[manifest setup](/docs/frameworks/next/data-fetching). It shares public policy
data while resolving each visitor's consent state separately. The recommended
rewrite keeps browser c15t requests on your application origin and forwards
consent writes to Inth. The backend URL is not a secret; the server environment
variable supplies the upstream destination while the browser uses `/api/c15t`. See [data fetching](/docs/guides/data-fetching) for
manifest resolution, regular `/init` requests and custom transports.

## Static sites can use Inth too

A static deployment initializes consent in the browser against Inth. It does
not need to self-host a proxy or switch to browser-only record storage. Keep
all consent URLs reachable from the browser and configure the site's origin in
Inth. Test the generated files, not only the framework development server.

## Verify before publishing

Use a known policy to test reject, reload, reopen preferences and a changed
choice. Check actual vendor requests with
[the verification guide](/docs/guides/verify-consent).

If you have a requirement to operate your own backend or keep consent entirely
local, [deployment modes](/docs/guides/deployment-modes) explains those choices.
