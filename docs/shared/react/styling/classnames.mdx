  ## Prefer Component Slots for Stock Components

  There is no single top-level `className` contract across every pre-built consent component.

  For the stock `ConsentBanner`, `ConsentDialog`, and `ConsentWidget`, prefer `options.components` first. That keeps the markup intact and lets you target the exact part you need.

  ## Per-Slot className

  Target individual component parts via the provider `components` object. Each slot accepts React attributes:

  ```tsx
  <ConsentManagerProvider
    options={{
      components: {
        banner: {
          title: { className: 'text-xl font-semibold' },
          footer: { className: 'flex gap-3' },
        },
        description: {
          banner: { className: 'text-sm text-gray-600' },
        },
        button: {
          primary: { className: 'rounded-full px-6' },
        },
      },
    }}
  />
  ```

  ## Combining with CSS Modules

  ```tsx
  import styles from './consent.module.css';

  <ConsentManagerProvider
    options={{
      components: {
        banner: {
          card: { className: styles.bannerCard },
          title: { className: styles.bannerTitle },
        },
        button: {
          primary: { className: styles.primaryButton },
        },
      },
    }}
  />
  ```

  ## When to Use Raw className

  Use slot-level `className` styling when:

  - your styling system is already class-driven
  - tokens are too broad for the change
  - component slots already identify the correct element

  If the request is "make the banner footer darker", prefer `theme.colors.surfaceHover` first. If the request is "add a border and spacing only to the footer", prefer `components.banner.footer`.

  For full custom markup and behavior, continue to [Headless Mode](../headless).
