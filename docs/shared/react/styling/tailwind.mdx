<section id="intro-and-setup">
  c15t works with Tailwind CSS out of the box. Use component slots to apply Tailwind utility classes to specific component parts.

  ## Setup

  Import the standard c15t stylesheet once in your app-level CSS entrypoint:

  ```css
  /* React: src/index.css */
  @import "c15t/react/styles.css";

  /* Next.js: app/globals.css */
  @import "c15t/next/styles.css";
  ```

  <import src="./stylesheet-entrypoint.mdx#why-global-css" />

  ### Tailwind v4

  Tailwind v4 needs no c15t-specific PostCSS config. Import Tailwind normally, then keep the c15t stylesheet last in the top-level `@import` block so Fumadocs, `tw-animate-css`, or other preset styles load first.

  ```css title="src/index.css"
  @import "tailwindcss";
  @import "tw-animate-css";
  @import "c15t/react/styles.css";
  ```

  ### Tailwind v3

  Import the Tailwind 3-compatible c15t stylesheet after `@tailwind components;` and before `@tailwind utilities;`:

  ```css title="src/index.css"
  @tailwind base;
  @tailwind components;
  @import "c15t/react/styles.tw3.css";
  @tailwind utilities;
  ```

  If you import c15t component styles (`@c15t/ui/styles/components/*.css`) with Tailwind 3, add the `@c15t/ui` compatibility plugin before `tailwindcss` in your PostCSS config:

  ```js title="postcss.config.mjs"
  export default {
    plugins: ['@c15t/ui/postcss-tailwind3', 'tailwindcss', 'autoprefixer'],
  };
  ```

  The string plugin form requires Node.js 20.19 or later — the plugin is an ES module, and frameworks such as Next.js load string plugins with `require()`, which only supports ES modules from that version on.
</section>

<section id="dark-mode-to-nostyle">
  ## Dark Mode with Tailwind

  Combine Tailwind's dark mode with c15t's `dark` tokens and component slots:

  ```tsx
  <ConsentProvider
    options={{
      theme: {
        colors: {
          primary: '#6366f1',
          surface: '#ffffff',
          text: '#1f2937',
        },
        dark: {
          primary: '#818cf8',
          surface: '#1f2937',
          text: '#f9fafb',
        },
      },
      components: {
        banner: {
          card: {
            className: 'bg-white dark:bg-gray-900 shadow-lg dark:shadow-gray-900/30',
          },
          title: { className: 'text-gray-900 dark:text-gray-100' },
        },
      },
    }}
  />
  ```

  ## Optional: noStyle Mode

  If you want Tailwind to own all layout and visual styling, use `noStyle: true`.

  <Callout type="info">
    When using `noStyle: true` with Tailwind, you're responsible for all layout and visual styling. Start with component slots first, then switch to `noStyle` only when you need full control.
  </Callout>

  For full custom markup (not just styles), see [Headless Mode](../headless).
