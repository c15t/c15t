<section id="state-and-actions">
  ## State and actions

  `useConsentManager()` reads the current provider and its preference draft.

  | Field | Meaning |
  | --- | --- |
  | `explicitChoice` | Latest receipt per explicitly confirmed category, or `null` |
  | `effectivePermissions` | Current processing permissions after policy, expiry and privacy restrictions |
  | `promptRequirement` | Remaining `choice`, `notice` or `none` interaction |
  | `noticeDismissal` | Separate local dismissal, or `null` |
  | `privacySignals`, `optOutDirectives`, `restrictions` | Detected signals and effective restrictions |
  | `policyRule`, `resolution` | Active behavior and resolution outcome |
  | `selectedConsents`, `draftIsStale` | Editable displayed values and whether they need review |

  Call `has(condition)` for a gate check. Use `setSelectedConsent(category, value)`
  to edit the draft, then `saveConsents('custom')` to confirm it. `saveConsents('all')`
  accepts the displayed scope; `saveConsents('necessary')` rejects it. These actions
  never dismiss an outstanding notice. `resetDraft()` rebases stale drafts.
  `setActiveUI('dialog')` opens persistent preferences.

  For narrower subscriptions, use `useExplicitChoice`, `useEffectivePermissions`,
  `usePromptRequirement`, `usePolicyResolution` and `useRestrictions`.
  `useDismissNotice` exposes the dedicated dismissal command.
</section>

<section id="key-types">
  ## Record types

  `ExplicitChoice` contains per-category receipts with `value` and `confirmedAt`.
  Missing categories remain undecided. `ConsentState` is a boolean permission map;
  it is not a receipt. `PromptRequirement` has a `kind` and, for a required prompt,
  a `reason` of `missing`, `expired` or `policy-changed`.

  The only permission models are `opt-in`, `opt-out` and `iab`. Read the current
  prompt instead of inferring it from a model or from the presence of a receipt.
</section>
