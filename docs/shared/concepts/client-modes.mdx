<section id="overview">
  c15t supports three client modes that determine how consent data is stored and synchronized. Choose the mode that matches your infrastructure:

  - **Hosted mode** - Recommended for production. Backend-backed consent with geolocation, centralized policy resolution, audit history, and automatic retry.
  - **Offline mode** - Browser-only storage with no network requests. Best for local development, demos, static deployments, or deployments without a backend.
  - **Custom mode** - Bring your own backend with custom endpoint handlers

  <Callout type="warn">
    If you need durable consent records, server-side enforcement, or automatic jurisdiction detection, use hosted mode. Offline mode cannot provide those guarantees because consent lives only in the browser.
  </Callout>
</section>

<section id="hosted-mode">
  ## Hosted mode

  Provider `hosted({ url })` selects a backend transport. Core callers use
  `createHostedTransport({ backendURL })`. Initialization resolves policy; direct
  choices and privacy directives use separate write paths. Failed initialization
  keeps the first layer hidden while fallback permissions and retries apply.
</section>

<section id="offline-mode">
  ## Offline mode

  `offline({ policyRules })` resolves local rules without network requests. Browser
  persistence stores category receipts, notice dismissals and privacy directives.
  Cookie projections can seed server rendering. There is no central backend history,
  automatic geography or trusted cross-profile identity linkage. Missing records
  can require another interaction; they never imply a grant.
</section>

<section id="custom-mode">
  ## Custom mode

  Implement the canonical `KernelTransport` and pass it through `custom(transport)`
  to a provider. Return explicit versioned policy resolution and preserve receipt
  coverage and confirmation times. Privacy directives use their own endpoint;
  notice dismissal remains local. Old endpoint-handler bridges are removed.
</section>

<section id="decision-guide">
  ## Choose a transport

  Use hosted mode for centrally stored records and backend policy resolution.
  Use offline mode when local rules and browser records meet your requirements.
  Use a custom transport when another service implements the full canonical contract.
  Persistence, server rendering and presentation remain separate concerns.
</section>
