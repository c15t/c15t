Set `buildManifest: true` on the `c15t()` integration, next to `manifest()`:

{/* example: fragment */}

```js title="astro.config.mjs"
c15t({
	buildManifest: true,
	mode: manifest({ backendURL: 'https://your-project.inth.app' }),
});
```

The integration fetches the manifest when `astro build` or `astro dev` starts,
then embeds it in its generated server options. Middleware, init routes and
manifest routes use that same snapshot automatically. The browser options
omit the full manifest. No generated file or extra import is needed.
`astro check` and `astro sync` do not fetch, so type checks work without the
backend. `astro preview` serves the completed build and never fetches a new
snapshot.

Use an absolute upstream `backendURL` or `manifestURL`; a build cannot fetch a
route in the app it is still compiling. `buildManifest` with `hosted()` or
`offline()` stops `astro build` and `astro dev`. The config is read once at
build time, so the built server keeps the backend URL and the snapshot it was
built with.

<include src="../build-time-manifest-notes.mdx" />

For policy updates without a rebuild, omit `buildManifest` and keep
`manifest()` to fetch and cache the policy at runtime.
