The module bundles the manifest by default. `manifest()` is the default mode,
and the module reads `NUXT_PUBLIC_C15T_BACKEND_URL` when the `c15t` key sets no
`backendURL`, so `nuxt.config.ts` needs only the module:

<include src="../examples/nuxt/nuxt-config.mdx" />

The module fetches the snapshot during `nuxt build` or development setup and
embeds it in the server bundle. `nuxt prepare` does not fetch a manifest, so
dependency installation and type preparation do not require the backend. The
consent route the module mounts at `routePrefix`, `/api/c15t` by default,
uses it automatically, and the full manifest stays out of runtime
configuration and the browser bundle. Production server startup does not run
module setup or fetch another manifest.

The build fetches only from an absolute upstream URL. It skips the fetch for
`hosted()`, `offline()`, `manifest({ snapshot })` and
`manifest({ source: 'runtime' })`. If the fetch fails, `nuxt build` stops.
`nuxt dev` logs a warning instead, and the server fetches and caches the
policy at runtime. Set `onBuildError: 'runtime'` under the `c15t` key, or
build with `C15T_ON_BUILD_ERROR=runtime`, to let a build continue the same way.
For a static host without a server, use
`mode: manifest({ resolve: 'browser' })` with `routePrefix: false`; only then
does the browser bundle get the snapshot.

fetches and caches the policy at runtime.
