Wrap your Next.js config in `withConsentManifest`. An existing config object
or function goes in as the first argument, unchanged:

<include src="../examples/nextjs/next-config.mdx" />

`next build`, `next dev` and `next typegen` fetch `${backendURL}/manifest` and
write the policy to `c15t-manifest.ts` in the directory you run them from.
`next start` serves the built snapshot and fetches no policy. The build reads
`NEXT_PUBLIC_C15T_BACKEND_URL` with the same fallback as `c15t.config.ts`, so
saves and the snapshot point at the same project. Keep `c15t-manifest.ts` out
of Git.

If the fetch fails or takes longer than 10 seconds, the build logs a warning
and keeps going. `c15t-manifest.ts` then exports `undefined`, and the server
fetches and caches the policy at runtime, as with
[runtime manifest caching](/docs/frameworks/next/optimization#reuse-cached-policy-data).
The build skips the fetch and writes the same file when `backendURL` is not an
absolute http(s) URL, or when the config sets `output: 'export'`, which has no
server to use the snapshot.

To stop the build when the fetch fails, set `onBuildError: 'fail'`:

{/* example: fragment */}

```ts title="next.config.ts"
export default withConsentManifest(nextConfig, {
	backendURL: 'https://your-project.inth.app',
	onBuildError: 'fail',
});
```

With `'fail'`, a relative `backendURL` stops the build too. A static export
still skips the fetch.
