Wrap your Next.js config in `withConsentManifest`. An existing config object
or function goes in as the first argument, unchanged:

<include src="../examples/nextjs/next-config.mdx" />

`next build`, `next dev` and `next typegen` fetch `${backendURL}/manifest` and
write the policy to `c15t-manifest.ts` in the directory you run them from.
`next start` serves the built snapshot and fetches no policy. Without a
`backendURL` option, the build reads `NEXT_PUBLIC_C15T_BACKEND_URL`, as
`c15t.config.ts` does, so saves and the snapshot point at the same project.
Keep `c15t-manifest.ts` out of Git.

If the fetch fails, `next build` stops. `next dev` logs a warning instead, and
`c15t-manifest.ts` exports `undefined`, so the server fetches and caches the
policy at runtime, as with
[runtime manifest caching](/docs/frameworks/next/optimization#reuse-cached-policy-data).
To let a build continue the same way, set `onBuildError: 'runtime'`, or run it
with `C15T_ON_BUILD_ERROR=runtime`:

{/* example: fragment */}

```ts title="next.config.ts"
export default withConsentManifest(nextConfig, { onBuildError: 'runtime' });
```

A missing backend URL counts as a failed fetch. The build skips the fetch and
writes the same file when the backend URL is relative, or when the config sets
`output: 'export'`, which has no server to use the snapshot. With
`onBuildError: 'fail'`, a relative URL stops the build. A static export always
skips the fetch.
