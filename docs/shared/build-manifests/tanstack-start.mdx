<include src="../vite-build-manifest.mdx" />

Without a `backendURL` option, the plugin reads `VITE_C15T_BACKEND_URL`,
including from `.env` files. If the variable is unset, the plugin sets it to
the URL it used, so `import.meta.env.VITE_C15T_BACKEND_URL` in the app reads
the same value.

If the fetch fails, `vite build` stops. `vite dev` logs a warning instead,
and `src/c15t-manifest.ts` exports `undefined`, so the server fetches and
caches the policy at runtime. To let a build continue the same way, set
`onBuildError: 'runtime'`, or run it with `C15T_ON_BUILD_ERROR=runtime`:

{/* example: fragment */}

```ts title="vite.config.ts"
consentManifest({ onBuildError: 'runtime' }),
```

If you install `@c15t/tanstack-start` directly, set
`importSource: '@c15t/tanstack-start/static'`.

For policy updates without a rebuild, remove the plugin and the `manifest`
line, and use [runtime fetching](/docs/frameworks/tanstack-start/rendering#await-consent-in-the-loader).
