The plugin reads the backend URL from `backendURL`, or from
`VITE_C15T_BACKEND_URL` when you leave `backendURL` out. If that variable is
unset, the plugin sets it to the URL it used, so app code can read
`import.meta.env.VITE_C15T_BACKEND_URL` instead of repeating the URL.

When `vite build` or `vite dev` starts, the plugin fetches the policy and
serves it to server code as `snapshot` from `c15t/generated`. In the browser
bundle, `snapshot` is `undefined`, so the policy never ships to the browser.
Pass `snapshot` and the backend URL to `createConsentStateHandler`, as the
[quickstart root route](/docs/frameworks/tanstack-start/quickstart#resolve-consent-in-the-root-route)
does.

If you also mount `createConsentServerRoute`, declare the options once so the
route and the server function resolve from the same snapshot:

Without a `backendURL` option, the plugin reads `VITE_C15T_BACKEND_URL`,
including from `.env` files. If the variable is unset, the plugin sets it to
the URL it used, so `import.meta.env.VITE_C15T_BACKEND_URL` in the app reads
the same value.

If the fetch fails, `vite build` stops. `vite dev` logs a warning instead,
and `snapshot` is `undefined`, so the server fetches and caches the policy at
runtime. To let a build continue the same way, set `onBuildError: 'runtime'`,
or run it with `C15T_ON_BUILD_ERROR=runtime`:

{/* example: fragment */}

```ts title="vite.config.ts"
consentManifest({ onBuildError: 'runtime' }),
```

For policy updates without a rebuild, remove the plugin and the `manifest`
option, set `VITE_C15T_BACKEND_URL` yourself, and use [runtime fetching](/docs/frameworks/tanstack-start/rendering#await-consent-in-the-loader).
