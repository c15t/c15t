Add the plugin before `tanstackStart()`. It writes `src/c15t-manifest.ts`;
keep that file out of Git:

{/* example: fragment */}

```ts title="vite.config.ts"
import { consentManifest } from 'c15t/tanstack-start/build';

plugins: [
	consentManifest({ backendURL: 'https://your-project.inth.app' }),
	tanstackStart(),
	viteReact(),
];
```

Bind the backend URL and snapshot once:

<include src="../examples/tanstack-start/consent-options.mdx" />

Keep the `.server.ts` suffix. If browser code ever uses `consentOptions`,
TanStack Start's import protection fails the build instead of shipping the
manifest.

Pass it to the server function in `__root.tsx`:

<include src="../examples/tanstack-start/build-manifest-server-fn.mdx" />

If you mount `createConsentServerRoute`, pass it the same object:

{/* example: fragment */}

```ts title="src/routes/api/c15t/$.ts"
handlers: createConsentServerRoute({ ...consentOptions, proxy: true }),
```

`outputFile`, `exportName` and `importSource` change the generated file. Set
`importSource: '@c15t/tanstack-start/static'` if you install
`@c15t/tanstack-start` directly.

For policy updates without a rebuild, remove the plugin and the `manifest`
line, and use [runtime fetching](/docs/frameworks/tanstack-start/rendering#await-consent-in-the-loader).
