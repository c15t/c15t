Add `consentManifest` from `c15t/vue/vite` to your existing Vite plugins:

<include src="../examples/vue/vite-config.mdx" />

The plugin reads `VITE_C15T_BACKEND_URL`, or a `backendURL` option. When
`vite build` or `vite dev` starts, it fetches the policy and serves it as
`snapshot` from `c15t/generated`. Pass `manifest()` from
`c15t/vue/vue-plugin` as the plugin's `mode` in `src/main.ts`:

{/* example: fragment */}

```ts title="src/main.ts"
import { c15tVue, manifest } from 'c15t/vue/vue-plugin';

app.use(c15tVue, { mode: manifest() });
```

`manifest()` reads the snapshot and the backend URL from `c15t/generated`.
The browser resolves policy from the bundled snapshot without fetching
`/manifest`. When the policy depends on a location the page does not know,
it asks the backend's `/init`, unless you pass `inputs` or `geoURL`. The
bundle includes the policy and the resolver. Keep your scripts and other
plugin options.

When the build has no snapshot, as in `vite dev` after a failed fetch,
`snapshot` is `undefined`, and the browser fetches
`${backendURL}/manifest` instead.

For policy updates without a rebuild, use `hosted()` from
`c15t/vue/vue-plugin`, which asks the backend's `/init` on each page load, or
`manifest({ source: 'runtime' })`, which fetches the manifest at runtime.
