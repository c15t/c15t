## c15t's IAB CMP registration

Inth makes c15t. Inth's legal entity, Consent Management Inc., is registered
with IAB Europe as a CMP under CMP ID 490. The
[IAB Europe CMP list](https://iabeurope.eu/cmp-list/) shows it under the name
Consent Management Inc.

## How the preference centre shows features

The stock IAB preference centres in React, Next.js, Vue, Svelte, Astro and the
script tag follow TCF 2.4 and Policies v5.0.b. Special purposes stay in their
locked section with a lock icon, because the visitor cannot object to them.

Features get their own section after the special purposes. It shows the IAB
standard text for features from the Global Vendor List's
`standardTexts.features`. If the list has no standard text, it shows the
`iab.preferenceCenter.features.description` translation. Each feature lists
its name, description, illustrations and the vendors that use it. The section has no switch, lock or vendor toggle, because
TCF forbids showing features next to a control that cannot be disabled.

The feature section follows the theme's spacing and typography tokens.
Its disclosure arrows are decorative and stay out of the accessibility tree.

A custom preference UI gets the same rows from
`resolveIABDialogDisplayModel` in `@c15t/iab/headless`. `essentialRows` holds
the special purposes only. `featureRows` holds the features, with
`locked: false` and `toggle: 'none'`, so render them without a control.
`featuresStandardText` is the standard text, or `null` when you should use the
translation.

Each vendor's privacy policy and legitimate interest links come from its
`urls[]` entry in the Global Vendor List. The stock preference centres pick
the entry for the language the banner shows, then English. A custom UI gets
the same links from `resolveIABVendorUrls(vendor, language)` in
`@c15t/iab/headless`, or from `policyUrl` and `legitimateInterestUrl` on the
vendors `processGVLForDialog` returns when you pass it `language`. Vendor lists
older than GVL v3 have a single `policyUrl` field, which c15t still reads.

c15t shows a vendor link only when it is an absolute `http:` or `https:` URL
with a host. It drops any other link, such as another scheme, a relative path
or a protocol-relative URL. The privacy policy then becomes `''`, the
legitimate interest and storage disclosure links become `null`, and the stock
vendor lists show no link. This applies to GVL links and to `privacyPolicyUrl`
on custom vendors. A custom UI can check other links with
`resolveIABSafeUrl(url)` from `@c15t/iab/headless`.

## Legal bases for custom vendors

A custom vendor in `customVendors` declares its own legal bases: `purposes`
for consent and `legIntPurposes` for legitimate interest. TCF Policies
Appendix A allows purposes 1, 3, 4, 5 and 6 only with consent, so c15t ignores
those purposes in `legIntPurposes`. Accept All never signals legitimate
interest for them, `setPurposeLegitimateInterest` refuses them, and the stock
preference centres offer no objection for them. For a custom vendor whose
`legIntPurposes` lists only those purposes, Accept All sets no vendor
legitimate interest signal, `setVendorLegitimateInterest` refuses to set one,
and a saved choice from an earlier release loses it when c15t restores it.

If a custom vendor processes one of those purposes, move it from
`legIntPurposes` to `purposes`. Earlier releases turned such an entry into a
legitimate interest signal. After Accept All, `__tcfapi` reported it until
c15t's state next changed, for example when the preference centre opened, or
until a reload. IAB Europe's CMP Validator check 9 reads that report and flags
it. The TC string never carried those bits.

## Consent scope

c15t stores TCF choices per site and browser, which the TCF calls
service-specific scope. It does not sync TC strings across devices, and every
TC string it writes has `IsServiceSpecific` set to `1`.

Do not use `/consent/check` or your own account data to skip the TCF banner on
another device. That turns the choice into multi-device scope, which the TCF
requires you to disclose in the first layer, and c15t does not show that
disclosure. The `isServiceSpecific` option is deprecated. c15t ignores it and
logs a warning when you pass `false`.
