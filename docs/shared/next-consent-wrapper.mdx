## Register scripts in a client wrapper

The [runnable Next.js example](/docs/examples) uses PostHog for measurement and
X Pixel for marketing. Replace the placeholder IDs `phc_your_project_key` and
`your-pixel-id` with your own. Remove a vendor's entry to leave it out, or
replace its helper with the [integration](/docs/integrations/overview) your
application uses. Include the
measurement and marketing categories in your policy for these two vendors.

Create `lib/scripts.ts` with the example's script configuration:

<include src="./examples/nextjs/scripts.mdx" />

PostHog waits for measurement consent here. `cookieless_mode: 'never'` disables
cookieless capture after rejection. X Pixel waits for marketing consent. Remove
any existing loader for these vendors, including `next/script` and tag-manager
entries, so each integration loads once.

Create this client wrapper. It owns everything that has to run in the browser:
the consent config, the scripts, the banner, the dialog and a persistent
preferences link. The layout or `_app.tsx` passes only the visitor's state.

<include src="./examples/nextjs/consent-wrapper.mdx" />

Import `consentConfig` in this `'use client'` file, as shown, and do not pass it
from a Server Component. `defineConsentConfig` marks its result with a symbol
key, and React cannot send an object with symbol keys from a Server Component
to a Client Component.

`ConsentRoot` already provides the consent runtime. Mount this wrapper once and
do not add a second provider. Keep your site's content and footer inside it.

The files import through the `@/` path alias that `create-next-app` sets up.
With a `src/` directory the alias points at `src/`, so the same imports work.
Without the alias, use relative paths.
