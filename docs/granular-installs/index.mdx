## One Package, Many Entry Points

The docs teach a single install:

<PackageCommandTabs mode="install" command="c15t" />

The `c15t` package is an umbrella: each entry point re-exports one of the scoped packages that make up c15t. `import { ConsentManagerProvider } from 'c15t/react'` loads exactly the same code as `import { ConsentManagerProvider } from '@c15t/react'` — the umbrella adds no wrapper layer, and it has no bundle-size cost because your bundler only includes the entry points you import.

## Package Mapping

| Umbrella entry point | Scoped package                                                      |
| -------------------- | ------------------------------------------------------------------- |
| `c15t` (root)        | `@c15t/core` — the headless consent engine                          |
| `c15t/react`         | `@c15t/react` — React components, hooks, and headless primitives    |
| `c15t/next`          | `@c15t/nextjs` — Next.js integration (App Router and Pages Router)  |

Every subpath carries over, including stylesheets: `c15t/react/styles.css` is `@c15t/react/styles.css`, `c15t/next/headless` is `@c15t/nextjs/headless`, and so on.

The umbrella pins each scoped package to the exact matching version, so installing `c15t` always gives you a consistent, tested set — you never have to align scoped package versions yourself.

## When to Prefer Scoped Installs

The scoped packages are not a legacy path. They are published from the same source as the umbrella entry points and remain permanently supported. Prefer them when:

- **You are building a library.** Depend on `@c15t/core` for consent logic or `@c15t/ui` for the framework-agnostic theme system without pulling React or Next.js integrations into your dependency tree. See [Building UI](/docs/frameworks/javascript/building-ui) for the full pattern.
- **You want the smallest install footprint.** The umbrella installs all of its scoped packages into `node_modules`. A project that only needs the headless engine can install `@c15t/core` alone. This affects install size only — bundle output is identical either way.

Install the scoped package for your layer directly:

<PackageCommandTabs mode="install" command="@c15t/core" />

<PackageCommandTabs mode="install" command="@c15t/react" />

<PackageCommandTabs mode="install" command="@c15t/nextjs" />

With a scoped install, use the scoped import paths (`@c15t/react`, `@c15t/react/styles.css`, …) wherever the docs show the `c15t/*` equivalents from the [package mapping](#package-mapping).
