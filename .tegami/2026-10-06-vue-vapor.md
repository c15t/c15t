### Support Nuxt 4.6 and Vue Vapor

`@c15t/vue` now lists `vue` `^3.5.39 || ^3.6.0-0` as a peer dependency. Vue
Vapor needs Vue 3.6, which is still a release candidate, and npm refused to
install `@c15t/vue` next to `vue@3.6.0-rc` with an `ERESOLVE` peer conflict.

The Nuxt module and components work in Nuxt 4.6 apps with `vue.vapor`
enabled. Vapor pages and components can render `ConsentRoot`,
`ConsentGate`, `ConsentWidget` and `ConsentPreferencesLink`, pass them slots,
and call the composables. c15t's own components stay on the virtual DOM.

Also fixed: on Nuxt 4.6, `defineAppConfig()` stopped checking the `c15t` key
in `app.config.ts`, so unknown options and wrong types passed silently and
callback parameters such as `onRequestBlocked`'s `info` became implicit
`any`. Nuxt 4.6 no longer derives `AppConfigInput` from `CustomAppConfig`, so
the module now types both.

Also fixed: with `future.compatibilityVersion: 5`, Nuxt stops auto-importing
into server code, and the build failed because the module's `ssr: false`
`/init` script plugin imported from `#imports`. The plugin now imports from
`nitropack/runtime` and reads `app.config.ts` through a Nitro virtual the
module registers. Without server auto-imports Nitro cannot load
`app.config.ts`, so `ssr: false` pages get no early `/init` script there and
the browser starts the request when the app loads.
