### Support SvelteKit 3

`@c15t/svelte` accepts `@sveltejs/kit` 2 or 3 as a peer dependency.
`c15tHandle()` returns a new `C15tHandle` type from `@c15t/svelte/kit`. It is
assignable to `Handle` in both versions, so existing hooks work unchanged.

SvelteKit 3's Cloudflare adapter no longer exposes `waitUntil`, and its Vercel
adapter has no edge runtime. Pass the platform's `waitUntil` as
`onBackgroundRevalidate` so background work finishes after the response.

```ts title="src/routes/api/c15t/[...path]/+server.ts"
import { createSvelteKitConsentRouteHandlers } from '@c15t/svelte/kit';
import { waitUntil } from 'cloudflare:workers'; // Vercel: '@vercel/functions'

export const { GET } = createSvelteKitConsentRouteHandlers({
	backendURL: 'https://your-project.inth.app',
	onBackgroundRevalidate: (promise) => waitUntil(promise),
});
```

SvelteKit 3's `adapter-node` ignores `ORIGIN`. If you pass `loadConsent` a
relative `backendURL` with your own `fetch`, set `paths.origin` in the
`sveltekit()` options or use an absolute `backendURL`.

If you self-host `@c15t/backend` in a SvelteKit 3 route, import it dynamically
to avoid an `Invalid export` build error. See the
[self-hosting quickstart](https://c15t.com/docs/self-host/quickstart#sveltekit).
