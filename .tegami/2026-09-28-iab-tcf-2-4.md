### Support IAB TCF 2.4

c15t now follows TCF 2.4 and TCF Policies v5.0.b, which CMPs on the web must meet by 23 October 2026. `tcfPolicyVersion` stays 5, so existing TC strings stay valid and visitors are not asked again. Hosted and self-hosted users need no migration beyond upgrading.

**Features have their own section.** The IAB preference centre in React, Vue, Svelte, Astro and the script tag no longer lists Features in the locked "Essential Functions" section. They now appear in a separate section after the special purposes, under the IAB standard text from the vendor list's `standardTexts.features`. When the list has no standard text, the section uses the new `iab.preferenceCenter.features` translation, which ships in all 35 locales. Each feature shows its name, description, illustrations and the vendors that use it, with no switch, lock or vendor toggle. The policies forbid showing Features next to a control that cannot be disabled. Special purposes keep their locked section. React exports the new row as `IABConsentDialog.FeatureItem`.

**`disclosedVendors` in TC data.** `__tcfapi('getTCData')` now returns `vendor.disclosedVendors`, as CMP API v2.2 requires. It lists the same vendors as the TC string's disclosed vendors segment, with `true` for each.

**Special-purpose-only vendors.** `@c15t/iab` now uses `@iabtechlabtcf/core` 1.5.22. A vendor that declares only special purposes no longer gets its vendor legitimate interest bit set. TCF 2.4 requires that bit to be 0.

**`isServiceSpecific` is deprecated.** TCF requires `IsServiceSpecific=1`, and group-specific scope is also encoded as 1, so `false` could only produce invalid TC strings. c15t now always encodes `true` and logs one warning when you pass `false`. Publisher restrictions therefore always encode. `decodeTCString` still rejects restrictions in a stored string that is not service-specific. c15t stores TCF choices per site and browser and does not sync them across devices.

**Vendor list validation keeps new fields.** The GVL schemas in `@c15t/schema` now accept fields they do not know about instead of stripping them, so `standardTexts` and anything the IAB adds later reach the browser through the backend's cache. `GVLStandardTexts` is exported next to the other GVL types.

#### Migration

- Headless IAB UIs: `resolveIABDialogDisplayModel` from `@c15t/iab/headless` now returns special purposes only in `essentialRows`, and `essentialPartnerCount` counts only their vendors. Render `featureRows` in a separate section without controls, and show `featuresStandardText` above them, or your `features.description` translation when it is `null`. Feature rows have `locked: false` and `toggle: 'none'`.
- Custom translation objects can add `iab.preferenceCenter.features` with `title` and `description`. The key is optional, and missing values fall back to English.
- Remove `isServiceSpecific: false` from your IAB options. It has no effect other than the warning.
