### Add a Sentry integration

`sentry()` from `@c15t/integrations/sentry` loads Sentry from its CDN or works with the SDK your app already runs. Error monitoring runs before consent by default. Replay and user data wait for measurement consent; `loadMode: 'after-consent'` gates error monitoring too. The CLI offers the integration in its picker.

Filter user data at the final envelope and transport stages, including users restored by later processors, feedback contact details, logs, metrics, and root and child spans. Stop Replay without flushing on withdrawal or removal, block application starts and flushes while denied, and discard queued Replay uploads. Keep late SDK initialization synchronized, honor vendor denial for every feature, and preserve app-initiated shutdowns.

Disable SDK data collection while the user-data permission is denied, then restore the app's resolved settings and allowlists on grant. Remove request headers, cookies, bodies and URL details at send time, including HTTP attributes on spans. Apply CDN consent before startup integrations run, and avoid client polling while after-consent initialization is denied.

Share equivalent configurations before mounting and across remounts, retaining active recordings and the SDK bundle. Track each loader separately and require every loader to satisfy each feature condition, including compound conditions and initially denied CDN loaders. The core loader adds `observeConsentBeforeLoad` to report consent before a resource loads. Changed CDN settings initialize a client with the new DSN, release and sampling options. Publish the `@c15t/scripts/sentry` compatibility export alongside the integration.

Keep a shared external script downloading when its original loader is removed. Transfer element ownership to a remaining loader, deliver load and error events to each active loader, and release each loader's listeners on removal.

Combine consent from every active configuration targeting the same Sentry client, including configurations with different categories or callbacks and adapters registered before SDK initialization. Removing one configuration releases its restriction and preserves the surviving configuration's recording; the final removal denies data collection and stops Replay.

Apply a new CDN configuration when it adopts another loader's completed SDK bundle, honoring its DSN, release, tracing and Replay settings without reinitializing on later consent changes. Load the selected version and bundle type when they differ, and use Replay options from the configuration that initialized the client. The core loader adds `Script.resourceKey` to distinguish DOM resources under the same logical script ID. Release both `resourceKey` and `observeConsentBeforeLoad` with a minor core bump.

Omit Replay's consent category when no Replay loader or positive CDN sample rate is enabled. Coalesce matching resource keys in one batched mount, while preserving each logical script's callbacks, consent and ownership through removal and loader disposal.
