---
'@c15t/backend': major
---

Accept the documented consent wire and store v3 receipts. `POST /subjects` now takes the body every c15t client transport sends (`domain`, `preferences`, an epoch `givenAt`, `type`) instead of an internal `domainId`/`purposeIds` shape that no shipped client produced. A v3 client's `choice` receipts are stored on the consent row exactly as sent, so a partial save never renews a category the subject did not touch; a save without receipts stores the values it submitted as `legacy-v2` receipts, refusals included. `givenAt` and every `confirmedAt` are recorded as sent and refused when later than the server clock, never clamped. A `policySnapshotToken` is verified when present and asserted manifest-mode inputs are recomputed through the same resolver `/init` uses; the decision is recorded on `runtimePolicyDecision`. Replays return the same consent; a replay with different purposes or receipts is a `CONFLICT`.

`GET /subjects/:id` and `GET /subjects` return `preferences` again (2.x parity) plus each consent's `choice`, and the subject read adds `subjectChoice` (latest receipt per category with original times and bases), `privacyDirectives` and the subject's `identityProvider`. Rows the 2.x backend wrote contribute grants only; no refusal is invented from historical omission, and a row whose stored receipts cannot be read is skipped rather than salvaged.

Add privacy directives: `POST` and `GET /subjects/:id/privacy-directives` record and read a subject's own standing opt-out directive (Global Privacy Control) without writing a consent row, a decision or a `consent_given` audit entry; `POST` and `GET /privacy-directives` (API key) record and read identity-level directives for `(externalId, identityProvider)`. Only an identity link asserted by an authenticated request exposes identity-level directives to a subject; a browser-asserted link neither reads them nor carries a directive onto another profile. Directives store no client IP or user agent.

Negotiate the policy contract: every response carries `x-c15t-policy-contract: 1`, the header is allowed through CORS and exposed to browsers, a client declaring another contract receives `policyResolution` as `failed`/`unsupported-contract`, and `policyFailure` is logged once at startup. Migration `3-consent-receipts-and-privacy-directives` adds `consent.choice`, `subject.identityAuthority` and the `privacyDirective` table; it is additive and idempotent. New typed failures: `409 POLICY_SNAPSHOT_REQUIRED`/`POLICY_SNAPSHOT_INVALID` and `422 STALE_POLICY`.

Configure `policyRules` and use `policyRulePresets`; old policy configuration, resolved-policy exports and legacy wire projections are removed. Init requires versioned policy resolution, manifests use schema version 2, and snapshot tokens assert the canonical policy fingerprint. Frozen material metadata is used only to compare historical receipts.
