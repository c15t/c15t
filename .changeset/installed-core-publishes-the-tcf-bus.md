An installed c15t app now publishes the `IABTCF_*` storage bus its own core was already computing. iOS writes standard `NSUserDefaults`; Android writes the application-default `SharedPreferences` through `PreferenceManager.getDefaultSharedPreferences`, never a file name of its own, because those are the two places the IAB CMP specification tells a vendor SDK to look and an ad SDK reading a c15t-named file finds nothing. Both cores carried the projection and neither platform carried a writer, so a device running this SDK answered a vendor's consent read as though no CMP were present. The rows stay the two whose source state the core owns -- `IABTCF_PolicyVersion` from the stored vendor list and `IABTCF_gdprApplies` from the resolved policy -- and every other key in the specification's table stays absent rather than guessed. A row moves with the record it projects, never ahead of it: the bus is written in the same step as the envelope, `reset()` and a discarded envelope clear it, and a table somebody emptied outside the SDK is rebuilt from stored bytes. It is on by default with no configuration and no host step, since the readers are third-party SDKs in the host process and never ask first, and it stays a signal rather than the record -- the Keychain on iOS and encrypted storage on Android remain authoritative, and nothing in the core reads a bus value back.
