Refuse a CMP ID that cannot be encoded, at mount. A TC String carries the CMP ID in a 12-bit field and the IAB encoder rejects anything below 2, so a placeholder ID could never produce a string. What it did produce was a page that installed `__tcfapi` and answered `ping` with `cmpId: 0`, so vendor scripts believed a CMP was present, followed by `TCModelError: invalid value 0 passed for cmpId` from inside `save()` once a user tried to act. `createIAB` now validates before it installs anything, and `iab()` rejects a present-but-unusable ID at configuration time while still accepting none, because the hosted path legitimately gets the ID from `/init`. `createCMPApi` validates rather than defaulting, and the `CMP_ID = 0` fallback it defaulted to is gone. Accepted range is 2 to 4095, which is what the encoder writes losslessly. `cmpVersion` defaults to the package major from the version module that already claimed to be the single source of truth, instead of a hardcoded `1`, so `__tcfapi` and the TC String agree and the value moves with releases; it reported `1` for every release up to 3.x, discarding the field that exists to identify which CMP build wrote a string. TCF policy version is unchanged and still comes from the served vendor list.
