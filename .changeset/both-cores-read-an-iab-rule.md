A device under an IAB policy now asks instead of refusing. Both native cores used to reject the wire model `iab` as a contract they did not speak, which left a subject under an IAB rule looking at a deny-all snapshot with an unreadable policy. Both read it now and evaluate it with the web kernel's own answer: `defaultPermission` in `@c15t/core` grants an in-scope category only under `opt-out` or `none`, so an IAB rule still leaves every optional category denied until the subject makes a choice, `necessary` stays granted, and a rule carrying a prompt or a preselection that `@c15t/schema` forbids beside `iab` is refused rather than approximated. A model name neither core knows fails closed exactly as it did before -- only `iab` stopped being unsupported. The snapshot reports `opt-in` while an IAB rule is in force, following `deriveModel` in `@c15t/core`, because the name `iab` advertises a vendor-side record the device cannot produce: no `tcString` goes on the save body and no `IABTCF_*` key is written, since a TC String has to open with a CMP ID IAB Europe assigned and this build holds no registered one. Nothing about the matched rule is hidden -- `resolution` still names the IAB policy and `iab.gvl` still carries the vendor list `/init` served.
